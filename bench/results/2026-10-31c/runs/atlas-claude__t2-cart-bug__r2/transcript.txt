## Final report

**Root cause (from the investigation, confirmed against the code):** `total()` had five independent defects. Quantity was never multiplied in, the percent branch subtracted nothing (it kept the discount instead of the remainder), there was no zero clamp, there was no cent rounding, and `COUPONS[couponCode]` read inherited `Object.prototype` keys.

**Fix as it stands (`src/cart.js:13-27`):**
- Line 16 sums `item.price * item.qty`.
- Line 18 looks up the coupon only if `Object.prototype.hasOwnProperty.call(COUPONS, couponCode)` is true.
- Line 21 sets the percent result to `sum - sum*value/100`, which is the remainder.
- Line 23 subtracts the fixed value.
- Line 26 returns `Math.max(0, Math.round(sum * 100) / 100)`, so rounding happens once, after all discounts, and the result is clamped at zero.
- Line 29 keeps `module.exports = { total }`.

**Does it remove the cause?** Yes. Each customer symptom maps to one fixed line, and no branch still produces the bad value.

**Would the regression tests fail without the fix?** Checked by reading the original behaviour described in the handoff:
- `quantity multiplies the price` (19.9 × 3 → 59.7): the original returned 19.9, so it fails without the fix.
- `fixed coupon never makes the total negative` (5 − 10): the original returned −5, so it fails.
- `percent coupon leaves the discounted amount` (OFF20 on 100 → 80): the original returned 20, so it fails.
- `percent coupon on a mixed cart` (59.7 + 5 with OFF20 → 51.76): the original returned about 4.98, so it fails.
- `totals are rounded to cents` (0.1 × 3 → 0.3): the original returned 0.30000000000000004, so it fails.
- `unknown coupons are ignored` with `toString`: the original fell into the fixed branch and returned NaN, so it fails.
- `half-percent coupon still applies` (HALF on 10 → 5): this passes on the original code too. It is a guard, not a regression test.

**Hand-checked outputs with the fix:**
- 19.9 × 3 → 59.7.
- 5 with TENOFF → max(0, −5) = 0.
- 100 with OFF20 → 80.
- Mixed cart with OFF20 → about 51.76, rounded to 51.76.
- 0.1 × 3 → 0.3.
- Unknown and inherited coupon names, including `toString` → 10.

**Side effects and callers:** The only consumer in the worktree is `test/cart.test.js`. No other file requires the module. The API is unchanged. The only behaviour change for valid inputs is that totals are now rounded and clamped, which is what the bug report asks for.

**Edge cases and possible regressions (all low severity, outcome still pass):**
1. **Half-cent rounding (`src/cart.js:26`).** `Math.round` on a binary float can round the wrong way at exact half-cents. For example, 1.005 becomes 1.00 rather than 1.01. The handoff already names this residual risk, and nothing in the tests covers it. Whether to use a decimal-safe rounding is for the owner to decide.
2. **Invalid numbers pass through.** `Math.max(0, NaN)` returns NaN, so a missing `price` or `qty` gives NaN rather than an error or a sane value. This existed before the fix, and no test covers it.
3. **Negative inputs are silently clamped.** A negative price or quantity is hidden by the zero clamp, so bad data produces 0 with no signal.
4. **Coupon codes are case-sensitive.** `tenoff` is ignored. This matches the "unknown coupons are ignored" rule, but it is worth confirming that is intended.
5. **Test gaps.** There is no test for a half-cent value, a zero quantity, a non-integer quantity, a NaN input, or a percent coupon on a fractional-cent subtotal.

**Could not verify:**
- I did not execute `npm test` or the regression tests. Atlas is read-only for this step, so I could not confirm the 9-pass result from the handoff or the fail-on-original claims by running them. The results above come from reading the code and doing the arithmetic by hand.
- I did not check the floating-point intermediate values exactly. The rounding outcomes are robust to that for the listed cases, but I did not run them.

**Verdict:** pass. The cause is removed, the regression tests target each reported symptom, and I found no regression in the code paths that existed before. The findings above are for the owner to decide.
