## Architecture & Code Validator: `src/users.js`

**Verdict: fail.** Three defects in `src/users.js` are blocking: an HTML-escaping bug that allows injection, an off-by-one in pagination, and an age check that ignores the birthday. The module is small (28 lines), has no dependencies, and fits the README's description of "a tiny CommonJS module." The layout is fine. The problems are inside the functions.

### Findings (most severe first)

**1. High · Security · `escapeHtml` only escapes the first occurrence of each character**
- **File:** `src/users.js`, lines 17–20 (used by `userRow`, line 25)
- **Reason:** `String.prototype.replace` with a string pattern replaces only the first match. The three calls therefore escape only one `&`, one `<` and one `>`. A name with a second `<` passes through unescaped. For example, `<<img src=x onerror=alert(1)>` becomes `&lt;<img src=x onerror=alert(1)&gt;`, and the second `<` opens a live tag. This is a stored XSS path into the users table.
- **Recommendation:** Use global regexes and escape `&` first:
  ```js
  return String(text)
    .replace(/&/g, '&amp;')
    .replace(/</g, '&lt;')
    .replace(/>/g, '&gt;')
    .replace(/"/g, '&quot;')
    .replace(/'/g, '&#39;');
  ```
  Adding the quote escapes also makes the function safe in attribute values. Its doc comment ("Text safe to put inside HTML") currently overstates what it does.

**2. High · Correctness · `paginate` skips the first page**
- **File:** `src/users.js`, line 5
- **Reason:** The doc comment on line 3 says `page` is 1-based ("1 is the first page"). The code computes `start = page * size`. For `page = 1`, `start = size`, so the first page of items is never returned. Page 2 returns page 3's items, and so on. No input validation exists either: `page = 0` returns the first page, and negative or fractional values produce unpredictable slices.
- **Recommendation:** Use `const start = (page - 1) * size;` and validate that `page` and `size` are positive integers. Throw a `RangeError` otherwise, or document the 0-based behaviour and change the comment to match.

**3. High · Correctness · `isAdult` compares only the year**
- **File:** `src/users.js`, lines 11–12
- **Reason:** The age is `today.getFullYear() - birthDate.getFullYear()`, so a person born on 2008-11-01 is counted as 18 on 2026-10-31, when they are actually 17. The check is also wrong on the exact birthday boundary in the other direction. This is an age gate, so it can admit people below the threshold.
- **Recommendation:** Subtract one year when the birthday has not yet occurred on `today`:
  ```js
  let age = today.getFullYear() - birthDate.getFullYear();
  const m = today.getMonth() - birthDate.getMonth();
  if (m < 0 || (m === 0 && today.getDate() < birthDate.getDate())) age--;
  return age >= 18;
  ```
  Add tests for the day before and the day of the 18th birthday.

**4. Medium · Testing · No tests exist for a module whose `npm test` script expects them**
- **File:** `package.json`, line 1 (`"test": "node --test"`); the repo has no test files (Glob over `**/*` lists only `README.md`, `package.json`, `src/users.js`).
- **Reason:** Running `npm test` in this state exercises nothing. The three defects above would have been caught by simple unit tests for each function.
- **Recommendation:** Add `test/users.test.js` using `node:test` and `node:assert`. Cover each helper, with the cases from findings 1–3 in particular.

**5. Low · Security (documentation accuracy) · Escaping does not cover attribute contexts**
- **File:** `src/users.js`, lines 15–21
- **Reason:** Without quote escaping, `escapeHtml` is unsafe for values placed in quoted attributes. The current caller, `userRow`, uses it only in text content, so this is not exploitable today. It becomes a risk as soon as the helper is reused.
- **Recommendation:** Fixed by the change in finding 1. If the helper stays text-only, state that in the doc comment.
