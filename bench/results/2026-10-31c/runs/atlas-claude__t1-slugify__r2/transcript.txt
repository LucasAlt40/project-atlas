**Goals**

**Decisions the Developer must follow**

1. **Order of operations:** `toLowerCase()`, then `normalize('NFD')`, then remove combining marks with `/[\u0300-\u036f]/g`, then replace runs of non-`[a-z0-9]` with a single `-` using `/[^a-z0-9]+/g`, then trim leading and trailing `-`. Lowercasing first keeps `Ã`/`Ç` handling correct. `ç` decomposes to `c` + U+0327, which the mark regex removes.
2. **Type check first:** `if (typeof text !== 'string') throw new TypeError(...)`. Default `options` to `{}` and treat `null` as `{}` too.
3. **Truncation with `maxLength`** (the subtle part). Let `s` be the slug and `m` be `maxLength`:
   - If `s.length <= m`, return `s`.
   - Let `head = s.slice(0, m)`. If `s[m] === '-'`, the word ends exactly at `m`, so return `head`. This case is required: `'hello-big-world'` with `m = 9` must give `'hello-big'`, and a plain `lastIndexOf` would wrongly return `'hello'`.
   - Otherwise let `i = head.lastIndexOf('-')`. If `i > 0`, return `head.slice(0, i)`.
   - Otherwise the first word does not fit, so return `head` (hard cut).
   - The result never ends with `-`, because the slug has no doubled dashes and `head` is cut before a non-dash character.
4. **Invalid `maxLength`:** The spec only says "optional, a positive integer" and does not say what to do otherwise. I recommend throwing `RangeError` for a non-integer or value below 1, and treating `undefined` as "no limit". This is my choice, not something the spec states. The Developer should follow it unless the task owner says otherwise.
5. **Empty result:** `slugify('!!!')` and `slugify('ß')` return `''`. The spec does not define this, and `''` is the natural result.
6. **Export shape:** exactly `module.exports = { slugify };`.

**Test cases** (`test/slugify.test.js`)
- The five spec examples: `' Olá, Mundo! '`, `'Ação & Reação'`, and the three `maxLength` cases (`9` gives `'hello-big'`, `8` gives `'hello'`, `supercalifragilistic`/`5` gives `'super'`).
- Lowercase output, and accent removal for `é`, `ç`, `ã`, `ü`.
- No leading or trailing `-`, and runs of separators collapse to one `-`.
- `maxLength` exactly equal to the slug length returns the full slug.
- `maxLength` landing on a dash returns the head without a trailing dash.
- Non-string input throws `TypeError`.
- Invalid `maxLength` throws `RangeError`, if decision 4 is adopted.
- An empty or all-symbol input returns `''`.

**Files to change:** `src/slugify.js` (new) and `test/slugify.test.js` (new). Nothing else.

**Risks**
- The `maxLength` boundary, especially the `s[m] === '-'` case, is the easiest place to get a bug. The tests above cover it.
