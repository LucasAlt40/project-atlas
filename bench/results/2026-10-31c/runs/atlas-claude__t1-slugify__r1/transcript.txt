### Design (decisions the Developer must follow)
1. **Type check first.** `if (typeof text !== 'string') throw new TypeError(...)`. This runs before any other work.
2. **Normalization pipeline, in this order:**
   - `text.toLowerCase()`
   - `.normalize('NFD').replace(/[\u0300-\u036f]/g, '')`. NFD is required, because the combining-mark strip does nothing on precomposed characters.
   - `.replace(/[^a-z0-9]+/g, '-')`. This collapses each run of non-alphanumerics into one `-`.
   - Strip leading and trailing `-`, e.g. `/^-+|-+$/g`.
3. **`maxLength` validation (my choice, since the spec does not cover it):** if `options` is given and `maxLength` is `undefined`, skip truncation. Otherwise, a non-integer `maxLength` throws `TypeError`, and an integer below 1 throws `RangeError`. Both are caller errors.
4. **Truncation rule.** If `slug.length <= maxLength`, return the slug unchanged. Otherwise:
   - `window = slug.slice(0, maxLength + 1)`
   - `idx = window.lastIndexOf('-')`
   - If `idx > 0`, return `slug.slice(0, idx)`. Since the slug never starts with `-`, `idx > 0` is equivalent to `idx !== -1`.
   - Otherwise (no dash in the window), return `slug.slice(0, maxLength)`, a hard cut.

   Why the `maxLength + 1` window: it handles the case where the character at `maxLength` is itself `-`. The result never ends in `-`, because the cut removes the dash and the character before it is a letter or digit.
5. **Empty results.** Input with no a-z or 0-9 (e.g. `''` or `'!!!'`) returns `''`. The spec does not say, so this is my choice.
