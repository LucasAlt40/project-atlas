## Architecture and impact

The project has two small boundaries:

- `src/store.js`: owns todo state, validation, mutation, copying, and list ordering.
- `src/format.js`: pure presentation logic over todo-shaped objects.

`test/store.test.js` covers both boundaries. There are no runtime dependencies; tests use Node’s built-in test runner.

The change belongs entirely within these existing boundaries. Priority validation and ordering should remain store concerns, while the `!` marker should remain formatting concern. No shared abstraction is needed for the three-value priority domain.

## Developer decisions

- Preserve `add(title)` compatibility by treating omitted `options` as `{}`.
- Accept only `'low'`, `'normal'`, and `'high'`; invalid values throw `RangeError`.
- Store the resolved priority on every todo, including todos created without options.
- Keep `list()` defensive-copy behavior.
- With `filter.priority`, return only matching todos.
- Without a filter, order todos by `high`, `normal`, then `low`; retain insertion order for equal priorities. An explicit comparator returning `0` for equal priorities should preserve this contract.
- Keep formatting unchanged for normal and low priorities, and render high priority as `[ ] !Title` or `[x] !Title`.
- Existing manually constructed todo objects without `priority` must continue formatting as before.

  - Add the high-priority marker without changing checkbox or title behavior.

No new files or dependencies are required.
