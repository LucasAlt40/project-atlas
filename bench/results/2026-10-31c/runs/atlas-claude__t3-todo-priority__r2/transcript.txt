## Plan: priorities for the todo store

**Goal:** add a `priority` field (`low` | `normal` | `high`) to todos, filter and sort in `store.list`, and mark high-priority rows with `!` in `formatList`. Existing behaviour and tests must not change.

**Scope in:** `src/store.js` (`add`, `list`), `src/format.js` (`formatList`), `test/store.test.js` (new tests).

**Scope out:** `complete`, the README, persistence (the store is in-memory only), a CLI, and any new modules or dependencies.

### Current state (verified by reading)
- `src/store.js`: `createStore()` returns `add(title)`, `complete(id)` and `list()`. `add` validates the title, then pushes `{id, title, done}`. `list()` returns shallow copies in insertion order, so a `priority` field would be copied automatically.
- `src/format.js`: `formatList` maps each todo to `[x]`/`[ ]` plus the title. It has no dependency on the store.
- `test/store.test.js`: one file that covers both modules, using `node:test` and `node:assert`. `package.json` runs `node --test`. Baseline `npm test`: 4 pass, 0 fail.

### Steps
1. **store.js, `add(title, options)`**
   - Add a module-level constant: `PRIORITY_RANK = { high: 0, normal: 1, low: 2 }`. Its keys are the valid priorities.
   - Default `options` to `{}`. `priority = options.priority === undefined ? 'normal' : options.priority`.
   - If `priority` is not an own key of `PRIORITY_RANK`, throw `RangeError`.
   - Run all validation before `nextId++`, so a rejected add does not consume an id.
   - Store `priority` on the todo object.
2. **store.js, `list(filter = {})`**
   - Build the copies as today.
   - If `filter.priority` is set, keep only the todos with that priority.
   - Without a filter, sort by `PRIORITY_RANK`. `Array.prototype.sort` is stable in Node, so insertion order is kept within each priority.
   - With a filter, keep the insertion order (all items share one priority, so this is the same result).
3. **format.js, `formatList`**
   - Prefix the title with `!` when `t.priority === 'high'`: `` `[${mark}] ${prefix}${t.title}` ``.
   - Leave `normal`, `low` and todos with no `priority` field exactly as they are now. The existing `format` test uses todos without that field, so it must still pass.
   - Keep the literal `'high'` in `format.js`. Importing the store's constant would couple the formatter to the store for one string.
4. **test/store.test.js**: append tests to the existing file, following its one-file convention.
   - Default priority is `normal`; explicit priority is stored on the todo.
   - An invalid priority (`'urgent'`, `'HIGH'`, `null`, `''`) throws `RangeError`. A following `add` gets id 1 or the next expected id, showing no id was consumed.
   - `list({ priority: 'high' })` returns only high todos, in insertion order.
   - `list()` orders high, normal, low; ties keep insertion order.
   - `list()` still returns copies, so mutating a result does not change the store.
   - `formatList` gives `[ ] !Pay rent` for high; normal and low have no `!`; a todo without a `priority` field formats as before.

### Files to change

Nothing else. `README.md` is not required by the task.
