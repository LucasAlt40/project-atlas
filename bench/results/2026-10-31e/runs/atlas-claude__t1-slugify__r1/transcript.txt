# Plan: `slugify(text, options)`

**Goal:** add a CommonJS slug utility at `src/slugify.js` with tests at `test/slugify.test.js`, runnable with `npm test`.

**In scope:** `src/slugify.js` (new), `test/slugify.test.js` (new).
**Out of scope:** `package.json`, `README.md`, any other file, any dependency, any change to the existing `"type": "commonjs"` setup.

## Architecture impact
- A leaf module with no imports and no I/O. Nothing else in the project depends on it.
- The test runner is the built-in `node --test`, which picks up `test/*.test.js` by default. No config changes are needed.

## Decisions the Developer must follow
1. **Export shape:** `module.exports = { slugify };` with a named `function slugify(text, options)` declaration.
2. **Type check first:** `if (typeof text !== 'string') throw new TypeError(...)`. This covers `null`, `undefined`, numbers and arrays.
3. **Pipeline, in this order:**
   - `text.toLowerCase()`
   - `.normalize('NFD').replace(/[\u0300-\u036f]/g, '')` to strip diacritics (`é→e`, `ç→c`, `ã→a`, `ü→u`)
   - `.replace(/[^a-z0-9]+/g, '-')` so each run of other characters becomes one `-`
   - strip leading and trailing `-` with `.replace(/^-+|-+$/g, '')`
4. **Non-decomposable letters** (`ß`, `ø`, `æ`, `œ`) are not in `a-z`, so they become `-` under rule 3. This is the literal reading of the spec. `'straße'` becomes `'stra-e'`.
5. **`maxLength` handling:**
   - If `options` is absent, or `maxLength` is `undefined`, no truncation happens.
   - If `slug.length <= maxLength`, return the slug unchanged.
   - Otherwise, let `i = slug.slice(0, maxLength + 1).lastIndexOf('-')`. If `i > 0`, return `slug.slice(0, i)`. If `i` is `-1`, return `slug.slice(0, maxLength)`.
   - This never ends with `-`: the prefix before a found `-` has no `-` in it, and the hard cut contains no `-` by construction.
6. **Invalid `maxLength`:** the spec does not say what happens. I recommend throwing `TypeError` for a non-integer and `RangeError` for an integer below 1. This is my decision, not the spec's, so the Developer should keep it and say so in the summary.
7. **Style:** match the existing project style. There is no existing code yet, so use 2-space indentation, single quotes and semicolons. Keep comments minimal; one short comment on the truncation rule is enough.

## Test cases
- The five examples from the spec: `' Olá, Mundo! '`→`'ola-mundo'`, `'Ação & Reação'`→`'acao-reacao'`, and the three `maxLength` cases (9→`'hello-big'`, 8→`'hello'`, and `'supercalifragilistic'` with 5→`'super'`).
- Lowercasing, and each accent example (`é`, `ç`, `ã`, `ü`).
- A run of symbols collapses to one `-`, and leading or trailing punctuation is trimmed.
- Empty string returns `''`. A whitespace-only string returns `''`.
- `maxLength` edge cases:
  - a hard cut when the first word does not fit (`'hello big world'`, 3→`'hel'`)
  - a cut where the character at `maxLength` is `-` (`'hello big'`, 5→`'hello'`)
  - a result never ends with `-` across several lengths
  - a `maxLength` at or above the slug length returns it unchanged
- Throws `TypeError` for `null`, `undefined`, `42`, and `['a']`.
- If decision 6 is kept: throws for `maxLength` of `0`, `-1`, `2.5`, and `'5'`.

- **Test discovery:** `node --test` discovers `test/*.test.js` under Node's default patterns. If `npm test` runs zero tests, the Developer should check the Node version and pass the file path explicitly.
