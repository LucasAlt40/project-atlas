The implementation should use standard JavaScript string normalization (`NFD`) and built-in regular expressions. No abstraction layer is warranted for this isolated utility.

### Architectural impact and decisions

- The change adds one independently testable utility with no new coupling.
- `module.exports = { slugify }` is the required public contract.
- Processing order should be: validate string → normalize/decompose Unicode → remove combining marks → lowercase → replace each non-ASCII-alphanumeric run with `-` → trim hyphens → apply length policy.
- Length truncation must prefer the last separator that fits, while hard-cutting the first word when it alone exceeds the limit.
- Existing project conventions are preserved: CommonJS, no dependencies, and built-in Node tests.
- Tests should include the supplied examples plus boundary cases for accents, punctuation runs, leading/trailing separators, non-string input, exact length, and first-word hard cuts.

- `src/slugify.js`
  - Export: `module.exports = { slugify }`.
  - Function: `slugify(text, options)`.
  - Throws `TypeError` when `text` is not a string.
- `test/slugify.test.js`
  - Import via `require('../src/slugify')`.
  - Use `node:test` and `node:assert`.
  - No other files should be modified.
