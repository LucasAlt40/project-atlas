## Verification report: cart total fix

**Verdict: pass.** The fix addresses the root cause for all four reported symptoms. The existing suite passes. Two low-severity hardening notes are listed below for the team to decide on.

### Root cause (from the original bug report, traced against the fixed code)
- **Quantity ignored:** the line total did not multiply by `qty`, so 3 × 19.90 became 19.9.
- **Fixed coupon unclamped:** TENOFF was subtracted with no floor, so 5.00 − 10 gave −5.
- **Percent coupon returned the discount:** OFF20 returned `sum * 20 / 100` (20) rather than `sum − discount` (80).
- **No cent rounding:** float sums like 0.1 + 0.2 were returned as 0.30000000000000004.
- **Inherited keys:** a lookup such as `COUPONS['toString']` found a non-coupon property, which produced NaN.

### Fix applied (src/cart.js:13–29)
- Line totals use `price * qty` (src/cart.js:16).
- The coupon is looked up only when `Object.prototype.hasOwnProperty.call(COUPONS, couponCode)` holds (src/cart.js:18–20). Unknown codes and inherited keys are ignored.
- Percent coupons subtract the discount from the sum (src/cart.js:22–23). Fixed coupons subtract their value (src/cart.js:25).
- The return is `Math.max(0, Math.round(sum * 100) / 100)` (src/cart.js:28), which floors at zero and rounds to cents in one step.
- The export is unchanged: `module.exports = { total }` (src/cart.js:31).

### Validation evidence
- **Executed:** `npm test` ran `node --test` and reported 8 tests, 8 pass, 0 fail. The suite includes `multiplies price by quantity` (59.7), `fixed coupon never makes the total negative` (0), `percent coupon returns the discounted total` (80), `totals are rounded to cents` (0.3) and `unknown coupons are ignored`, including `'toString'`.
- **Read:** I traced each reported scenario through src/cart.js by hand and each gives the expected value.
- **Read:** test/cart.test.js has 37 lines and 8 tests. The handoff says the change added 25 lines and 6 regression tests. I could not run `git diff` in this read-only session, so I could not confirm which tests are new.
- **Reasoned, not executed:** each new test should fail on the pre-fix code. Missing quantity gives 19.9 instead of 59.7. The unclamped TENOFF gives −5. The old percent path gives 20 instead of 80. Unrounded floats give 0.30000000000000004. Without the `hasOwnProperty` guard, `'toString'` produces NaN. I could not confirm this by running the pre-fix file.

### Side effects and callers
- The only consumer found is the `total` export. I could not search the wider repository for other callers with the tools available, so that scope is unverified.
- The change keeps the signature `total(items, couponCode)` and the return type (a number).
- Empty cart: `total([])` gives 0.
- `null` or `undefined` coupon codes are ignored, because `'null'` and `'undefined'` are not own keys.

### Findings
- **Low, rounding (hardening, not reported as a bug):** `Math.round(x * 100) / 100` can round exact half-cents the wrong way because of float representation. For example, 1.005 becomes 100.49999999999999 before rounding, so the result is 1.00 rather than 1.01. The reported examples do not hit this. The fix is to compute in integer cents. Reasoned from IEEE 754 behaviour, not executed.
- **Low, behaviour:** coupon codes are case-sensitive, so `tenoff` is ignored. This matches the original code and the spec does not mention case. The product owner should confirm.
- **Low, hardening:** a non-numeric `price` or missing `qty` gives NaN, which is then returned unchanged because `Math.max(0, NaN)` is NaN. The spec does not cover invalid input.

### What remains unverified
- The pre-fix failure of the new tests (reasoned only).
- The exact list of new tests, since `git diff` was not available.
- Callers outside src/cart.js.
- The 1.005 half-cent case, which I did not execute.
