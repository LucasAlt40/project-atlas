## Verdict: fail

Four defects in `src/users.js` must be fixed before this is accepted. Two are functional bugs, one is an XSS hole, and the test script has nothing behind it.

## Findings (most severe first)

**1. escapeHtml only escapes the first occurrence of each character (High, Security)**
- File: `src/users.js`, lines 17–20
- Why it is wrong: `String.prototype.replace` with a string pattern replaces only the first match. `'<<img onerror=alert(1)>>'` becomes `'&lt;<img onerror=alert(1)>>'`, so the second `<` and the `>` pass through raw. The function's doc comment says "Text safe to put inside HTML", and it is not. The `&` replacement happens to be correct only because it runs first. (This is language semantics, which I'm confident of, but I have not executed it.)
- Recommendation: use global regexes, or a map:
  ```js
  const HTML_ESCAPES = { '&': '&amp;', '<': '&lt;', '>': '&gt;', '"': '&quot;', "'": '&#39;' };
  function escapeHtml(text) {
    return String(text).replace(/[&<>"']/g, (ch) => HTML_ESCAPES[ch]);
  }
  ```

**2. escapeHtml does not escape quotes (Medium, Security)**
- File: `src/users.js`, lines 15–21
- Why it is wrong: the doc comment promises safety "inside HTML" generally, but `"` and `'` are not escaped. Any caller that puts the result inside a quoted attribute can break out of it. `userRow` (line 25) only uses it in element text, so it is not exploitable there today. The gap is in the helper's contract, and it will bite the next caller.
- Recommendation: include `"` → `&quot;` and `'` → `&#39;` (covered by the fix above).

**3. paginate is off by one for 1-based pages (High, Correctness)**
- File: `src/users.js`, lines 3–6
- Why it is wrong: the doc says `page` is 1-based ("1 is the first page"), but `start = page * size`. Page 1 with size 10 returns items 10–19 and skips items 0–9. Page 0 would be the first page, which contradicts the doc.
- Recommendation: `const start = (page - 1) * size;` and add a guard for `page < 1` (throw or clamp), since the current code silently returns wrong data for it.

**4. isAdult ignores month and day (High, Correctness)**
- File: `src/users.js`, lines 10–12
- Why it is wrong: it subtracts only the birth year. Someone born 2008-12-31 is treated as an adult on 2026-10-30, when their real age is 17. The error is up to a year in each direction at the threshold. If this gates age-restricted content or actions, it is an access-control bug.
- Recommendation: compute the age from the full date, e.g.
  ```js
  let age = today.getFullYear() - birthDate.getFullYear();
  const m = today.getMonth() - birthDate.getMonth();
  if (m < 0 || (m === 0 && today.getDate() < birthDate.getDate())) age--;
  return age >= 18;
  ```
  Also consider rejecting invalid dates (`isNaN(birthDate)`), which currently yield `NaN >= 18 === false`, silently.

**5. Declared test script with no tests (Medium, Testing)**
- File: `package.json`, line 1 (`"test": "node --test"`); no test files exist in the repo.
- Why it matters: none of the four defects above would be caught. `node --test` with no test files exits without testing anything, so a green run means nothing.
- Recommendation: add `test/users.test.js` using `node:test` and `node:assert`, with cases for: page 1 returns the first slice; the 18th birthday on the exact day and the day before; `escapeHtml('<<a>>')` and quote escaping; `userRow` output for admin and non-admin users.
