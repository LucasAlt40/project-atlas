# Plan: Add priorities to todos

## Goals

- Add validated `low`, `normal`, and `high` priorities to `store.add`.
- Default omitted priority to `normal`.
- Store priority on every todo.
- Filter and sort todos by priority.
- Mark high-priority todos with `!` in `formatList`.
- Preserve all existing behavior and tests.

## Scope

In scope:

- `src/store.js`
- `src/format.js`
- Tests under `test/`
- Plan document: `docs/plans/todo-priorities.md`

Out of scope:

- Persistence, new modules, dependencies, CLI/UI changes, or changes to IDs, completion, and title validation.

## Architecture and dependencies

`src/store.js` remains the domain boundary. It owns priority validation, defaults, filtering, and ordering. The existing in-memory array remains the source of insertion order.

`src/format.js` remains a pure presentation function. It will inspect `priority` only to add `!` for high-priority items. Missing priority fields should retain the existing rendering.

Tests continue using Node’s built-in test runner and existing module boundaries.

## Decisions for implementation

1. `add(title, options)` treats omitted options as `{}`.
2. Valid priorities are exactly `low`, `normal`, and `high`.
3. Invalid add priorities throw `RangeError`; invalid titles continue throwing `TypeError`.
4. Every todo includes `priority`, defaulting to `normal`.
5. `list(filter)` returns shallow copies.
6. `list({ priority })` uses strict matching; unspecified invalid-filter behavior will not introduce a new exception contract.
7. Unfiltered results are ordered high, normal, low, while preserving insertion order within each priority.
8. Sorting must not mutate the internal todo array.
9. `formatList` renders only high priority with `!`, for example `[ ] !Pay rent`; other priorities and legacy objects retain existing output.

## Files and contracts

- `src/store.js`
  - Extend `add` to accept options and return `{ id, title, done, priority }`.
  - Extend `list` with filtering and stable priority ordering.
- `src/format.js`
  - Add the high-priority marker.
- `test/store.test.js`
  - Add coverage for defaults, valid and invalid priorities, ordering, filtering, and formatting.
- `docs/plans/todo-priorities.md`
  - Saved implementation plan for handoff.

## Risks and trade-offs

- Sorting each list result is `O(n log n)`, but is appropriate for this small in-memory store and avoids maintaining another index.
- The internal array must not be sorted in place, or future operations could lose insertion-order semantics.
- Filter behavior remains intentionally minimal because the task specifies validation only for `add` options.

- Confirm all existing tests still pass.
- Verify defaulting, `RangeError`, stable priority ordering, filtering, and exact formatting.
- Review the diff for changes limited to the planned files.
