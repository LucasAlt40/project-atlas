## Verdict: FAIL

Three of the four helpers have defects that produce wrong results. One of them, `escapeHtml`, is an XSS hole. Nothing in the repo exercises these helpers, so none of the defects would have been caught.

## Findings (most severe first)

**1. Security: `escapeHtml` leaves HTML injection open (high)**
- **File:** `src/users.js:18-20`
- **Reason:** `String.prototype.replace` with a string pattern replaces only the first occurrence. `escapeHtml('<script>a</script><script>')` leaves the second `<` and `>` unescaped in the output. Because `userRow` (line 25) passes user-controlled `user.name` through this function into HTML, a name containing a second `<` or `>` is injected as markup. Double quotes and single quotes are also never escaped, so the output is unsafe inside attribute values.
- **Recommendation:** Use global regexes and cover quotes too:
  ```js
  return String(text)
    .replace(/&/g, '&amp;')
    .replace(/</g, '&lt;')
    .replace(/>/g, '&gt;')
    .replace(/"/g, '&quot;')
    .replace(/'/g, '&#39;');
  ```
  The `&` replacement must stay first, as it is now, or the other entities get double-escaped.

**2. Correctness: `paginate` skips the first page (high)**
- **File:** `src/users.js:3-6`
- **Reason:** The doc comment on line 3 says "1 is the first page", but line 5 computes `start = page * size`. With that formula, `page = 1` returns items `size..2*size-1`, so the first `size` items are never reachable from page 1. `page = 0` gives the first page, which contradicts the documented contract.
- **Recommendation:** Use `const start = (page - 1) * size;`, and reject `page < 1` explicitly (throw or clamp) rather than returning a slice from a negative offset.

**3. Correctness: `isAdult` ignores month and day (high)**
- **File:** `src/users.js:10-12`
- **Reason:** `age` is computed from the year difference alone. Someone born on 2008-12-31 is reported as an adult on 2026-01-01 (age "18" by year difference) but is actually 17. The function's doc comment promises "18 or older on `today`", so it is wrong for roughly 364 days of every year for anyone turning 18 in the year being checked, and it can wrongly deny or grant access in an age-gated flow.
- **Recommendation:** Compute the actual age, decrementing when the birthday has not yet occurred on `today`:
  ```js
  let age = today.getFullYear() - birthDate.getFullYear();
  const m = today.getMonth() - birthDate.getMonth();
  if (m < 0 || (m === 0 && today.getDate() < birthDate.getDate())) age--;
  return age >= 18;
  ```
  Note that this uses local-time getters; if the birth dates are stored as UTC, use the `getUTC*` variants consistently.

**4. Testing: no tests exist for these helpers (warning)**
- **File:** repository root. `package.json:1` declares `"test": "node --test"`, but the Glob shows no test files and no test references to `paginate`, `isAdult`, `escapeHtml` or `userRow` anywhere in the repo.
- **Reason:** The three defects above would each be caught by a one-line test (for example, `escapeHtml` with two `<` characters, `paginate(items, 1, 10)`, or `isAdult` on a birthday one day in the future). Their absence is why they reached the file.
- **Recommendation:** Add `test/users.test.js` using `node:test` and `node:assert` covering the cases above, and run `npm test`.

**5. Maintainability: `userRow` does not guard against missing data (warning)**
- **File:** `src/users.js:25`
- **Reason:** If `user.name` is `undefined`, `escapeHtml` renders the literal string `"undefined"` into the table, and a `null` name renders as `"null"`. This is not a crash, but it silently puts garbage into the page.
- **Recommendation:** Decide the intended behaviour for a missing name (empty string or a validation error) and handle it explicitly, rather than relying on `String(undefined)`.
