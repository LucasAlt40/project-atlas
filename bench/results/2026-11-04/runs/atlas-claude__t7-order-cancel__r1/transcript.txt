## Plan: order cancellation

**Goal:** add `orders.cancel(orderId, reason)` so cancelled orders return their stock, record status and reason, emit one `order.cancelled` event, and drop out of `reports.revenue()` and `reports.unitsSold(sku)`.

**In scope:** `src/orders.js`, `src/inventory.js`, `src/reports.js`, `test/shop.test.js`.

**Out of scope:** `src/shop.js` (wiring is unchanged, since `createOrders` already receives `inventory` and `bus`), `src/events.js`, README, price or refund logic, and any change to `place()`'s behaviour.

**Architecture impact:** `inventory` gains a write operation it never had (restock). `reports` gains a dependency on the order `status` value. Both are small, one-directional couplings and stay inside the existing dependency graph: `shop → orders → inventory, bus`, `shop → reports → orders`.

### Decisions for the Developer

1. **Restock method:** add `restock(sku, qty)` to `createInventory` in `src/inventory.js`. It does `stock.set(sku, (stock.get(sku) ?? 0) + qty)`. Do not reuse `take` with a negative quantity.
2. **Validation order in `cancel`:** check the reason first (`TypeError`), then look up the order (`Error` containing "not found"), then check the status (`Error` containing "already cancelled"). Every validation runs before any mutation, so a failed call changes nothing.
3. **Reason rule:** a reason is valid only if `typeof reason === 'string' && reason.trim() !== ''`. Whitespace-only counts as empty. Keep the reason as given, without trimming.
4. **Status and state:** set `status: 'cancelled'` and `reason` on the stored order object inside the closure's `Map`, not on a copy. `get()` and `all()` already return copies, so changes to the stored object are visible to them.
5. **Stock and event order:** restock every item from the stored order's `items`, set the status, then emit `order.cancelled` with exactly `{ orderId, reason }`. Emitting once, after all state changes, matches how `place()` emits.
6. **Return value:** return a copy shaped like `place()`'s return (`{ ...order, items: copied }`).
7. **Reports filter:** filter `o.status !== 'cancelled'` inside `revenue()` and `unitsSold()` in `src/reports.js`. Leave `orders.all()` returning every order, so listing still shows cancelled orders.
8. **Tests:** add them to `test/shop.test.js`, in the same style as the existing tests. The file uses one shared `setup()`.

### Files and contracts

- `src/inventory.js`: new `restock(sku, qty)`.
- `src/orders.js`: new `cancel(orderId, reason)`. Order records gain `reason` (set only when cancelled) and a `status` of `'cancelled'`. The event payload is `{ orderId, reason }`.
- `src/reports.js`: `revenue()` and `unitsSold(sku)` skip cancelled orders.
- `test/shop.test.js`: new cases (below).

### Verification

- The three existing tests still pass with `npm test`.
- New tests:
  - Cancel restores stock, sets `status` and `reason`, and returns the cancelled order.
  - Exactly one `order.cancelled` event with `{ orderId, reason }` is emitted.
  - An unknown id throws an `Error` containing "not found".
  - Cancelling twice throws an `Error` containing "already cancelled", and the second call changes no stock and emits nothing.
  - An empty, whitespace-only, or non-string reason throws a `TypeError`, and nothing changes.
  - After a cancel, `revenue()` and `unitsSold()` exclude that order, while the other orders are still counted.
- Run `npm test`. The expected result is all tests passing.

### Risks

- **Mutating copies:** if the developer changes a copy returned by `get()` or `all()`, the cancel is silently lost. Mutate the stored object only.
- **Handler failures:** `bus.emit` is synchronous. If a subscriber throws, the stock and status changes are already applied. `place()` has the same property, so this is a known trait of the bus, not something this change introduces.
- **Status string coupling:** `reports` now depends on the literal `'cancelled'`. This is acceptable for a three-module codebase. A helper would be an abstraction the task does not need.
