## Plan: token-bucket limiter (`src/limiter.js`)

**What I found.** The worktree has `package.json` (`"type": "commonjs"`, `"test": "node --test"`) and a one-line `README.md`. There is no `src/` or `test/` directory yet. The repo has no dependencies, so the module should use only built-ins.

**Goals.** Add `src/limiter.js` exporting exactly `module.exports = { createLimiter }`. Add `test/limiter.test.js` using `node:test` and `node:assert`. Touch no other file.

**Out of scope.** Changes to `package.json`, `README.md`, or any other file. Async waiting or timers. Per-key limiters. Exporting a class.

**Architecture.** One module, one factory. `createLimiter` returns a plain object of closures over two pieces of private state: `tokens` (a float) and `last` (the reference timestamp in ms). There are no classes and no helper modules, because the task does not need them. The module depends on nothing except the injected `now` (default `Date.now`).

**Decisions the Developer must follow**

1. **Validation at creation.** `capacity` must satisfy `Number.isInteger(c) && c > 0`. `refillPerSecond` must satisfy `typeof r === 'number' && Number.isFinite(r) && r > 0`. Either failure throws `RangeError`. A missing `options` argument should fall through to the `capacity` check, so `options = {}` is the default.
2. **`now` handling.** If `options.now` is `undefined`, use `Date.now`. If it is provided but is not a function, throw `TypeError`. The spec does not cover this case, so this is my choice; the user can redirect it.
3. **Single refill routine.** `refill()` reads `t = now()`. If `t < last`, set `last = t` and add nothing. Otherwise `tokens = min(capacity, tokens + (t - last) * refillPerSecond / 1000)`, then `last = t`. `tryRemove`, `available` and `msUntil` each call `refill()` first.
4. **Argument checks for `n`.** `n` must be an integer greater than 0, or `RangeError`. If `n > capacity`, throw `RangeError` from both `tryRemove` and `msUntil`. The default is `n = 1`.
5. **Float tolerance.** Use one constant `EPS = 1e-9`. `available()` returns `Math.floor(tokens + EPS)`. `tryRemove` compares `tokens + EPS >= n`. `msUntil` returns `Math.max(0, Math.ceil((n - tokens) * 1000 / refillPerSecond - EPS))`. Without this, rates such as `0.3` can produce results off by one millisecond or one token.
6. **`reset()`.** Call `refill()` first so the reference time moves to now, then set `tokens = capacity`.
7. **Return shape.** The returned object has exactly four methods: `tryRemove`, `available`, `msUntil`, `reset`.

**Files and contracts**

- `src/limiter.js` (new): `createLimiter(options)` returns `{ tryRemove(n = 1), available(), msUntil(n = 1), reset() }`.
- `test/limiter.test.js` (new): tests described below.

**Verification**

- `npm test` runs `node --test` and must pass. Node finds `test/*.test.js` by default.
- Tests use an injected fake clock, a mutable `t` that the test advances.
- Cases to cover:
  - Each invalid `capacity` and `refillPerSecond` value throws `RangeError`. The list is 0, negative, 1.5 for capacity, a string, `NaN`, `Infinity`, and missing.
  - The bucket starts full.
  - `tryRemove` returns `false` and removes nothing when tokens are short.
  - A fractional rate (0.5/s) gives 0 tokens at 1000 ms and 1 token at 2000 ms.
  - Tokens never exceed capacity after a long wait.
  - Invalid `n` (0, -1, 1.5, `'2'`) throws `RangeError`. `n > capacity` throws `RangeError`.
  - `available()` floors the value.
  - `msUntil` returns 0 when tokens are available. For an empty bucket at 0.5/s, `msUntil(1)` is 2000. Waiting exactly that long makes `tryRemove(1)` succeed.
  - `reset()` restores a full bucket.
  - A backwards clock adds no tokens and removes none. After the clock moves backwards, refill resumes from the new reference.
  - `Object.keys(require('../src/limiter.js'))` equals `['createLimiter']`.

**Risks**

- Float accumulation near integer boundaries. Mitigated by decision 5 and a test with a rate such as 0.3/s.
- The `now` non-function case is my assumption, not part of the spec. Easy to change.

**Low-severity findings (not failures)**

1. **Invalid clock value drops an interval.** If `now()` returns `NaN` once, `t > last` is false, so that interval's tokens are lost and `last` becomes `NaN`. The next valid time recovers. A `now()` that always returns `NaN` stalls refill entirely. (`src/limiter.js:31-37`; reasoned, not executed.)
2. **Tiny refill rate can return `Infinity`.** With `refillPerSecond` near `1e-320`, `msUntil()` computes `Math.ceil(Infinity)`, which returns `Infinity`, not a millisecond count. The spec does not cover this. (`src/limiter.js:62`; reasoned.)
3. **`createLimiter(null)` throws `TypeError`, not `RangeError`.** The destructuring on line 14 fails before validation. The spec only covers missing or invalid fields. (`src/limiter.js:14`; reasoned.)
4. **Small rounding in `available()`.** `Math.floor(tokens + EPS)` can report one whole token when the true balance is `n - 5e-10`. This is the intended float tolerance and is well inside any practical use. (`src/limiter.js:52`.)
5. **Coverage gaps (nice-to-have):**
   - No test that `tryRemove(capacity)` succeeds exactly at the boundary.
   - No test of `tryRemove` or `msUntil` after a clock regression; only `available()` is covered.
   - No test of `reset()` after a clock regression or after a partial refill.
