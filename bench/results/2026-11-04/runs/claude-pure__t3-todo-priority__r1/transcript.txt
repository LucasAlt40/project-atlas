**What changed**

- **`src/store.js`**
  - `add(title, { priority = 'normal' } = {})` validates the priority and stores it on the todo. Anything other than `'low'`, `'normal'` or `'high'` throws a `RangeError`. The title check still runs first and throws `TypeError` as before.
  - `list(filter = {})` filters by `filter.priority` when given, then sorts high, normal, low. `Array.prototype.sort` is stable in current Node, so insertion order holds within each priority. The sort runs on a filtered copy, so the stored order is never changed.
- **`src/format.js`**: a todo with `priority === 'high'` renders as `[ ] !Pay rent`. Other todos, including ones with no priority field, render as before.
- **`test/priority.test.js`** (new): covers the default, storage, invalid values, sort order, the filter, that completion state is unaffected, that returned copies are independent, and the `!` marker. The existing `test/store.test.js` is unchanged.

**Not verified:** I checked the code by reading it, not by running it, so please run `npm test` before relying on this. The existing tests should still pass, since the only behaviour change for them is the new `priority` field and the sort, and the old test data has no priorities.
