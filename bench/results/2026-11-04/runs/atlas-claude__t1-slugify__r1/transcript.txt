### Design for `src/slugify.js`
Single exported function `slugify(text, options = {})`. Steps, in order:

1. **Type check.** `if (typeof text !== 'string') throw new TypeError(...)`.
2. **Accent removal first, then lowercase.** `text.normalize('NFD').replace(/[\u0300-\u036f]/g, '')`, then `.toLowerCase()`. The order matters: lowercasing before stripping turns `İ` into `i` + U+0307, which the strip would then leave in place. Stripping first avoids that.
3. **Collapse non-alphanumerics.** `.replace(/[^a-z0-9]+/g, '-')`. This covers rule 3, and the run collapse covers "single `-`".
4. **Trim dashes.** `.replace(/^-+|-+$/g, '')`. Rule 4.
5. **`maxLength`, only if provided.** Validate first: `if (maxLength !== undefined && (!Number.isInteger(maxLength) || maxLength < 1)) throw new RangeError(...)`. Then:
   - If `slug.length <= maxLength`, return `slug`.
   - Otherwise `head = slug.slice(0, maxLength + 1)`. Let `idx = head.lastIndexOf('-')`. If `idx > 0`, return `slug.slice(0, idx)`. This keeps only whole words and never ends in `-`, because the char at `idx` is excluded.
   - Otherwise (the first word alone is too long), return `slug.slice(0, maxLength)`. Since that window has no `-`, the result cannot end in `-`.

Checked by hand against the spec examples:
- `'hello big world'`, max 9: `slug` is `hello-big-world`. `head` is `hello-big-`, `idx` is 9, result `hello-big`. ✓
- Same string, max 8: `head` is `hello-big`, `idx` is 5, result `hello`. ✓
- `'supercalifragilistic'`, max 5: `head` is `superc`, no `-`, hard cut to `super`. ✓

The file should be short, with a brief comment on the ordering in step 2 and on the cut rule in step 5. The repo has no comment style to match yet, so keep comments minimal.

### Tests for `test/slugify.test.js`
Use `const { test } = require('node:test')` and `const assert = require('node:assert')`. Use `assert.strictEqual` and `assert.throws`.
- The five spec examples, one `test` each or grouped.
- Accents: `'Ç'`, `'ã'`, `'ü'`, and `'Crème Brûlée'` → `creme-brulee`.
- Lowercasing: `'HELLO'` → `hello`.
- Digits kept: `'Room 101'` → `room-101`.
- Punctuation runs and edges: `'  --a!!!b--  '` → `a-b`.
- Empty and all-punctuation: `''` → `''`, `'!!!'` → `''`.
- `maxLength` exact fit: `slugify('abc', { maxLength: 3 })` → `abc`.
- `maxLength` cut lands on a dash: `'ab-cd'` with max 3 → `ab`, and the result must not end in `-`. Also `'ab-cdefgh'` with max 3 → `ab`.
- Non-string input throws `TypeError` for `123`, `null`, `undefined`, and `['a']`.
- Invalid `maxLength` (0, -1, 2.5, `'5'`) throws `RangeError`.

### Decisions the Developer must follow
1. Export shape is exactly `module.exports = { slugify };`. No default export.
2. Normalize with NFD, strip `\u0300-\u036f`, then lowercase, in that order.
3. Characters with no NFD decomposition (`ø`, `æ`, `ß`, `đ`) become `-` by rule 3. This is the literal reading of the spec. `'Søren'` becomes `s-ren`. This is a real limitation, not a bug in the code. If the user wants `ø`→`o` etc., that is a follow-up decision.
4. Invalid `maxLength` throws `RangeError`, including non-number values. The spec does not specify this, so this is my choice.
5. An input with no `a-z0-9` characters returns `''`. The spec does not specify this either.
6. The `maxLength` truncation rule is as in the design above. Do not fall back to the full slug on overflow.
7. No changes outside `src/slugify.js` and `test/slugify.test.js`.
