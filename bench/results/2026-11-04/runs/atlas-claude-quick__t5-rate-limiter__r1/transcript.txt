## Plan: token-bucket limiter (`src/limiter.js`, `test/limiter.test.js`)

**Goals.** Provide `createLimiter({ capacity, refillPerSecond, now })` as a token bucket with `tryRemove`, `available`, `msUntil`, and `reset`. Validate inputs strictly and handle a backwards clock without losing or adding tokens.

**Out of scope.** Other modules, README, package.json, and any shared state. Nothing else in the repo changes. The only files touched are `src/limiter.js` (new) and `test/limiter.test.js` (new). The `src/` and `test/` directories do not exist yet, so the Developer creates them.

**Modules and dependencies.** None. The module uses only the language built-ins. Tests use `node:test` and `node:assert/strict`. There is no architectural impact outside the new files, and no shared state.

**Design decisions for the Developer.**

1. **Factory and state.** `createLimiter(options = {})` keeps private closure state: `tokens` (a float, starts at `capacity`) and `last` (the reference time in ms). Do not use classes. The project has no classes, and a closure matches the `{ createLimiter }` contract.
2. **Option validation.** Throw `RangeError` for:
   - `capacity`: not `Number.isInteger` or `<= 0`. This covers missing, string, `NaN`, `Infinity`, `1.5`, `0`, and negatives.
   - `refillPerSecond`: `typeof !== 'number'`, `!Number.isFinite`, or `<= 0`.
   - Default `now` to `Date.now` when `undefined`. I'm not adding a check on `now` beyond that. Its return value is not validated, which is a known gap (see risks).
   - Read `last` from `now()` once in the factory so the first refill has a reference.
3. **Refill.** Compute `t = now()`. If `t < last`, set `last = t` and add nothing. Otherwise `tokens = min(capacity, tokens + (t - last) * refillPerSecond / 1000)` and `last = t`. The backwards branch stores the earlier time as the new reference, as the spec requires.
4. **`tryRemove(n = 1)`.** Validate `n` first: it must be an integer `>= 1`, and `n > capacity` throws `RangeError`. Then refill. If `tokens >= n`, subtract `n` and return `true`. Otherwise return `false` and change nothing.
5. **`available()`.** Refill, then return `Math.floor(tokens)`.
6. **`msUntil(n = 1)`.** Validate `n` the same way as `tryRemove`. Refill. If `tokens >= n`, return `0`. Otherwise return `Math.ceil((n - tokens) * 1000 / refillPerSecond)`. Compute the division in that order so exact cases stay exact.
7. **`reset()`.** Set `tokens = capacity` and `last = now()`, so the reference matches the reset moment.
8. **Export.** End the file with `module.exports = { createLimiter };` and nothing else.

**Contracts to honour.** Error types are `RangeError` for the cases above. Return types are a boolean for `tryRemove`, an integer for `available` and `msUntil`, and `undefined` for `reset`. The public API has exactly four methods on the returned object.

**Test plan** (`test/limiter.test.js`, using `node:test` and `node:assert/strict`, with an injected clock object `{ t }` and `now: () => clock.t`).

- Starts full: `available()` equals capacity.
- `tryRemove` removes tokens and returns `true`. When not enough tokens are available it returns `false` and the count is unchanged.
- Refill over time: after advancing by 1000 ms at 2/s, two tokens are back.
- Fractional rate: at `refillPerSecond: 0.5`, 1000 ms adds 0.5, so `available()` stays 0 and 2000 ms gives 1.
- Cap: a long idle period never exceeds `capacity`.
- `msUntil`: returns 0 when enough tokens exist. Otherwise it returns the ceiling, for example 1500 ms at 0.5/s for a missing token deficit of 1 token equals 2000 ms, and a half-token case rounds up.
- `reset()` restores full capacity.
- Backwards clock: move the clock back, check that no tokens are added or lost, then move forward and check that refill resumes from the earlier reference.
- Invalid options: a table of bad `capacity` and `refillPerSecond` values (undefined, `'5'`, `0`, `-1`, `NaN`, `Infinity`, `1.5` for capacity), each expected to throw `RangeError`. Also `createLimiter()` with no argument throws `RangeError`.
- Invalid `n`: `0`, `-1`, `1.5`, `'1'`, and `capacity + 1` throw `RangeError` from both `tryRemove` and `msUntil`.
- Module shape: `require('../src/limiter.js')` has exactly one export, `createLimiter`.

**Verification.** Run `npm test`, which runs `node --test`. Every test must pass. The Developer must confirm that no file other than the two named ones is changed (`git status`).

**Risks.**

- **Float precision.** Fractional refill rates can make `Math.floor` or `Math.ceil` land one step off, for example `0.9999999` where `1` is expected. Tests should use rates and durations that are exact in binary, such as `0.5`, `0.25`, `2`, and `4`. The Developer should not add an epsilon unless a test shows the need.
- **Unvalidated `now` return value.** A `now()` that returns `NaN` or a non-number poisons `tokens`. The spec does not require a guard, so this is documented rather than handled.
- **Backwards-clock semantics.** After a backwards move, the reference is the earlier time, so the next forward refill counts the interval from that earlier time. This is what the spec asks for, but it means tokens may accrue faster than real time afterward. Tests should document it.

**Decisions I made where the spec was silent.** `createLimiter()` with no argument throws `RangeError`, not `TypeError`. `reset()` re-reads `now()`. `now` is not validated. Tell me if you want any of these changed.
