**Root causes (confirmed by reading the code and running `npm test` before the fix):**

1. **Quantity ignored.** `src/cart.js:16` summed `item.price` and never used `item.qty`. That gives 19.9 instead of 59.7.
2. **Percent coupon inverted.** `src/cart.js:21` computed `sum * value / 100`, which is the discount amount, not the amount to pay. OFF20 on 100 gave 20 instead of 80.
3. **No floor at zero.** A fixed coupon larger than the cart gave a negative total (TENOFF on 5 gave -5).
4. **No cent rounding.** Float addition returned values like `0.30000000000000004`.
5. **Unknown coupons not safely ignored.** `COUPONS[couponCode]` also matched inherited object keys such as `'toString'`, which produced `NaN`.

**Fix:** In `src/cart.js`, the sum now multiplies price by qty. Percent coupons apply `sum * (100 - value) / 100`. Coupon lookup uses `Object.hasOwn`. The total is clamped with `Math.max(0, sum)` and rounded with `Math.round(sum * 100) / 100`. The export `module.exports = { total }` is unchanged.

**Regression tests:** I added five tests to `test/cart.test.js`: quantity multiplication, the percent coupon, the fixed-coupon floor, cent rounding, and unknown coupons (including `'toString'`).

**Files changed:**
- `src/cart.js`
- `test/cart.test.js`

**Residual risk:**
- `Math.round(x * 100)` can round half-cent values unexpectedly due to float representation (for example, `1.005` may round down to `1.00`). A decimal-safe rounding helper would fix this if it matters for your prices.
- Negative prices or quantities are not validated. They are outside the reported bugs, so I left them alone.
- `Object.hasOwn` needs Node 16.9 or later. The project uses `node --test`, so this should already be satisfied.

## Verification report: cart total fix

**Verdict: pass.** The five defects in `src/cart.js` are fixed, and the regression tests cover them. I found no regression in the code paths I traced. The findings below are low severity and for you to decide on.

**Note on the diff:** The fix is already committed in HEAD (`559ab0e`, "Atlas: step exec-2"), so `git diff` against HEAD is empty. I compared against the original fixture commit `75330f3` instead.

### Root cause (read: `git show 75330f3`)
The original `total()` had five independent defects:
1. **Quantity ignored:** the loop added `item.price` and never multiplied by `item.qty`. This gives 19.9 instead of 59.7.
2. **Percent coupon inverted:** `sum * value / 100` returned the discount amount, not the remainder. This gives 20 instead of 80 for OFF20 on 100.
3. **No floor:** a fixed coupon could push the total below zero. This gives -5 for TENOFF on 5.
4. **No rounding:** float arithmetic leaked into the result. This gives 0.30000000000000004.
5. **Prototype lookup:** `COUPONS[couponCode]` matched inherited keys such as `toString`. The function was truthy, so the arithmetic produced NaN.

### Fix applied (read: `src/cart.js:13-28`)
- Line 16: `sum += item.price * item.qty`.
- Line 18: `Object.hasOwn(COUPONS, couponCode)` guards the lookup, so unknown and inherited keys are ignored.
- Line 21: percent coupons compute `sum * (100 - value) / 100`.
- Line 26: `Math.max(0, sum)` floors the total.
- Line 27: `Math.round(sum * 100) / 100` rounds once, at the end.
- `module.exports = { total }` is unchanged.

### Validation evidence
- **Executed:** `npm test` (`node --test`) passed 7 of 7, with 0 failures.
- **Read, regression coverage:** the five new tests in `test/cart.test.js:13-32` map one-to-one to the five defects: quantity, percent coupon, fixed-coupon floor, cents rounding, and unknown coupon (`NOPE` and `toString`).
- **Read, would the regression tests fail without the fix:** I traced the original code by hand against each new test. Quantity gives 19.9 ≠ 59.7. OFF20 gives 20 ≠ 80. TENOFF gives -5 ≠ 0. The rounding case gives 0.30000000000000004 ≠ 0.3. `toString` gives NaN ≠ 10. That is five failures, which matches the prior step's report. I could not execute this against the old code, because I cannot write files or run `node` directly in this read-only mode.
- **Read, dependents:** `grep` for "cart" finds only `test/cart.test.js`. Nothing else in the repo imports `src/cart.js`. `package.json` has no `engines` field. `Object.hasOwn` needs Node 16.9 or later, which the `node --test` runner already requires (Node 18 or later).

### Scope judgement
The fix addresses the causes, not just the symptoms. Each defect is handled at its source. The change is minimal and keeps the existing structure and the API.

### Not verified
- Behaviour on the old code was traced by hand, not executed.
- I did not run the tests on a Node version other than the sandbox's default.

### Low-severity findings (for you to decide; outcome stays pass)
- **Half-cent rounding:** `Math.round(sum * 100) / 100` is binary-float sensitive. For example, `1.005 * 100` is `100.49999999999999`, so 1.005 rounds to 1.00, not 1.01. Decimal-exact rounding would need integer-cent arithmetic. The spec says only "rounded to cents", so this may be acceptable.
- **Negative or zero quantity:** a line with `qty: -1` produces a negative line total, and the zero floor can hide it. Input validation may be wanted.
- **Coupon case sensitivity:** `'tenoff'` is ignored. The spec does not say whether codes are case-insensitive.
- **Test gaps:** no test covers a multi-item cart with a coupon, the `HALF` coupon, a `__proto__` key, or an explicit `undefined` coupon. None of these is a known defect.
- **NaN inputs:** a missing `price` still returns NaN. This was already the case before the fix and is outside the reported bugs.
