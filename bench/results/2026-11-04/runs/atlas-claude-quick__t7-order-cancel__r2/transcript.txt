## Plan: order cancellation

**Goal:** Add `orders.cancel(orderId, reason)` so that a placed order returns its stock, becomes `cancelled` with its reason kept, emits `order.cancelled`, and drops out of `reports.revenue()` and `reports.unitsSold(sku)`.

**Current state (read, not changed):**
- `src/orders.js`: `createOrders({ inventory, bus, prices })` keeps orders in a `Map` and records them as `{ id, items, total, status: 'placed' }`. `get` and `all` return copies. `place` checks stock, then calls `inventory.take`, then emits `order.placed`.
- `src/inventory.js`: has only `quantity` and `take`. There is no way to add stock back.
- `src/reports.js`: both functions read `orders.all()` and do not look at `status`.
- `src/events.js`: a synchronous bus. A handler that throws propagates to the emitter.
- `test/shop.test.js`: 3 tests, all passing. Baseline `npm test` gives 3 pass, 0 fail.

**In scope:** `orders.cancel`, an `inventory.restock` method, the report filter, and tests.
**Out of scope:** partial cancellation, refunds or payments, a `cancel` path for orders that were not placed, changes to `shop.js` wiring, and changes to the event bus.

**Decisions for the Developer:**
1. **Inventory gets a `restock(sku, qty)` method.** It adds `qty` to the stock for `sku`, treating a missing SKU as 0. It sits next to `take` in `src/inventory.js` and follows the same `stock` Map style. Nothing in the existing code calls it, so existing behaviour does not change.
2. **Orders call inventory directly, not through the bus.** `place` already calls `inventory.take` directly, so `cancel` calls `inventory.restock` the same way. The bus is used only to announce the event. This adds no new dependency, because `inventory` is already injected into `createOrders`.
3. **Check order inside `cancel`:**
   - (a) Validate `reason`: it must be a string, and I recommend rejecting empty or whitespace-only strings (`reason.trim() === ''`). Throw `TypeError`.
   - (b) Look up the order. If missing, throw `Error` with a message containing "not found", e.g. `order ${orderId} not found`.
   - (c) If `status === 'cancelled'`, throw `Error` with a message containing "already cancelled".
   - Validation runs before lookup, so a bad reason gives a `TypeError` even when the order does not exist. Nothing is touched on any throw.
4. **Mutation order:** restock every item, then set `status = 'cancelled'` and `reason` on the stored order, then emit, then return a copy. Setting the status before emitting means a handler that calls `cancel` again gets "already cancelled". Restocking cannot throw, so no partial state is possible.
5. **Stored shape:** add `reason` to the stored order only when it is cancelled, or set it to `null` on placement. Either is acceptable, but `place` should keep its current return shape for existing callers.
6. **Event payload:** `bus.emit('order.cancelled', { orderId, reason })`, with exactly those two keys, as the spec says.
7. **Reports:** both `revenue` and `unitsSold` skip orders with `status === 'cancelled'`. Keep the filter in `reports.js` and do not change `orders.all()`, so the ledger still shows cancelled orders.
8. **Tests** go in `test/shop.test.js`, following the existing style of `setup()` and `node:test`. They cover:
   - stock is returned and the status and reason are kept;
   - exactly one `order.cancelled` event with `{ orderId, reason }`;
   - the return value is the cancelled order;
   - unknown id throws "not found" and changes nothing;
   - double cancel throws "already cancelled" and changes nothing (no stock move, no second event);
   - empty, whitespace and non-string reason throw `TypeError` and change nothing;
   - revenue and `unitsSold` exclude cancelled orders while other orders still count.

**Files to change:**
- `src/inventory.js`: add `restock`.
- `src/orders.js`: add `cancel`, which stores the reason on the order.
- `src/reports.js`: filter out cancelled orders in `revenue` and `unitsSold`.
- `test/shop.test.js`: add the new tests.

**Contracts:**
- New event `order.cancelled` with payload `{ orderId, reason }`.
- New order status `'cancelled'`.
- New method `inventory.restock(sku, qty)`.
- Existing signatures for `place`, `get`, `all`, `quantity`, `take` and both reports functions are unchanged.

**Risks:**
- Cancelled orders stay in `orders.all()`, so any future consumer that sums orders without checking status will miscount. The filter lives only in `reports.js`. This is acceptable for now, but any new report needs the same filter.
- `orderId` is matched strictly, so `cancel('1')` will not find order `1`. This matches the existing `get(id)` and is not a regression.
- Event handlers run synchronously after the state change. A throwing `order.cancelled` handler leaves the cancellation applied, the same as `order.placed` today.

- `npm test` must show the 3 existing tests and all the new ones passing.
- Read the diff to confirm `place`, `get`, `all` and the existing report numbers are unchanged.
