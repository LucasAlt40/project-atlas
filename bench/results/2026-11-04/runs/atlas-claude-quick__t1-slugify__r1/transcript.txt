### Design decisions for the Developer

1. **Pipeline, in this order:**
   - Check that `text` is a string. Otherwise `throw new TypeError(...)`.
   - Normalise: `text.normalize('NFD').replace(/[\u0300-\u036f]/g, '').toLowerCase()`.
   - Replace runs of non-`[a-z0-9]`: `.replace(/[^a-z0-9]+/g, '-')`.
   - Strip leading and trailing dashes: `.replace(/^-+|-+$/g, '')`.
   - Apply `maxLength` (below).
2. **Signature:** `function slugify(text, options = {})`. `options` is optional. `maxLength` is optional, and `undefined` means no limit.
3. **Invalid `maxLength`** (anything other than a positive integer, including `NaN`, `0`, `-1`, `2.5`, strings): throw `TypeError`. This matches rule 6 and avoids a second error class. Note this is my choice; the spec does not define it.
4. **Truncation, when `s.length > maxLength`:**
   - `const i = s.slice(0, maxLength + 1).lastIndexOf('-')`.
   - If `i > 0`, return `s.slice(0, i)`. This cuts at the last dash that fits and never leaves a trailing dash, because slugs contain no doubled dashes.
   - If `i === -1`, hard-cut with `s.slice(0, maxLength)`. That prefix has no dash, so it cannot end with one.
   - When `s.length <= maxLength`, return `s` unchanged.
   - Check: `'hello-big-world'` with max 9 gives `'hello-big'`. With max 8 it gives `'hello'`. `'supercalifragilistic'` with max 5 gives `'super'`.
5. **Non-decomposing letters** become `-` (for example `'straße'` gives `'stra-e'`). This follows rule 3 literally. Document it in a code comment or leave it, and flag it in the summary.
6. **Code style:** no comments beyond what the logic needs, no helper modules, no dependencies, no `'use strict'` unless the rest of the project adopts it (it does not yet).

### Test cases

- The five spec examples: `' Olá, Mundo! '`, `'Ação & Reação'`, and the three `maxLength` cases.
- Diacritics: `'é ç ã ü'` gives `'e-c-a-u'`. Lowercasing: `'HeLLo'` gives `'hello'`.
- Runs of separators collapse: `'a   --  b'` gives `'a-b'`. No leading or trailing dash: `'  !!x!!  '` gives `'x'`.
- Empty or punctuation-only input: `''` and `'!!!'` both give `''`.
- `maxLength` exact fit (`'abc'`, max 3), one under the length, and max larger than the slug (no change).
- Result never ends with `-` for a range of `maxLength` values on one fixed input.
- Non-string input throws `TypeError`: `123`, `null`, `undefined`, `{}`.
- Invalid `maxLength` throws `TypeError`: `0`, `-1`, `2.5`, `'5'`, `NaN`.

### Risks

- The `maxLength` cut is the only subtle logic. The boundary tests above are what protect it.
- `null` as `options` throws a `TypeError` from the property read, not an explicit check. That is acceptable for this scope.
- Default `node --test` discovery depends on Node version. The Developer should confirm that the test file runs, not just that the command exits 0.
