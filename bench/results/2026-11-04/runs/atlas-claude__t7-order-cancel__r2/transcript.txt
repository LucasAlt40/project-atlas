## Plan: order cancellation

**Goal.** Add `orders.cancel(orderId, reason)`. It restocks the order's items, marks the order `cancelled` and keeps the reason, emits one `order.cancelled` event, and returns the cancelled order. Reports stop counting cancelled orders.

**In scope.** `src/orders.js`, `src/inventory.js`, `src/reports.js`, and `test/shop.test.js`.

**Out of scope.** `src/events.js` (no change is needed), `src/shop.js` (no wiring change), README, and the existing shared-reference return in `place()`. That last one is a pre-existing issue, noted below.

**Modules and dependencies.**
- `shop.js` composes everything. `orders` depends on `inventory` and `bus`, which are injected. `reports` depends on `orders.all()`.
- The change keeps these directions. Nothing new is imported.
- The new contract is the `order.cancelled` event with payload `{ orderId, reason }`. Nothing subscribes to it yet.

**Decisions the Developer must follow.**
1. **Inventory gets a `restock(sku, qty)` method.** It adds `qty` to the current stock. It is the mirror of `take()`, which is the only mutator today. Do not validate beyond what `take` does.
2. **Validation order in `cancel`:**
   1. Check `reason` first. A non-string, or a string that is empty after `trim()`, throws `TypeError`. Nothing changes.
   2. Look up the order. A missing order throws `Error` with a message containing "not found".
   3. If the order is already `cancelled`, throw `Error` with a message containing "already cancelled".
   
   Because argument checks come first, a bad reason always gives `TypeError`, whatever the order's state.
3. **Lookup is strict.** Ids are numbers, as `place()` creates them. Do not coerce string ids.
4. **Restock from the stored items, not from the caller's input.** The caller passes only `orderId` and `reason`.
5. **Mutation order mirrors `place()`:** validate, then restock each item, then set `status = 'cancelled'` and `reason` on the stored order, then emit, then return a copy. The copy is built the same way `get()` builds it, with items copied. Emitting after the state change matches `place()`.
6. **Keep `reason` as given.** Don't trim the stored value. Trimming is only used for the emptiness check.
7. **Reports filter in `reports.js`.** `revenue()` and `unitsSold()` skip orders whose `status === 'cancelled'`. `orders.all()` keeps returning every order, because it is a data accessor and the sales rule belongs to reports.

**Files and contracts to change.**
- `src/inventory.js`: add `restock(sku, qty)`.
- `src/orders.js`: add `cancel(orderId, reason)`. Its contract is: it returns the cancelled order copy, and it throws `TypeError` or `Error` as described above. Emits `order.cancelled`.
- `src/reports.js`: add the `cancelled` filter in `revenue()` and `unitsSold()`.
- `test/shop.test.js`: add tests. Existing tests stay unchanged.

**Tests to add** (in `test/shop.test.js`, following the existing `node:test` style):
- A cancel restores stock, sets `status` to `'cancelled'`, keeps `reason`, returns the cancelled order, and emits exactly one `order.cancelled` event with `{ orderId, reason }`.
- An unknown id throws an error matching `/not found/`, and no event is emitted.
- A second cancel throws an error matching `/already cancelled/`. Stock is not restocked again, and no second event is emitted.
- A reason of `''`, `'   '`, `undefined` or `42` throws `TypeError`. Stock, status and events stay unchanged.
- After a cancel, `reports.revenue()` and `reports.unitsSold(sku)` exclude that order.

**Risks.**
- **Pre-existing:** `place()` returns `{ ...order }`, which shares the internal `items` array with the stored order. A caller can mutate the store through the returned object. This is outside the task, so leave it alone, and `cancel` should not copy that pattern.
- **Handler exceptions:** the bus is synchronous. If a future `order.cancelled` subscriber throws, the state has already changed. This matches `place()`, so it is accepted for now.

**Verification.** Run `npm test`. All 3 existing tests and the new cancellation tests should pass. Then confirm by reading that `reports.js` filters in both methods.
