## Plan: todo priorities

**Size: moderate**

### Goals
- `store.add(title, options)` accepts `options.priority` of `'low' | 'normal' | 'high'`, defaulting to `'normal'`. Any other value throws `RangeError`.
- Each todo carries a `priority` field.
- `store.list(filter)`: with `filter.priority`, return only that priority. Without a filter, sort high, normal, low, keeping insertion order within each priority.
- `formatList` prints high-priority todos as `[ ] !Title`. Other todos render exactly as before.
- All existing tests keep passing, and new tests cover the new behaviour.

### Out of scope
- No change to `complete`, the title validation, or the id scheme.
- No new modules, no persistence, no CLI, no new dependencies.
- No exported priority constants. The rank table stays private to `store.js`.

### Current state and impact
- `src/store.js` (`add` at line 8, `list` at line 26): all logic is local to `createStore`. `list()` returns copies, so sorting those copies is safe.
- `src/format.js` (line 3): one `map` over todos. It only needs to know whether `priority === 'high'`.
- Architectural impact is small and contained. `format.js` depends on the literal `'high'` in the store's data, which is a soft coupling. Accepted, because the alternative (importing a constant from the store) adds a dependency for one comparison.
- Existing todos created by old code have no `priority`. Under the plan, `format` treats a missing priority as non-high, so existing callers see no change.

### Decisions for the Developer
1. **Validation order in `add`:** check the title first (existing `TypeError`), then the priority (`RangeError`), before pushing anything, so a rejected call leaves the store unchanged.
2. **Missing or undefined options:** `add(title)` and `add(title, {})` both default to `'normal'`. Check with `options.priority === undefined`, not truthiness, so `null` or `''` are rejected by the `RangeError` check.
3. **Rank table:** `const RANK = { high: 0, normal: 1, low: 2 }` in `store.js`. Membership check is `Object.hasOwn(RANK, p)` or equivalent. This avoids accepting inherited keys such as `'toString'`.
4. **Sorting:** sort a copy of the array (`todos.map(copy).sort(...)`). Never sort `todos` in place, because that reorders the internal insertion history. `Array.prototype.sort` is stable in Node 12+, so equal ranks keep insertion order.
5. **Filter:** when `filter.priority` is present, filter by equality and keep insertion order. An unknown `filter.priority` throws `RangeError`, consistent with `add`. This is my choice; the task did not specify it. Alternative: return `[]`. I recommend throwing because it surfaces typos.
6. **`format.js`:** `const bang = t.priority === 'high' ? '!' : '';` and output `` `[${mark}] ${bang}${t.title}` ``. No other formatting changes.
