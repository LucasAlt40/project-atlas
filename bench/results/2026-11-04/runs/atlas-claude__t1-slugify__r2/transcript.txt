## Plan: `slugify` module and tests

**Goal:** add `src/slugify.js` exporting `{ slugify }`, plus `test/slugify.test.js`, and nothing else.

**In scope**
- `src/slugify.js` (new), `test/slugify.test.js` (new).

**Out of scope**
- Any other file, including `package.json` and `README.md`. No dependencies. Non-ASCII letters that do not decompose (such as `ø`, `ß`) are treated as separators per rule 3. That is a known limitation, not something to fix here.

**Architecture impact**
- None. This is a leaf module with no imports and no other modules depending on it. The only dependency is the built-in runner, `node:test` and `node:assert`.

**Algorithm (decisions for the Developer)**
1. If `typeof text !== 'string'`, throw `TypeError`.
2. Normalize with `text.normalize('NFD').replace(/[\u0300-\u036f]/g, '')` to strip combining marks, then `.toLowerCase()`. This covers `é`, `ç`, `ã`, `ü`.
3. Replace `/[^a-z0-9]+/g` with `-`, then strip leading and trailing `-`.
4. If `maxLength` is `undefined`, return the result. Otherwise:
   - If `result.length <= maxLength`, return it.
   - Otherwise take `window = result.slice(0, maxLength + 1)`. Use `+ 1` so a dash sitting exactly at index `maxLength` counts as a valid cut. Without it, `'hello-big-world'` with `maxLength: 9` would wrongly give `'hello'`.
   - Let `idx = window.lastIndexOf('-')`. If `idx > 0`, return `result.slice(0, idx)`.
   - Otherwise, the first word does not fit, so return `result.slice(0, maxLength)`. This cannot end in `-` because the window has no dash.
5. Options handling: `const { maxLength } = options ?? {}`, so `null` and `undefined` options both work.
6. `maxLength` validation (my choice; the spec does not state it): if `maxLength !== undefined` and it is not an integer ≥ 1, throw `RangeError`.

**Files and contracts**
- `src/slugify.js`: `module.exports = { slugify }`, with `slugify(text, options)` returning a string.
- `test/slugify.test.js`: `require('../src/slugify')`, using `node:test` (`test`) and `node:assert/strict`.
  - Spec examples: `' Olá, Mundo! '` → `'ola-mundo'`; `'Ação & Reação'` → `'acao-reacao'`; `('hello big world', {maxLength: 9})` → `'hello-big'`; `{maxLength: 8}` → `'hello'`; `('supercalifragilistic', {maxLength: 5})` → `'super'`.
  - Extra cases: `ü` and `ç` accents; collapsing of runs such as `'a---b  c'`; empty result for `'!!!'`; exact-fit length; `maxLength` never producing a trailing `-`; `TypeError` for `123`, `null` and `undefined`; `RangeError` for `0` and `1.5`.

**Verification**
- Run `npm test` and confirm all cases pass, with the output shown.
- Confirm that `git status` lists only `src/slugify.js` and `test/slugify.test.js` as new.

**Risks**
- The `+ 1` window is the easiest place to get the cut wrong. The `maxLength: 9` and `maxLength: 8` cases in the tests guard against this.
- The `RangeError` rule goes beyond the spec. The Developer should keep it, but it can be dropped if the person prefers the minimal contract.
