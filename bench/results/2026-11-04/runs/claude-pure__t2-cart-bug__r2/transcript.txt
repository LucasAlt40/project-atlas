The fix is in `src/cart.js` and the regression tests are in `test/cart.test.js`, but I could not run the test suite. `node --test` was blocked by the permission prompt, and this session can't approve it. I traced every assertion by hand instead, so please run `npm test` to confirm.

**Root causes**

1. **Quantity ignored.** The loop added `item.price` and never multiplied by `item.qty`, so 3 × 19.90 gave 19.9.
2. **OFF20 applied to the wrong amount.** The percent branch computed `sum * value / 100`, which is the discount itself (20), not the amount to pay (80). The discount should be `sum * (100 - value) / 100`.
3. **Fixed coupons could go negative.** `TENOFF` on a 5.00 cart produced -5 because nothing clamped the result.
4. **Float noise.** Totals were summed as raw floats, which produced values like 0.30000000000000004. There was no rounding.
5. **Inherited keys counted as coupons.** `COUPONS[couponCode]` also matches properties inherited from `Object.prototype`, so a code like `toString` would be treated as a coupon. Unknown codes are now checked with `Object.hasOwn`.

**The change**

- Totals are computed in integer cents: each line is `Math.round(price * 100) * qty`.
- Coupons apply to cents. Percent coupons use `(100 - value)`, and fixed coupons subtract `value * 100`.
- The result is clamped at 0, rounded to whole cents, and divided by 100.
- The API is unchanged: `module.exports = { total }`, and the two existing tests are untouched.

**Regression tests added**

- Quantity multiplies price: 3 × 19.9 → 59.7.
- `TENOFF` never goes negative: 5 → 0, and 30 → 20.
- `OFF20` and `HALF` take the discount off: 100 → 80 and 50.
- Unknown and inherited codes (`NOPE`, `toString`, `__proto__`) are ignored.
- Float noise is gone: 0.1 + 0.2 → 0.3, and 1.1 × 3 with `OFF20` → 2.64.
