**Root causes**

1. **Commas in quotes:** the parser called `split(',')` on each line, so quoting was never considered. `"Lisbon, Portugal"` was split at the comma.
2. **Doubled quotes:** nothing turned `""` into `"`. The only unquoting was stripping the outer quotes.
3. **Trailing newline:** `split('\n')` produces an empty last piece, which became an extra `[""]` row.
4. **CRLF:** only `\n` was treated as a line break, so `\r` stayed at the end of each row's last field.
5. **Newlines in quotes:** lines were split before quotes were read, so a quoted line break always cut the record in two.

**The fix**

I replaced the line-splitting with a single left-to-right pass over the characters. It tracks whether it is inside quotes, turns `""` into `"` while quoted, and ends a record only on an unquoted `\n` or `\r\n`. A record that is still pending at the end is emitted only if it has content, so a trailing newline adds no row. An unclosed quote throws `SyntaxError`. Empty input returns `[]`. The module still exports `{ parseCsv }`.

I kept two lenient behaviours that go beyond the spec. A quote that appears in the middle of an unquoted field (such as `5" screen`) is kept as a literal character. A bare `\r` that is not followed by `\n` is also kept as a literal.

**Tests added to `test/csv.test.js`**

- trailing newline adds no row
- CRLF line endings
- line break inside a quoted field
- empty fields are preserved, including `""` as an empty field

- unterminated quote throws `SyntaxError`

The two original tests are unchanged.
