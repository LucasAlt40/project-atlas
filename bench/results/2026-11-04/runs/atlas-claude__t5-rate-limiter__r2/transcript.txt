### Architectural impact
- `limiter.js` is a leaf module. It has no imports and only depends on the injected `now` function, so it is fully deterministic under test.
- The factory-closure style (`createLimiter` returns an object over private state) fits the spec's API. A class is not needed.

### Design decisions the Developer must follow
1. **Validation in `createLimiter`.** `capacity` must satisfy `Number.isInteger(c) && c > 0`. `refillPerSecond` must satisfy `typeof r === 'number' && Number.isFinite(r) && r > 0`. Any failure throws `RangeError`, including missing values. `now` defaults to `Date.now` when `undefined`.
2. **State.** Keep `tokens` (a float, starts at `capacity`) and `last` (the reference time, set to `now()` at creation).
3. **Refill.** Read `t = now()`. If `t < last`, set `last = t` and add nothing. Otherwise add `(t - last) * refillPerSecond / 1000`, cap at `capacity`, and set `last = t`. This covers the backwards-clock rule: no tokens are added and none are lost.
4. **`n` validation** (for `tryRemove` and `msUntil`): `Number.isInteger(n) && n > 0`, otherwise `RangeError`. Also throw `RangeError` when `n > capacity`. Validate `n` before refilling.
5. **`tryRemove(n = 1)`.** Refill, then if `tokens >= n` subtract `n` and return `true`; otherwise return `false` and change nothing.
6. **`available()`.** Refill, then return `Math.floor(tokens)`.
7. **`msUntil(n = 1)`.** Refill. If `tokens >= n`, return `0`. Otherwise return `Math.ceil((n - tokens) * 1000 / refillPerSecond)`.
8. **Floating-point guard.** Fractional refill can leave `tokens` a hair under an integer (for example `0.9999999999`), which would make `available()` or `msUntil` off by one. Compare with a small epsilon (`1e-9`): `tokens + 1e-9 >= n`, and in `msUntil` subtract `1e-9` before `Math.ceil`. This is a judgment call on my part; the Developer should note it in a comment.
9. **`reset()`.** Set `tokens = capacity` and `last = now()`.
10. **Style.** Match the project's plain CommonJS, no dependencies, and no build step. Keep comments short and only where the clock-backwards and epsilon logic need them.

### Files and contracts
- **Create** `src/limiter.js`: exports `{ createLimiter }`, returns `{ tryRemove, available, msUntil, reset }`.
- **Create** `test/limiter.test.js`: uses `node:test` and `node:assert/strict`.

### Test plan (fake clock: `let t = 0; now: () => t`)
- Starts full: `available() === capacity`.
- `tryRemove` succeeds while tokens last, then returns `false` with no change.
- Fractional refill: rate `0.5`, after 2000 ms one token is back.
- Refill never exceeds `capacity`.
- `available()` floors fractional tokens.
- `msUntil` rounds up: rate `3`, empty bucket, `msUntil(1) === 334`. Returns `0` when already available.
- `reset()` refills to full.
- Clock goes backwards: no tokens added, none lost, and the earlier time becomes the new reference.
- Invalid options table (missing, `0`, negative, `NaN`, `Infinity`, string, fractional capacity) each throws `RangeError`.
- Invalid `n` (`0`, `-1`, `1.5`, `'1'`, `NaN`) and `n > capacity` each throw `RangeError` from `tryRemove` and `msUntil`.
- Exports are exactly `{ createLimiter }`.

### Risks
- **Floating-point drift** with fractional rates. Mitigated by decision 8; the tests should include a case that exposes it, such as rate `0.1` stepped in 100 ms increments.
- **Non-monotonic `Date.now`.** Handled by decision 3.
- **Ambiguity:** the spec leaves `now` validation open. I chose to default only on `undefined` and not to validate its type. The Developer should not add extra validation beyond that.

## Findings (all low, none failing)

1. **`msUntil` can return 0 while `tryRemove` still fails** (`src/limiter.js:57-65`, read). Reachable only with fractional-millisecond clocks or contrived rates. Suggested fix: apply the epsilon to the comparison only, and return at least 1 when the deficit is positive.
2. **`msUntil` can return `Infinity`** for denormal-small `refillPerSecond` (`src/limiter.js:64`, read). Consider rejecting such rates at creation.
3. **`createLimiter(null)` throws `TypeError`**, not `RangeError` (`src/limiter.js:20`, read). The task only names invalid capacity and refill, so this is hardening.
4. **A `now()` that returns `NaN` freezes refill until `reset()`** (`src/limiter.js:33-39`, read). `NaN > 0` is false, so `last` becomes `NaN` and every later elapsed value is `NaN`. This is outside the contract.
