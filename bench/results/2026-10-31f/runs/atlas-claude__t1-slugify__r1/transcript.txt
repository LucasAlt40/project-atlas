## Design (decisions the Developer must follow)
1. **Normalization order:** `text.normalize('NFKD').replace(/[\u0300-\u036f]/g, '').toLowerCase()`. NFKD splits `ç` into `c` + U+0327 and `ã`/`é`/`ü` into base letter + combining mark, and the strip removes the marks. Lowercasing comes last.
2. **Collapse separators:** `.replace(/[^a-z0-9]+/g, '-')`, then strip leading and trailing `-` (`/^-+|-+$/g`). Characters with no ASCII decomposition, such as `ø` or `ß`, become separators under rule 3. This is intended, so don't add transliteration tables.
3. **Type check first:** `if (typeof text !== 'string') throw new TypeError(...)`. Do this before any other work.
4. **`maxLength` (only when provided):**
   - If the slug is already `<= maxLength`, return it.
   - Otherwise take `cut = slug.slice(0, maxLength)`.
   - **If `slug.charAt(maxLength) === '-'`, return `cut`.** The cut lands exactly on a word boundary. This check must come first. Without it, `'hello-big-world'` with `maxLength: 9` would wrongly return `'hello'`.
   - Else, if `cut` contains a `-`, return `cut.slice(0, cut.lastIndexOf('-'))`.
   - Else hard-cut and return `cut`.
5. **Option validation:** the spec doesn't say what happens with a bad `maxLength`. I'm choosing `RangeError` when it is not a positive integer (`0`, `-1`, `1.5`, `'9'`). This is an extra choice beyond the spec, and the Developer must flag it in the final message.
6. **Signature:** `function slugify(text, options = {})`. Read `options.maxLength` only, so passing `undefined` or `{}` means no limit.
7. **Empty results:** input with no `a-z0-9` (for example `'!!!'`) returns `''`. This is not an error.
