# Plan: priorities for the todo store

## Goals
- Each todo carries `priority` ('low' | 'normal' | 'high'), defaulting to 'normal'. Invalid values throw `RangeError`.
- `store.list()` returns todos sorted high → normal → low, stable within a priority (insertion order kept).
- `store.list({ priority })` returns only todos of that priority.
- `formatList` renders high-priority todos as `[ ] !Title`; other priorities render as today.
- All existing tests keep passing.

## Out of scope
- No `complete()` changes, no persistence, no README/API docs beyond what is needed, no new modules or exports.
- No change to `list()` returning copies (`{ ...t }`); that stays.

## Modules and dependencies
- `src/store.js`: the only owner of priority validation and ordering. Self-contained, no dependencies.
- `src/format.js`: depends only on the todo shape. It will read `t.priority`. It should **not** import from `store.js`; a string comparison against `'high'` is enough and avoids a new dependency edge. The vocabulary is duplicated in two files, which is an accepted trade-off at this size.
- `test/store.test.js`: the single existing test file, which already covers both modules. Add tests there, following the same `node:test` style.

## Decisions for the Developer
1. **Default applies only when `options.priority` is `undefined`.** Use `const priority = options.priority === undefined ? 'normal' : options.priority;`, not `??`. Then `null` is an invalid value and throws, as the spec requires. The `options` parameter defaults to `{}`.
2. **Validate before mutating.** In `add`, check the title first (existing `TypeError`), then the priority (`RangeError`), and only then push. A rejected add must leave the list unchanged.
3. **Rank constant in `store.js`.** Define a module-level `const PRIORITY_RANK = { high: 0, normal: 1, low: 2 };`. Use it for validation (`in` check) and sorting.
4. **Always sort in `list()`.** Sort a copy: `todos.filter(...)` (when a filter is given), then `.sort((a, b) => PRIORITY_RANK[a.priority] - PRIORITY_RANK[b.priority])`, then map to copies. `Array.prototype.sort` is stable in Node 11+, so insertion order is kept within a priority. Do not sort `todos` in place.
5. **Invalid filter priority throws `RangeError`.** The spec does not cover this. I recommend throwing, so typos such as `'High'` fail loudly instead of silently returning `[]`. This is a choice I made; the Developer should follow it unless told otherwise.
6. **Formatter.** `formatList` adds `!` before the title only when `t.priority === 'high'`. Todos without a `priority` field, as in the existing format test, render unchanged.

## Files to change
- `src/store.js`: `add(title, options = {})` with validation and the default; `list(filter = {})` with filter and sort.
- `src/format.js`: the `!` marker in `formatList`.
- `test/store.test.js`: new tests (below). Existing tests stay untouched.

## Tests to add (in `test/store.test.js`)
- Default priority is `'normal'`.
- Each of `'low'`, `'normal'`, `'high'` is stored in `priority`.
- Invalid values throw `RangeError`: `'urgent'`, `'High'`, `null`, `''`, `1`.
- A rejected add leaves `list()` unchanged.
- `list()` without a filter is ordered high, normal, low, and insertion order is kept within each priority (add a mix, e.g. normal a, high b, low c, high d, normal e → b, d, a, e, c).
- `list({ priority: 'high' })` returns only high todos, in insertion order; a priority with no todos returns `[]`.
- Invalid filter priority throws `RangeError`.
- `formatList`: high renders as `[ ] !Pay rent`; low and normal render as before; `[x] !Title` for a done high todo.

## Risks
- **Sort stability:** relies on the stable `Array.prototype.sort` (Node 11+). Acceptable; the project has no `engines` field, but `node --test` already requires a modern Node.
- **Mutation:** if `list()` sorts `todos` in place, insertion order is lost for later calls. The plan sorts a copy to prevent this, and a test that calls `list()` twice guards it.
- **Unknown consumers:** the store's list shape gains a field. No other code in the repo reads todos, so nothing else breaks.
