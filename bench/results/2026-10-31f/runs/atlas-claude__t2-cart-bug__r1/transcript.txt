The bug is fixed and all 8 tests pass (the 2 original tests plus 6 regression tests).

**Root cause: confirmed.** It is four separate defects in `total()` in `src/cart.js`, all confirmed by reading the code and reproduced by the new tests failing before the fix:

1. **Quantity ignored** (line 16): `sum += item.price` dropped `item.qty`. Three units at 19.90 gave 19.9.
2. **Percent coupon returned the discount, not the total** (line 21): `sum * 20 / 100` gave 20 for a 100 cart instead of 80.
3. **No floor at zero** (line 23): the fixed coupon subtracted without a lower bound. TENOFF on 5.00 gave -5.
4. **No rounding** (line 26): raw float sums gave `0.30000000000000004`.

Also fixed, a latent bug the report didn't mention: `COUPONS[couponCode]` matched inherited properties, so a code like `toString` returned `NaN`. This is a direct breach of "unknown coupons are ignored", so I fixed it with `Object.hasOwn`.

**Before the fix:** `npm test` showed 5 failures (quantity, TENOFF, OFF20, rounding, `toString`). The unknown-coupon test already passed.
**After the fix:** `npm test` shows `tests 8, pass 8, fail 0`.

**Files changed**
- `src/cart.js`: quantity multiplication, percent formula, coupon lookup via `Object.hasOwn`, and final `Math.max(0, Math.round(sum * 100) / 100)`. The `module.exports = { total }` API is unchanged.
- `test/cart.test.js`: six regression tests covering each symptom plus the `toString` case. Existing tests are unchanged.

**Residual risks**
- `Math.round(x * 100) / 100` is standard but can be off by one cent on exact half-cent values that binary floats can't represent (e.g. `1.005`). Exact fixes would need integer-cent arithmetic, which is a larger change than this task asked for.
- Inputs with more than 2 decimal places are rounded, not rejected. An item with no `qty` yields `NaN`; the JSDoc says `qty` is required, and I did not add validation.
- `Object.hasOwn` needs Node 16.9 or later. `node --test` already implies a modern Node, so this should be fine.
- The `HALF` coupon, which is not in the report, was left as it was.
- `git log` was refused by the sandbox approval step, so I did not review commit history for recent changes.

## QA verdict: pass

The fix removes the root cause of all five reported problems. `npm test` passes 8/8. I found no regression in the code paths I could trace. There are five low-severity findings, listed below, for the person to decide on.

### Root cause (from the original `total()`, per the prior step's report)
- **Quantity ignored:** the loop added `item.price` only, never `item.qty`.
- **Percent coupon inverted:** `sum * value / 100` returned the discount amount, not the discounted total.
- **Fixed coupon unbounded:** `sum - value` had no lower bound, so the total could go negative.
- **No rounding:** float sums leaked values like `0.30000000000000004`.
- **Prototype lookup:** `COUPONS[code]` matched inherited keys such as `toString`, which produced `NaN`.

### Fix applied (`src/cart.js`, lines 13–28)
- Line 16 multiplies `item.price * item.qty`.
- Line 18 looks up coupons with `Object.hasOwn(COUPONS, couponCode)`.
- Line 21 computes `sum * (100 - value) / 100` for percent coupons.
- Line 23 subtracts fixed coupons.
- Line 27 returns `Math.max(0, Math.round(sum * 100) / 100)`, which rounds once after the coupon and then clamps at zero.
- The export is still `module.exports = { total }`.

### Evidence
- **Read:** I read `src/cart.js`, `test/cart.test.js` and `package.json`. I traced each reported symptom through the new code:
  - 3 × 19.90 gives 59.7.
  - TENOFF on 5 gives 0.
  - OFF20 on 100 gives 80.
  - Long decimals are rounded.
  - `total` is the only export and the only caller in the repo (Grep found no other references).
- **Executed:** `npm test` gave 8 pass, 0 fail. This includes the six new tests in `test/cart.test.js`: quantity, fixed coupon clamp, percent coupon, cent rounding, unknown coupon, and inherited property.
- **Reported, not re-executed:** the prior step says five of the new tests failed before the fix. I could not re-run them against HEAD. Reading the old logic, the quantity, percent, clamp, rounding and `toString` tests would each fail on the old code. The unknown-coupon test passes both before and after, so it is not a regression guard.

### Findings (all low, outcome pass)
1. **Items without `qty` now produce `NaN`** (`src/cart.js:16`). The old code returned the price for such items. The JSDoc requires `qty`, so this is outside the documented contract. Recommendation: default `qty` to 1, or document the requirement.
2. **Half-cent float rounding** (`src/cart.js:27`). `Math.round(1.005 * 100)` is `1` because `1.005 * 100` is `100.49999999999999`, so the result is `1.00` rather than `1.01`. This reasoning is not executed. It only matters for sub-cent inputs or percent discounts that land on a half-cent. Recommendation: decide whether this matters. If it does, use an epsilon or integer-cent arithmetic.
3. **Test coverage gaps** (`test/cart.test.js`). Nothing combines `qty > 1` with a percent or fixed coupon, or covers multi-item percent rounding. Also uncovered: missing `qty`, `null`/`undefined` coupon codes, and `__proto__`/`constructor` keys.
4. **`Object.hasOwn` needs Node 16.9 or later** (`src/cart.js:18`). `package.json` has no `engines` field, and I did not check the runtime Node version. Recommendation: confirm the target Node version.
5. **Coupon codes are case-sensitive** (`src/cart.js:18`). `tenoff` is silently ignored. The spec does not say either way. Recommendation: decide whether this is intended.

### What I could not verify
- **Pre-fix behavior:** `git diff` and `git show HEAD:src/cart.js` were refused by the approval gate in this session. I could not inspect the diff directly, so the "before" behavior comes from the prior step's report and my reading of the old logic.
- **Node runtime version:** not checked, so the `Object.hasOwn` availability is unverified.
- **Edge-case behavior:** findings 1 and 2 are reasoned from the code, not run. I had no way to execute ad-hoc scripts in this read-only mode.
