The review is done. Verdict: **fail**. `src/users.js` has three functional defects, and two of them are security-relevant. There is no test suite, and I could not run code (read-only), so every finding below rests on reading alone. I checked the outputs by hand.

**Findings, most severe first**

1. **High, Security, `src/users.js:16-21` (`escapeHtml`).** `.replace()` with a string pattern only replaces the first occurrence, so the escaping is incomplete. `escapeHtml('<<img src=x onerror=alert(1)>>')` returns `&lt;<img src=x onerror=alert(1)&gt;>`, so a live `<img` tag survives. The function is documented as "safe to put inside HTML", so this is an XSS hole. Fix: use global regexes, `.replace(/&/g,'&amp;').replace(/</g,'&lt;').replace(/>/g,'&gt;')`, and also escape `"` and `'` (`&quot;`, `&#39;`), because attribute contexts need them.

2. **High, Correctness, `src/users.js:5` (`paginate`).** The doc comment says page 1 is the first page, but `start = page * size` treats the page as zero-based. With `items=[a,b,c,d,e]`, `size=2`, page 1 returns `[c,d]` and skips `a,b`. Page 3 returns `[]`. Fix: `const start = (page - 1) * size;`, and decide explicitly what happens for `page < 1` (throw or clamp).

3. **Medium, Correctness, `src/users.js:10-12` (`isAdult`).** It compares only calendar years. Someone born 2008-12-31 is reported as adult on 2026-12-30, when they are 17 until the next day. The `birthDate` parameter is a full Date, so the month and day are available and should be used. Fix: subtract one from the age if the birthday has not yet occurred on `today` (compare month, then day).

4. **Low, Maintainability/Testing, whole file.** There are no tests. `package.json` defines `"test": "node --test"`, but no test files exist, so none of the above is caught. Fix: add `src/users.test.js` covering the page boundaries, the birthday edge case, and `<<`/`>>` inputs to `escapeHtml`.

**Checked and found fine:** `userRow` (`src/users.js:24-26`) escapes the name and renders the admin flag as a fixed string, so it adds no injection risk. The module layout and CommonJS export match `package.json`.

**Not looked at:** the web page that calls these helpers (the README says it exists, but it is not in the worktree), any runtime behaviour, and the test run itself.
