The total was wrong in four separate places in `src/cart.js`, and all four are fixed. All 8 tests now pass, including the 5 new regression tests that failed before the fix.

**Root causes (confirmed by reading and by running the tests):**
- **Quantity ignored:** the sum added `item.price` without `item.qty` (line 16). This gave 19.9 instead of 59.7.
- **Percent coupon wrong:** the code computed the discount amount, `sum * value / 100`, not the amount to pay (line 21). This gave 20 instead of 80.
- **Fixed coupon can go negative:** nothing clamped the result at zero (line 23). This gave -5.
- **No rounding:** the raw float was returned (line 26). This gave 0.30000000000000004.
- **Latent issue:** `COUPONS[couponCode]` read inherited object properties, so a code like `toString` produced `NaN`. It is not in the bug report, but the requirement that unknown coupons are ignored covers it.

**Fix:** quantity is multiplied in, the percent coupon uses `(100 - value)`, the total is clamped at zero, the result is rounded to cents once at the end, and coupon lookup uses `hasOwnProperty`. The `module.exports = { total }` API is unchanged.

**Verification:** `npm test` (which runs `node --test`) failed 5 of 8 before the fix, with `19.9 !== 59.7`, `20 !== 80`, `-5 !== 0`, `0.30000000000000004 !== 0.3`, and `NaN !== 10`. After the fix it passes 8 of 8 with 0 failures. I did not run `git log` because the sandbox refused it, so I did not check recent history.

**Files changed:**
- `src/cart.js`
- `test/cart.test.js`: added 5 regression tests (quantity, percent, fixed floor, rounding, inherited-property coupon)

**Residual risk:**
- Rounding uses `Math.round` on binary floats, so exact half-cent cases can round the other way (for example, a value that is really 1.005 may come out as 1.00).
- A missing or non-numeric `qty` still gives `NaN`. I did not add a guard because the report did not ask for one.
- The `HALF` coupon now also takes 50% off correctly, but no test covers it.
