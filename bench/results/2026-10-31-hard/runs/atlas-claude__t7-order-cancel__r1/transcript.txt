# Plan: order cancellation

**Baseline:** `npm test` passes all 3 existing tests (`test/shop.test.js`). I have not edited any files.

## Goals
- `orders.cancel(orderId, reason)` cancels a placed order, returns stock, stores status `'cancelled'` and the reason, and emits one `order.cancelled` event with `{ orderId, reason }`.
- Error and validation rules as specified in the task.
- `reports.revenue()` and `reports.unitsSold(sku)` ignore cancelled orders.

## In scope / out of scope
- **In:** `src/inventory.js`, `src/orders.js`, `src/reports.js`, and tests in `test/`.
- **Out:** refunds or payments, partial cancellation of single lines, cancelling placed-by-other-means orders, changes to `src/events.js` (the bus already supports this), changes to `src/shop.js` (wiring is unchanged, since `createOrders` already receives `inventory` and `bus`).

## Current state (what the change touches)
- `src/orders.js:6-16` `place()` checks stock, calls `inventory.take()`, builds the order `{ id, items, total, status: 'placed' }`, stores it in a `Map`, emits `order.placed`, and returns a copy. `get`/`all` return copies with copied items.
- `src/inventory.js:8-12` only has `quantity` and `take`. There is no way to put stock back, so one is needed.
- `src/reports.js:4-13` sums over `orders.all()` with no status filter.
- `src/events.js` is a synchronous `on`/`emit` bus.

## Steps for the Developer
1. **`src/inventory.js`:** add `add(sku, qty)` next to `take`, using the same style: `stock.set(sku, (stock.get(sku) ?? 0) + qty)`. No validation beyond that, to match `take`.
2. **`src/orders.js`:** add `cancel(orderId, reason)` in this order:
   1. If `typeof reason !== 'string' || reason.trim() === ''`, throw `TypeError('reason must be a non-empty string')`. This runs first so that bad input is always a `TypeError`, even for an unknown id.
   2. Look up the order. If missing, throw `Error(\`order ${orderId} not found\`)`.
   3. If `order.status === 'cancelled'`, throw `Error(\`order ${orderId} is already cancelled\`)`.
   4. Set `order.status = 'cancelled'` and `order.reason = reason`.
   5. For each item, call `inventory.add(sku, qty)`.
   6. `bus.emit('order.cancelled', { orderId, reason })` once.
   7. Return a copy in the same shape as `get`.
   
   All throws happen before any mutation, so a failed call changes nothing.
3. **`src/reports.js`:** in both `revenue` and `unitsSold`, filter `orders.all()` with `o.status !== 'cancelled'` before summing. Keep `orders.all()` returning every order, so `get`/`all` keep their current meaning.
4. **Tests** in `test/shop.test.js` (same file and style as the existing tests, using `setup()`):
   - Cancel restores stock and sets status and reason. Check the returned order and `orders.get(id)`.
   - Emits exactly one `order.cancelled` event with `{ orderId, reason }` (`deepStrictEqual`).
   - Unknown id throws `Error` matching `/not found/`. Stock and events are unchanged.
   - Cancelling twice throws `Error` matching `/already cancelled/`. The second call moves no stock and emits no event.
   - Empty string, whitespace-only and non-string reasons throw `TypeError`. Nothing changes.
   - Reports: after cancelling, `revenue()` and `unitsSold('pen')` drop the cancelled order's contribution.
   - The three existing tests stay unchanged.

## Decisions for the Developer to follow
- Argument validation (`TypeError`) runs before the lookup, so the error type never depends on whether the order exists.
- Whitespace-only reasons are rejected. The task says "non-empty"; treating `'   '` as empty is my recommendation. Flagging it so it can be changed.
- The stored field is `reason` on the order object, and status becomes `'cancelled'`. The order keeps `total` and `items`.
- Reports filter by status and do not change `orders.all()`.
- Ids are matched with `Map.get` and strict equality, so `cancel('1')` is "not found". This matches `get`.

## Architectural notes and risks
- **Status string coupling:** the `'cancelled'` literal would now appear in `orders.js` and `reports.js`. With two uses, a shared constant is not needed. If more consumers filter by status, extract one.
- **Any new consumer of `orders.all()` must filter cancelled orders itself.** This is the main maintainability risk, and the reason reports filter in `reports.js` rather than in `orders.all()` (which would silently change `get`/`all`).
- **Synchronous bus:** a handler that throws on `order.cancelled` would surface after the state change and restock have already happened. This is the same as the existing `order.placed` path. Not changed here, but worth knowing.
- **Restock is not atomic with validation:** `inventory.add` cannot fail, so the order of mutation is safe. If `add` ever gained validation, the cancel steps would need reordering.

## Verification
- `npm test` must pass the 3 existing tests plus the new cases.
- Run `npm test` before and after the change to confirm nothing regressed.
- The tests above cover each rule in the task: stock, status, reason, event shape, error types and messages, no-op on failure, and the report filters.
