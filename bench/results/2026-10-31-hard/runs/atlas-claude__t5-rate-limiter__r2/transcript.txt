## Plan: token bucket limiter (`src/limiter.js`, `test/limiter.test.js`)

**Goal:** Add a dependency-free CommonJS token bucket, `createLimiter(options)`, exported as `module.exports = { createLimiter }`, with tests that use an injected clock.

**Current state:** The repo has only `package.json` (`"type": "commonjs"`, `"test": "node --test"`), `README.md` (no dependencies, built-in runner), and no `src/` or `test/` yet. Node is v24, so `node --test` finds `test/*.test.js` by default. Nothing else in the repo needs to change.

**In scope:** `src/limiter.js` (new) and `test/limiter.test.js` (new). Nothing else.
**Out of scope:** `package.json`, `README.md`, any other file, and any new dependency.

### Design

- **State:** `capacity`, `refillPerSecond`, `tokens` (a float), and `lastTime` (the reference time in ms). `createLimiter` sets `tokens = capacity` and reads `now()` once to set `lastTime`.
- **Refill (private, called first in every public method):**
  - `t = now()`.
  - If `t < lastTime`, set `lastTime = t` and add nothing. This keeps the backwards-clock rule: no tokens are added or lost.
  - Otherwise `tokens = min(capacity, tokens + elapsed * refillPerSecond / 1000)`, then `lastTime = t`.
  - Multiply before dividing so that values like 0.5/s over 1000 ms come out exactly 0.5.
- **Validation in `createLimiter`:** `capacity` must pass `Number.isInteger` and be `> 0`. `refillPerSecond` must be `typeof === 'number'`, `Number.isFinite`, and `> 0`. Any failure throws `RangeError`. `now` defaults to `Date.now`. I will not add extra type checks on `now`, because the spec does not ask for them.
- **Count validation (`n`, default 1), shared by `tryRemove` and `msUntil`:** `n` must be an integer `> 0` and `<= capacity`. Otherwise throw `RangeError`.
- **`tryRemove(n = 1)`:** refill, then if `tokens + EPS >= n`, subtract `n`, clamp at 0, and return `true`. Otherwise return `false` and change nothing.
- **`available()`:** refill, then return `Math.floor(tokens + EPS)`.
- **`msUntil(n = 1)`:** refill, then `deficit = n - tokens`. If `deficit <= EPS`, return 0. Otherwise return `Math.ceil(deficit * 1000 / refillPerSecond)`, with the same epsilon guard applied to the ceiling.
- **`reset()`:** set `tokens = capacity` and refresh `lastTime = now()`.
- **`EPS`:** a small constant (`1e-9`) that absorbs float drift at exact boundaries. It is a single module-level constant with a short comment.

### Decisions the Developer must follow

1. Keep to the single-closure style: `createLimiter` returns an object of methods over private state. Do not introduce classes, a `this`-based API, or a separate file for helpers.
2. Refill happens inside every public method, including `reset`'s timestamp refresh. No timers and no background work.
3. Do not clamp or reject a backwards clock. Only move the reference point.
4. Use `Number.isInteger` for `capacity` and `n`. Do not accept numeric strings.
5. Tests use `require('node:test')` and `require('node:assert')`, plus a fake clock: `let t = 0; const now = () => t;`. Advance `t` manually. Do not use real time.

### Test plan (`test/limiter.test.js`)

- Starts full: `available()` equals capacity; `tryRemove` succeeds up to capacity, then fails.
- A failed `tryRemove` leaves the token count unchanged.
- Fractional refill: with `refillPerSecond` 0.5, after 1000 ms exactly 0.5 tokens are added, so `available()` is still 0 and `msUntil()` is 1000.
- Refill caps at capacity after a long wait.
- `available()` floors fractional tokens.
- `msUntil()` returns 0 when tokens are available, and rounds up otherwise.
- `n` checks: non-integer, 0, negative, and `n > capacity` throw `RangeError` for both `tryRemove` and `msUntil`.
- `createLimiter` throws `RangeError` for each invalid option: missing, string, zero, negative, `NaN`, `Infinity`, and a non-integer capacity.
- `reset()` refills to capacity.
- Clock going backwards: no tokens are added; time moves forward again from the earlier reference; tokens are not lost.
- `createLimiter` without `now` runs and returns a number from `available()`.

### Risks

- **Float drift** at exact boundaries (for example, `tokens = 0.9999999999` when 1 is expected). The `EPS` guard addresses this. Tests should cover exact boundaries.
- **Wall-clock jumps** (`Date.now` is not monotonic). Handled by the backwards-clock rule, but that rule also means a forward jump counts as real elapsed time.
- **Very small `refillPerSecond`** gives very large `msUntil` values. These stay finite and need no special handling.

4. **Robustness: a now() that returns NaN fails open** (`src/limiter.js:22-28`, `:45`). Read. NaN propagates through `Math.min`/`Math.max`, so `tokens + EPS < n` is false and tryRemove returns true. 5. **Correctness edge: the fixed EPS is below one ulp for very large capacity** (`src/limiter.js:2`, `:28`). Read, by reasoning, not executed.
