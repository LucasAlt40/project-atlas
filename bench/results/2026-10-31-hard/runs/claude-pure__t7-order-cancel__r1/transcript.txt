**Changes**
- **`src/inventory.js`**: new `restock(sku, qty)`, which adds stock back. `take` is unchanged.
- **`src/orders.js`**: new `cancel(orderId, reason)`.
  - It throws a `TypeError` if `reason` is not a non-empty string.
  - It throws an `Error` containing "not found" for an unknown order.
  - It throws an `Error` containing "already cancelled" for a repeat cancel.
  - Otherwise it restocks the items, sets `status` to `'cancelled'`, emits one `order.cancelled` event with `{ orderId, reason }`, and returns a copy of the order.
- **`src/reports.js`**: `revenue()` and `unitsSold(sku)` now skip cancelled orders.
- **`test/cancel.test.js`** (new): covers restock and event, not-found, double cancel, invalid reasons, and reports after cancelling.

**Choices I made**
- The reason is stored on the order as `reason`, to match the event payload. The spec didn't name the field.
- Argument validation runs first, so an invalid reason on a missing order throws the `TypeError`, not the "not found" error.
- A whitespace-only reason counts as non-empty, since the spec says "non-empty string" and I took that literally.

The existing tests in `test/shop.test.js` were not changed; I read them to confirm the expected totals still hold.
