All five reported bugs are fixed in `src/csv.js`, along with the empty-input and unclosed-quote requirements. `npm test` now passes 11 of 11, up from 2 passing before the change.

**Root causes (confirmed by reading the code, and reproduced by the new tests failing on the old code):**
- **Commas inside quotes split fields.** `split(',')` ignored quoting.
- **Doubled quotes were not unescaped.** The old code only stripped the outer quotes.
- **Line-based splitting caused three bugs.** `split('\n')` produced an extra row for a trailing newline, split quoted fields that contain line breaks, and left `\r` on the last field of CRLF rows.
- **Empty input** returned `[['']]` instead of `[]`.
- **Unclosed quotes** were never detected, so no `SyntaxError` was thrown.

**Fix:** I replaced the function body with a single left-to-right pass that tracks whether it is inside quotes. Quotes only open a quoted field at the start of a field, so `a"b` stays literal as before. The export is unchanged: `module.exports = { parseCsv }`.

**Files changed:**
- `src/csv.js`: the `parseCsv` body was rewritten.
- `test/csv.test.js`: 9 regression tests were added. Seven cover the reported bugs and the two requirements above. The other two (empty fields, unquoted quote kept literally) guard behavior that must not change. The original 2 tests are untouched.

**Residual risks:**
- Text after a closing quote is appended literally, so `"ab"c` becomes `abc`. This is lenient, not strict RFC 4180, and I did not add an error for it because the task did not ask for one.
- A lone `\r` not followed by `\n` is kept as field data.
- Files with a UTF-8 BOM are not handled specially, so the BOM stays at the start of the first field. This is unchanged from before.

**Root cause (read from `git show d848ae1:src/csv.js`).** The original parser split on `\n`, then on `,`, then stripped a leading and trailing `"` from each field. It had no quote state, so each reported bug follows from that:
- Commas inside quotes split fields.
- `""` was never unescaped.
- `split('\n')` produced a trailing empty row.
- `\r` survived in the last field.
- Line breaks inside quotes started new rows.
- Unclosed quotes were never detected.

**Fix applied (commit `29f2f19`).** The split-based body is replaced by one left-to-right character pass with an `inQuotes` state. Doubled quotes are unescaped, CRLF and LF are row terminators, and a trailing row is emitted only if the row is open. An unclosed quote throws `SyntaxError`. The export is still `module.exports = { parseCsv }`. This removes the cause, not a symptom.
