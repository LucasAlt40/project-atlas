The customer reports came from five defects in `src/cart.js`. I fixed all five, added regression tests, and `npm test` now passes 7/7 (the 2 original tests still pass).

**Root causes (confirmed by reading the code; each reported number matches the code path exactly):**
1. Quantity ignored: `sum += item.price` dropped `qty`, so 3 × 19.90 gave 19.9.
2. Percent coupon inverted: `sum * value / 100` returns the discount, not the amount to pay, so 100 with OFF20 gave 20.
3. Fixed coupon unbounded: `sum - 10` can go negative, so 5.00 with TENOFF gave -5.
4. No cent rounding: float sums gave values like 0.30000000000000004.
5. Unknown coupons not ignored (found on reading, not in the report): `COUPONS[couponCode]` matched inherited names like `toString`, which yields `sum - undefined` = NaN.

**Fix:** multiply by `qty`; apply the percent as `sum * (100 - value) / 100`; look up coupons with `hasOwnProperty`; then return `Math.round(Math.max(sum, 0) * 100) / 100`. The `module.exports = { total }` API is unchanged.

**Regression tests** (in `test/cart.test.js`): quantity (19.9 × 3 = 59.7), TENOFF on 5.00 → 0, OFF20 on 100 → 80, cent rounding (0.1 + 0.2 → 0.3, 9.99 with OFF20 → 7.99), and unknown or inherited coupon names ignored. Each would have failed on the original code. I reasoned that from the code, since I could not run the old version in isolation.

**Residual risks:**
- `Math.round(x * 100) / 100` can still be off by one cent on exact half-cent float values (e.g. 1.005). Exact integer-cent arithmetic would remove this, but it is a larger change than the report needs.
- `qty` is not validated. A missing or non-numeric `qty` yields NaN, as it did before the fix for other inputs.
- The fixed-coupon discount is applied before the zero clamp, so a coupon larger than the cart yields 0 as intended.

**Files changed:** `src/cart.js`, `test/cart.test.js`.
