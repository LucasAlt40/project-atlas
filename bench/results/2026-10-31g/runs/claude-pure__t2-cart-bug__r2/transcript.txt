## Root cause

All five customer symptoms came from `src/cart.js`:

| Symptom | Cause |
|---|---|
| 3 × 19.90 shows 19.9 | `sum += item.price` ignores `item.qty` |
| TENOFF on 5.00 shows -5 | fixed coupon subtracts with no floor at 0 |
| OFF20 on 100 shows 20 | percent coupon returned the discount amount, not `sum × (100 − value) / 100` |
| `0.30000000000000004` | float arithmetic was returned without rounding |
| Unknown coupon edge case | `COUPONS[couponCode]` also matched inherited keys such as `toString`, which turned into `NaN` |

## Changes

**`src/cart.js`** (API unchanged: `module.exports = { total }`)
- Line total is `price * qty`.
- Coupon lookup uses `Object.prototype.hasOwnProperty.call`, so unknown codes and inherited keys are ignored.
- Percent coupons apply `(100 − value)%`.
- The result is clamped at 0 with `Math.max(0, sum)`, then rounded to cents with `Math.round(… * 100) / 100`.

**`test/cart.test.js`**: added regression tests for quantity and rounding (59.7, and 0.1×3 + 0.2 = 0.5), the TENOFF floor (5 → 0), OFF20 (100 → 80), and unknown or inherited coupons (ignored).

The two existing tests still hold by inspection: a single item of 10 returns 10, and an empty cart returns 0.
