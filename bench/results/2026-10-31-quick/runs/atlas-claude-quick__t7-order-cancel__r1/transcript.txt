## Plan: order cancellation

### Goals
- Cancel a placed order: restore its stock, set `status: 'cancelled'`, store `reason`, emit `order.cancelled` once with `{ orderId, reason }`, and return the cancelled order.
- Reject bad input before anything changes.
- Keep reports consistent: cancelled orders do not count toward revenue or units sold.
- Keep all existing behaviour and tests.

### Out of scope
- Refunds, partial cancellation, re-placing a cancelled order, and cancelling in other states (no other states exist today).
- Changes to `shop.js` wiring: `createShop` already passes `inventory`, `bus` and `orders` through, so no wiring change is needed.

### Current structure and dependencies
- `createOrders({ inventory, bus, prices })` (`src/orders.js`) owns the order map and calls `inventory.take` and `bus.emit`. It is the only writer of order state.
- `createInventory` (`src/inventory.js`) exposes only `quantity` and `take`. There is no way to put stock back.
- `createReports({ orders })` (`src/reports.js`) reads `orders.all()` and sums every order. It knows nothing about status.
- `orders.get` and `orders.all` return copies. Cancel must return a copy as well, so callers cannot mutate internal state.

### Decisions the Developer must follow
1. **Inventory gets an inverse of `take`.** Add `add(sku, qty)` to `createInventory`: `stock.set(sku, (stock.get(sku) ?? 0) + qty)`. Do not reuse `take` with negative numbers, because `take`'s guard would reject them.
2. **Validation order in `cancel`:**
   1. `reason` is not a non-empty string → `TypeError`. A whitespace-only string counts as empty (`reason.trim() === ''`). This is my reading of "non-empty"; flag it if you want otherwise.
   2. Order not in the map → `Error` containing `not found`.
   3. `status === 'cancelled'` → `Error` containing `already cancelled`.
   4. Only after all checks pass: call `inventory.add` for each item, set `status` and `reason` on the stored order, emit `order.cancelled`, and return a copy.
   Doing all checks before any mutation is what makes "changes nothing" hold.
3. **Status values.** `place` keeps `'placed'`. `cancel` is the only transition to `'cancelled'`. Do not add a `reason` field in `place`; it is set only on cancel.
4. **Where the "counts as a sale" rule lives.** Put the filter in `reports.js`: both `revenue` and `unitsSold` skip orders with `status === 'cancelled'`. Do not add a flag to `orders.all()`. Reports already owns what counts, and this avoids growing the orders API.
5. **Event ordering.** Emit after the state change, matching how `place` emits after `take`. The bus is synchronous, so a throwing handler would leave the order cancelled and stock restored. This is the same existing risk as `place`; do not fix it in this change, but mention it.
6. **Keys.** Order IDs are numbers (`nextId`). `cancel('1')` will report "not found". Do not coerce; this matches `get`.

### Files and contracts to change
- `src/inventory.js`: new `add(sku, qty)`. Existing `quantity` and `take` unchanged.
- `src/orders.js`: new `cancel(orderId, reason)`. Returns `{ ...order, items: copies }` in the same shape as `get`. Event payload `{ orderId, reason }`. `place`, `get` and `all` unchanged.
- `src/reports.js`: `revenue` and `unitsSold` filter out cancelled orders. Result shape unchanged.
- `test/shop.test.js`: append new tests using the existing `setup()` helper and `node:test` style. Do not change the existing three tests.

### Tests to add
- Cancel restores stock: `pen` goes from 8 back to 10 after cancelling a pen+cup order.
- Cancel returns the order with `status: 'cancelled'` and the `reason`, and `get(id)` reflects the same.
- Cancel emits exactly one `order.cancelled` with `{ orderId, reason }`, and nothing else is emitted.
- Unknown id throws `Error` matching `/not found/`.
- Cancelling twice throws `Error` matching `/already cancelled/`. Stock and the event count do not change on the second attempt.
- Empty string, whitespace-only string and a non-string `reason` each throw `TypeError`, and stock, status and events are unchanged.
- Reports: after placing two orders and cancelling one, `revenue()` and `unitsSold(sku)` count only the remaining order.

### Risks
- **Partial state if a handler throws** (see decision 5). Pre-existing pattern; not fixed here.
- **Reports coupling.** `reports.js` now depends on the status string. If more statuses appear, the filter must be updated in one place. Acceptable at this size.
- **Input type drift.** Numeric IDs only; string IDs will be "not found".

- Check the diff: `src/shop.js` and `src/events.js` should be untouched.
