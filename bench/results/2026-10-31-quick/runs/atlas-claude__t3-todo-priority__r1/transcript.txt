### Scope
- **In:** priority validation and storage, filtered and sorted `list()`, `!` marker in `formatList`, tests for all of it.
- **Out:** changing `complete()`, adding a way to change priority on an existing todo, README updates, new modules, and changing the TypeError behaviour for titles.

### Architectural impact
- Priority is a small domain rule owned by the store. Presentation (`format.js`) only reads `t.priority === 'high'`. There is no new dependency and no new module.
- The priority vocabulary lives in one place in `store.js`: a rank map `{ high: 0, normal: 1, low: 2 }`. Validation uses its keys and sorting uses its values, so the two cannot drift apart. Do not export it: `format.js` only needs the literal `'high'`.
- **Behaviour change to existing API:** `list()` with no filter now returns todos sorted by priority, not pure insertion order. This is what the spec asks for. The only caller is the test file, so the effect is contained, but it should be called out in the final summary.

### Decisions the Developer must follow
1. **Default:** `add(title, options = {})`. Only `options.priority === undefined` yields `'normal'`. Any other value, including `null`, `''`, `'High'`, or numbers, throws `RangeError`. Matching is case-sensitive.
2. **Validation order:** keep the existing title check first (TypeError), then the priority check (RangeError).
3. **Stored field:** the todo object is `{ id, title, done, priority }`. `list()` still returns copies.
4. **Sorting:** do not mutate the internal `todos` array. Sort a copy, using `rank[a.priority] - rank[b.priority]`. `Array.prototype.sort` is stable in Node ≥ 12, which keeps insertion order within a priority. Add no explicit tiebreak based on id.
5. **Filter:** `list(filter)` treats `filter` as optional and filters only when `filter.priority !== undefined`. An unknown filter priority throws `RangeError`, matching `add`, so that a typo does not silently return an empty list.
6. **Format:** `formatList` writes `[ ] !title` only when `t.priority === 'high'`. Todos without a `priority` field (like the existing format test's inputs) render exactly as before.

### Files and contracts
- `src/store.js`
  - `add(title, options = {})` returns `{ id, title, done, priority }`.
  - `list(filter = {})` returns copies, filtered by `filter.priority` if given, otherwise sorted high → normal → low, stable within a priority.
- `src/format.js`: `formatList(todos)` gets the `!` marker for high. Its output format and signature stay the same.
- `test/store.test.js`: append new tests. Do not change existing ones.
