## Plan: order cancellation

**Goal:** `orders.cancel(orderId, reason)` restores stock, marks the order `cancelled` with its reason, emits one `order.cancelled` event, and returns the cancelled order. Reports stop counting cancelled orders. Existing behaviour and the tests in `test/` stay unchanged.

**In scope:** `src/orders.js`, `src/inventory.js`, `src/reports.js`, and new tests in `test/`.
**Out of scope:** `src/events.js` (no change needed), `src/shop.js` (wiring already passes `inventory`, `bus`, `orders` through), new statuses beyond `cancelled`, refunds, and payment.

### What I read
- `src/orders.js`: `createOrders({ inventory, bus, prices })` keeps orders in a `Map`. `place()` checks stock, takes it, computes `total`, stores `status: 'placed'`, emits `order.placed`. `get`/`all` return copies, so callers cannot mutate stored state.
- `src/inventory.js`: only `quantity` and `take` exist. There is no way to return stock.
- `src/reports.js`: `revenue()` and `unitsSold(sku)` both read `orders.all()` with no status filter.
- `src/events.js`: a synchronous `on`/`emit` bus.
- `test/shop.test.js`: uses `node:test` and `assert`, with a local `setup()` helper. `package.json` runs `node --test`.

### Decisions for the Developer
1. **Inventory gets a `restock(sku, qty)` method** that adds back to stock (`stock.set(sku, (stock.get(sku) ?? 0) + qty)`). Keep it next to `take` and in the same style. Do not add a general stock-adjustment API.
2. **Validation order in `cancel`:** check `reason` first (`TypeError`), then look up the order (`Error` containing "not found"), then check status (`Error` containing "already cancelled"). All checks run before any mutation, so a failed call changes nothing. Argument validation is cheapest and does not depend on state.
3. **Reason rule:** must be a `string` and `reason.trim() !== ''`. Whitespace-only counts as empty. This is my reading of "non-empty"; the spec does not say explicitly.
4. **Stored field names:** `status` becomes `'cancelled'`, and the reason is stored as `reason` on the order record. The copies returned by `get`/`all`/`place` will include it.
5. **Mutation then emit:** set status and reason, restock items, then `bus.emit('order.cancelled', { orderId, reason })` exactly once. Emitting after state is consistent means handlers see the final state. Restock cannot fail, so no partial-state case arises.
6. **Return value:** a copy of the cancelled order, using the same copy helper style as `get`. Implement the copy once inside `orders.js`, or reuse the existing inline pattern. Do not add a new module.
7. **Reports:** filter `o.status !== 'cancelled'` in both `revenue()` and `unitsSold()`. Reports keep reading through the public `orders.all()`. Do not add a second index.
8. **Tests:** add a new file `test/orders-cancel.test.js` that reuses the same `setup()` shape. Leave `test/shop.test.js` untouched so existing tests are not affected. Cases to cover:
   - Stock returns to the pre-order level.
   - Status is `cancelled`, the reason is kept, and the returned value matches.
   - `order.cancelled` fires once with `{ orderId, reason }`.
   - Unknown id throws an `Error` matching `/not found/`, with no stock change and no event.
   - Second cancel throws an `Error` matching `/already cancelled/`, with no stock change and no event.
   - Empty, whitespace-only, and non-string reasons throw `TypeError` with nothing changed.
   - `revenue()` and `unitsSold(sku)` exclude cancelled orders, and count the remaining placed orders.

### Files and contracts
- `src/inventory.js`: add `restock(sku, qty)`.
- `src/orders.js`: add `cancel(orderId, reason)`. Public contract: returns an order copy with `status: 'cancelled'` and `reason`. Emits `order.cancelled` with `{ orderId, reason }`.
- `src/reports.js`: status filter in both functions.
- `test/orders-cancel.test.js`: new.
- No changes to the `order.placed` payload or to `place()` behaviour.

### Risks
- Synchronous bus: if a `order.cancelled` handler throws, the state has already changed. This matches the existing `place` behaviour. It is a known limit, not something this change should solve.
- Ids: `cancel` uses strict `Map` lookup, so `'1'` will not match `1`. This is consistent with `get`.
- Existing `place` returns shallow order copies. The new `cancel` should copy items too, so callers cannot mutate stored items.

### Verification
- `npm test` (`node --test`) must pass with the existing tests unchanged and the new file included.
- I did not run tests in this step, since the step is analysis only.

**Open question:** none that blocks the work. Decision 3 (whitespace-only reason) is my interpretation; flag it if you want something different.
