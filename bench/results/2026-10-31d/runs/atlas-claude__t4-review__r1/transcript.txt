## Review: `src/users.js`

**Verdict: fail.** The module is small, has no dependencies, and fits the project. Three of its four functions have defects, and one of them is an XSS path in `escapeHtml`. I read the code and ran `npm test`. The tests report 0, so every finding below rests on reading alone. I could not execute the functions.

### Findings, most severe first

**1. High · Security · `src/users.js:18-20` · `escapeHtml` replaces only the first occurrence of each character**
- Why it is wrong: `.replace('&', …)`, `.replace('<', …)` and `.replace('>', …)` with string patterns change only the first match. Any later `<` or `>` passes through unescaped. `userRow` (line 25) puts `escapeHtml(user.name)` into HTML, so a crafted name is injected.
- Example, by trace: `name = "<<img src=x onerror=alert(1)>"`. The first `<` becomes `&lt;`, but the second stays raw. The output still contains a live `<img … onerror=…>` tag. This is a stored or reflected XSS path if a user name is untrusted.
- Fix: use global regexes and keep `&` first: `String(text).replace(/&/g, '&amp;').replace(/</g, '&lt;').replace(/>/g, '&gt;')`. Add `.replace(/"/g, '&quot;').replace(/'/g, '&#39;')` so the function is also safe in attribute values (see finding 4).

**2. High · Maintainability (correctness vs. documented contract) · `src/users.js:5-6` · `paginate` is off by one**
- Why it is wrong: the doc comment (line 3) says `page` is 1-based ("1 is the first page"), but `start = page * size` skips the first page entirely. Page 1 returns items `size…2·size-1`. Page 0 returns the first page. A `NaN` or negative page produces a silent wrong slice.
- Fix: `const start = (page - 1) * size;`. Also validate that `page` and `size` are integers ≥ 1 and throw otherwise, so bad input is not silently sliced.

**3. Medium · Maintainability (correctness vs. documented contract) · `src/users.js:11-12` · `isAdult` ignores month and day**
- Why it is wrong: the doc comment (line 9) says "18 or older on `today`", but the code subtracts only the years. Someone born on 2008-06-15 is counted as 18 on 2026-03-01, when they are actually 17. Someone born 2008-12-31 is counted as adult on 2026-01-01.
- Fix: compute the age exactly. After the year subtraction, subtract one if `today`'s month/day is before `birthDate`'s month/day, or use `today >= new Date(birthDate) + 18 years` in a consistent time zone. Because `getFullYear()` uses local time, also normalize the time zone or compare calendar date parts consistently.

**4. Low · Security · `src/users.js:15-21` · `escapeHtml` does not escape quotes**
- Why it matters: the doc says "Text safe to put inside HTML", which is broader than element content. Quotes are not escaped, so if this helper is later used inside an attribute value (e.g., `title="${…}"`), a `"` in the input breaks out. Current use in `userRow` is element content only, so there is no present exploit. This is a hardening point and not a current defect.
- Fix: escape `"` and `'` as in finding 1, and rename or document the function as element-content-only if quotes are intentionally left alone.

**5. Low · Testing · repository root · no tests exist**
- Evidence: a glob of `**/*.{js,json,md}` finds only `README.md`, `package.json` and `src/users.js`. `npm test` (`node --test`) reports `tests 0`. None of the defects above would be caught.
- Fix: add a `node:test` file (for example `test/users.test.js`) covering: page 1 returns the first `size` items; `escapeHtml` on `"<<a>"` and on `"a&b&c"`; `isAdult` at a birthday boundary on both sides; `userRow` with a `<`-containing name.

### Parts I did not look at
- The consuming web page, which is not in the repository. Whether `escapeHtml` is used anywhere other than `userRow` is unknown.
- The actual runtime behavior of the functions. I did not execute them; findings 1–3 come from reading the code.
- Time-zone behavior of `isAdult` across environments.
- Any intended design beyond the doc comments; the README gives no further contract.
