Phase 2 is done. All 7 tests pass, including the 5 regression tests that failed before the fix.

## What was wrong

All four reported symptoms, plus one latent bug, came from `src/cart.js` in `total()`:

1. **Quantity ignored** (line 16). The loop added `item.price` and never used `item.qty`, so 3 × 19.90 gave 19.9.
2. **Fixed coupon not floored** (line 23). `sum - coupon.value` could go negative, so 5.00 − 10 gave −5.
3. **Percent coupon returned the discount** (line 21). `sum * value / 100` gives the amount off, not the amount to pay. For 100 with OFF20 it gave 20 instead of 80.
4. **No rounding** (line 26). Float arithmetic produced values such as 0.30000000000000004.
5. **Prototype keys matched as coupons** (line 18). `COUPONS[couponCode]` finds inherited properties, so a code like `toString` returned `NaN`. This breaks "unknown coupons are ignored". It was not in the customer reports.

Causes 1–4 are confirmed by the code and the reports. Cause 5 was confirmed by the test run (`NaN !== 10`).

## The fix

- Items are summed in integer cents: `Math.round(price × 100) × qty`. This also removes float drift.
- Percent coupons keep the payable share: `cents × (100 − value) / 100`, rounded to whole cents.
- Fixed coupons subtract their value in cents.
- The result is clamped with `Math.max(0, cents)` and divided by 100, so it is a plain number with at most 2 decimals.
- Coupon lookup uses `Object.prototype.hasOwnProperty.call`, so only the codes in `COUPONS` apply.
- The public API is unchanged: `module.exports = { total }`.

## Tests

`test/cart.test.js` gained five regression tests: quantity, TENOFF floor, OFF20 price, cent rounding (0.1 + 0.2 = 0.3), and unknown or prototype coupon codes. They were run before the fix (5 failing, with the failures above) and after it (all passing).

## Commands run

- Baseline `npm test`: 2 pass, 0 fail.
- After adding the regression tests, `npm test`: 2 pass, 5 fail, with the expected assertion messages (19.9 !== 59.7, -5 !== 0, 20 !== 80, 0.30000000000000004 vs 0.3, NaN !== 10).
- After the fix, `npm test`: `tests 7, pass 7, fail 0`.

I could not run ad-hoc `node` commands, since Bash is limited to the project's test commands. The reproduction and verification therefore go through the test suite.

## Files changed

- `src/cart.js`
- `test/cart.test.js`

## Residual risk

- Each line is rounded to cents before quantity is applied. If a price has sub-cent precision, that rounding happens per unit; the spec does not say which rounding rule to use, so this is an assumption.
- Percent discounts use `Math.round`, so a half-cent rounds up. This is a choice, not something the spec fixed.
- Input is not validated. A missing `qty` gives `NaN`, and negative prices or quantities are accepted. The reports did not cover these, so I left them alone.
- The `HALF` coupon is still defined and is now computed correctly as 50% off. I did not add a test for it.

The suite passes and the only caller is the test file. I'll trace the reported cases by hand against the code, since I can't run ad-hoc scripts here.

**Root cause (from the investigate step, confirmed by reading the code):** `total()` had four independent defects: it ignored `qty`, subtracted fixed coupons without a floor, returned the discount instead of the payable amount for percent coupons, and used float arithmetic with no rounding. It also looked coupon codes up through the prototype chain.

**Fix (read in `src/cart.js:13-30`):** prices are converted to integer cents per line and multiplied by `qty`. The coupon is applied in cents, with a `Math.max(0, …)` floor. The result is divided by 100 once. Coupon lookup uses `hasOwnProperty.call`.

**Hand-traced reported cases (read, not executed):**
- `[{19.9,3}]`: `Math.round(1990.0000000000002)=1990`, ×3 = 5970 → **59.7** ✓
- `[{5,1}]`, TENOFF: 500 − 1000 = −500 → floored → **0** ✓
- `[{100,1}]`, OFF20: 10000 × 80 / 100 = 8000 → **80** ✓
- `0.1 + 0.2`: 10 + 20 = 30 → **0.3** ✓
- `'toString'` / `'constructor'`: not own properties → ignored → **10** ✓
- `'NOPE'` / `undefined` / `null`: not own properties → ignored ✓

Edge checks: empty cart → 0; the existing tests `single item` and `empty cart` are unchanged in the test file (the diff only adds tests). `HALF` still works through the percent branch.

**Executed:** `npm test` → 7 tests, 7 pass, 0 fail (`node --test`).

**Regression test sensitivity (read, reasoned; not re-executed):** against the pre-fix code, the `quantity`, `TENOFF`, `OFF20`, `rounding` and `prototype` tests each fail on the values the bug report gives (19.9, −5, 20, 0.30000000000000004, NaN). I could not revert the file to re-run them, because `git diff`/`git stash` and file writes are refused in this read-only mode. The pre-fix failures come from the previous step's recorded evidence.

**Side effects:** `total` has no other callers in the repo (grep confirmed). The return type is still a number, and the API is still `module.exports = { total }`.

**Findings (all low, outcome pass, for the owner to decide):**
1. **Fractional quantities break the cents rule.** `[{price:0.99, qty:1.5}]` gives `99 × 1.5 = 148.5` cents → `1.485`, which is not 2 decimals. Only matters if qty can be fractional (e.g. weight-based items). Repro: call `total([{price:0.99,qty:1.5}])`.
2. **Invalid inputs still pass through.** A missing `qty` gives `NaN` and `Math.max(0, NaN)` returns `NaN`. A negative price can offset other lines. This was out of the reported scope, as the investigate step noted. Repro: `total([{price:10}])` → NaN; `total([{price:-5,qty:1},{price:10,qty:1}])` → 5.
3. **Sub-cent prices lose a cent.** `Math.round(1.005*100)` is 100, so `total([{price:1.005,qty:1}])` → 1.00 instead of 1.01. Only matters for prices that are not whole cents.
4. **Test gaps.** No test covers a partial TENOFF on a cart above 10 (e.g. 25 → 15), which would catch a sign or ordering error. No test covers percent rounding on odd cent amounts, HALF, or a mixed cart with a coupon. No test covers a fractional qty.

**Limits:** I could not revert the fix to watch the regression tests fail, could not run any ad-hoc input checks, and could not view `git diff`. The fractional-qty and sub-cent behaviour are from reading the code, not from execution.
