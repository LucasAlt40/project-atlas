The fix addresses all four reported symptoms, and `npm test` passes 7/7. I could not revert the fix to watch the regression tests fail, so that part is verified by reading only.

## Root cause

The original `total()` in `src/cart.js` had four separate defects, one per reported symptom:

1. **Quantity ignored:** the line total added `item.price` and never multiplied by `item.qty`. That gives 19.9 instead of 59.7 for 3 × 19.90.
2. **Percent coupon inverted:** OFF20 returned the discount amount (20) rather than the discounted total (80).
3. **No floor at zero:** a fixed coupon larger than the cart (TENOFF on 5) produced -5.
4. **No cent rounding:** floating-point sums leaked through, e.g. 0.1 + 0.2 = 0.30000000000000004.

A related defect: the coupon lookup used a plain property access, so a code such as `constructor` matched `Object.prototype` and produced NaN.

## Fix applied (src/cart.js:13-28)

- Line total is `item.price * item.qty` (line 16).
- Coupon lookup uses `Object.prototype.hasOwnProperty.call(COUPONS, couponCode)` (line 18), so inherited names like `constructor` and `__proto__` are ignored.
- Percent coupons compute `sum - (sum * value) / 100` (line 21). Fixed coupons compute `sum - value` (line 23).
- `Math.max(0, sum)` clamps the total at zero (line 26).
- `Math.round(sum * 100) / 100` rounds once, on the final total (line 27).
- The public API is unchanged: `module.exports = { total }` (line 30).

Regression tests in `test/cart.test.js`, lines 13-32, cover the quantity case (19.9 × 3 = 59.7), TENOFF floored at 0, OFF20 on 100 = 80, 0.1 + 0.2 = 0.3, and unknown coupons including `constructor` being ignored. The five original tests are still there.

## Validation evidence

- **Executed:** `npm test` → 7 tests, 7 pass, 0 fail. Includes all five regression tests and the two original tests.
- **Read:** the quantity fix at line 16 directly addresses the 19.9 vs 59.7 symptom. The percent and fixed branches at lines 20-24 match the spec. Clamp and rounding are at lines 26-27.

- **Not executed:** I could not revert the fix temporarily to confirm each new test fails without it. From reading, the quantity, TENOFF, OFF20, and rounding tests each fail against the original logic, and the `constructor` test fails against the original NaN behavior.

- Coupon lookup is now case-sensitive, so `tenoff` is ignored. The spec says unknown coupons are ignored, so this is consistent.
- Clamping at zero is applied after the coupon, and rounding is applied after clamping. The order is correct.

## Findings

1. **Medium, correctness (not in the bug report, outcome still pass).** Rounding uses `Math.round(sum * 100) / 100`. Binary floating point makes half-cent values round down. For example, `1.005 * 100` is `100.49999999999999`, so `total([{price:1.005, qty:1}])` should return 1.00 by this code, not the 1.01 a half-up rule gives. The reported symptoms are fixed, but the cent-rounding rule is not fully exact. Recommended repro: `total([{price:1.005,qty:1}])`, and `total([{price:2.675,qty:1}])`. The owner should decide whether to switch to an integer-cents or epsilon-based rounding, and whether to add a test. Reasoned from the code, not executed.
2. **Low, test gap.** No test covers a fixed coupon when the cart exceeds its value, e.g. `total([{price:25,qty:1}], 'TENOFF')` should be 15. The current TENOFF test only checks the floor case. The HALF coupon is also untested.
3. **Low, input validation.** Negative prices are silently masked by the zero clamp: `total([{price:-5,qty:1}])` returns 0. Missing or non-numeric price or qty returns NaN, which breaks the "always a number" requirement. Both are hardening beyond the reported bug.
