## Analysis and plan

### Goals

Add a standalone CommonJS `slugify(text, options)` utility and focused Node built-in tests without changing existing project files.

### Scope

In scope:

- Create `src/slugify.js`.
- Create `test/slugify.test.js`.
- Support lowercase conversion, diacritic removal, separator normalization, trimming, and `maxLength`.
- Throw `TypeError` when `text` is not a string.
- Export exactly `module.exports = { slugify }`.

Out of scope:

- Dependencies, package configuration changes, README changes, browser integration, or behavior for unspecified invalid `options.maxLength` values.

### Modules and dependencies

The project currently has one boundary:

- `src/`: production CommonJS utilities.
- `test/`: Node test-runner tests.
- `package.json`: declares `"type": "commonjs"` and runs `node --test`.

There are no source modules, test modules, or runtime dependencies yet. The implementation should therefore remain a pure function with no added abstraction or dependency.

### Architectural impact

The change is isolated and low-risk. It adds one stateless utility module with no side effects and one test module. The only contract boundary is the exported object:

```js
module.exports = { slugify };
```

Tests should consume that public export rather than internal helpers.

### Decisions the Developer must follow

- Use CommonJS syntax consistently with the package configuration.
- Normalize Unicode text to remove combining diacritics, then lowercase and replace every non-ASCII-alphanumeric run with one hyphen.
- Trim leading and trailing hyphens after normalization.
- Apply `maxLength` after slug construction:
  - If the full slug fits, return it.
  - Otherwise use the last hyphen that fits, preserving whole words.
  - If no hyphen permits a result within the limit, hard-cut the first word at `maxLength`.
  - Ensure the result never ends with a hyphen.
- Treat only the documented positive-integer `maxLength` contract as required; unspecified invalid option values do not need additional behavior.
- Do not modify `README.md`, `package.json`, or any other file.

### Files and contracts to change

- `src/slugify.js`
  - New public module.
  - Input: string plus optional options object.
  - Output: normalized slug string.
  - Error: `TypeError` for non-string text.
  - Export: `{ slugify }`.

- `test/slugify.test.js`
  - New tests using `node:test` and `node:assert`.
  - Cover the supplied examples plus representative edge cases: whitespace/punctuation collapsing, accents and diacritics, trimming, type errors, word-boundary truncation, hard truncation, and exact-length results.

No existing files require modification.

### Verification

Run:

```sh
npm test
```

The tests should verify the public CommonJS export and all stated rules, including:

- `Olá, Mundo!` → `ola-mundo`
- `Ação & Reação` → `acao-reacao`
- `maxLength: 9` → `hello-big`
- `maxLength: 8` → `hello`
- hard truncation of `supercalifragilistic` to `super`
- no leading/trailing hyphens
- `TypeError` for non-string input

The working tree is currently clean, and no implementation has been made in this analysis step.
