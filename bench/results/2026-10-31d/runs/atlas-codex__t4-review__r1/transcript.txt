Findings, ordered by severity:

1. **High — Security — incomplete HTML escaping**

   - File: `src/users.js:16-21`
   - Evidence: `String.replace('&', ...)`, `.replace('<', ...)`, and `.replace('>', ...)` replace only the first occurrence. For example, `userRow({name: '<img src=x> <b>x</b>'})` leaves later tags unescaped.
   - Why wrong: `userRow` inserts the result directly into HTML at `src/users.js:25`, allowing attacker-controlled markup and potentially XSS.
   - Recommendation: Escape all occurrences using global replacements or a properly tested HTML-escaping utility, including any characters required by the output context.

2. **Medium — Functional correctness — pagination is off by one**

   - File: `src/users.js:3-6`
   - Evidence: The documentation says page `1` is the first page, but `const start = page * size` makes page 1 begin at index `size`. A probe with four items and page 1/size 2 returned items 3–4.
   - Recommendation: Convert the one-based page number to a zero-based offset: `(page - 1) * size`, with validation for invalid page and size values if those can be externally supplied.

3. **Medium — Functional correctness — adulthood ignores month and day**

   - File: `src/users.js:9-13`
   - Evidence: The implementation compares only calendar years. Someone born on `2008-12-01` is reported as an adult on `2026-11-30`.
   - Recommendation: Compare the full birthday against `today`, for example by subtracting one from the year when the current month/day precedes the birth month/day, or by comparing normalized dates.
