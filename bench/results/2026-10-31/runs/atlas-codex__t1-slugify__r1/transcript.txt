## Plan: Add isolated CommonJS slugification utility

### Goals

- Add `slugify(text, options)` as a CommonJS utility.
- Normalize case and Unicode diacritics.
- Collapse non-alphanumeric runs into one hyphen and trim boundary hyphens.
- Enforce `options.maxLength` without splitting words where possible.
- Add focused tests using Node’s built-in `node:test` and `node:assert`.

### Scope

In scope:

- `src/slugify.js`
- `test/slugify.test.js`
- Input validation for non-string `text`.
- Unicode normalization and max-length behavior described by the task.

Out of scope:

- Changes to `package.json`, `README.md`, or other project files.
- New dependencies or abstractions.
- Browser/frontend integration.
- Defining behavior for invalid `options.maxLength` values outside the stated positive-integer contract.

### Modules and dependencies

- The project is a minimal CommonJS package (`"type": "commonjs"`).
- `src/slugify.js` will be a standalone module with no runtime dependencies.
- Its public contract will be exactly:

  ```js
  module.exports = { slugify };
  ```

- `test/slugify.test.js` will import the named export and use only `node:test` and `node:assert`.

### Design decisions

1. Convert text to lowercase.
2. Apply Unicode NFD normalization and remove combining marks, allowing examples such as `é → e`, `ç → c`, `ã → a`, and `ü → u`.
3. Replace each run matching `[^a-z0-9]+` with `-`.
4. Remove leading and trailing hyphens.
5. Apply `maxLength` after slug construction:
   - If the full slug fits, return it.
   - Otherwise, use the last hyphen whose position allows the result to fit.
   - If no complete word fits, hard-cut at `maxLength`.
   - Ensure the result does not end with a hyphen.
6. Throw `TypeError` when `text` is not a string.

### Files and contracts to change

- `src/slugify.js`
  - Define the `slugify` function.
  - Export only `{ slugify }`.
  - Preserve the stated input and truncation contract.

- `test/slugify.test.js`
  - Cover normalization, punctuation collapsing, trimming, empty/punctuation-only input, `TypeError`, word-boundary truncation, hard truncation, and exact-fit behavior.

### Architectural impact

This is a leaf utility with no dependencies on other project modules, so it introduces no coupling or boundary changes. The main maintainability concern is keeping normalization and truncation as clear sequential transformations rather than adding a generic text-processing abstraction the project does not need.

### Risks

- Unicode normalization removes combining marks but does not transliterate every non-Latin character into ASCII; the specified contract only requires the stated accent/diacritic behavior.
- Truncation must distinguish a valid word boundary from a hard cut, especially when the first word exceeds `maxLength`.
- Tests should avoid depending on filesystem-wide test discovery beyond the existing `node --test` script.

- Confirm the module loads through `require('./src/slugify')`.
- Verify all supplied examples and edge cases through `test/slugify.test.js`.
- Confirm only the two requested files are added or modified.
