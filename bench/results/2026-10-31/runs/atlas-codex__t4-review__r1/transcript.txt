Verdict: **fail**. `src/users.js` contains two correctness defects and one high-severity XSS vulnerability. No files were changed.

1. **High — Security:** incomplete HTML escaping  
   **File:** `src/users.js:18-20, 24-25`  
   `escapeHtml` replaces only the first occurrence of each character. A name such as `< > <img src=x onerror=alert(1)>` produces a live `<img>` element in `userRow`, enabling HTML/script injection.  
   **Recommendation:** escape all occurrences using global replacements or `replaceAll`; keep the value in a text-only DOM API where possible.

2. **Medium — Conventions:** `isAdult` ignores the birthday month and day  
   **File:** `src/users.js:11-12`  
   The implementation compares only calendar years, so someone born on December 1, 2008 is considered 18 on November 30, 2026.  
   **Recommendation:** subtract one when today is before the birthday this year, or compare dates against the calculated anniversary.

3. **Medium — Conventions:** pagination contradicts its documented one-based contract  
   **File:** `src/users.js:3-6`  
   The comment states that page 1 is the first page, but `start = page * size` makes page 1 return the second page.  
   **Recommendation:** calculate `start` as `(page - 1) * size` and validate positive integer page/size inputs.

Verification: `npm test` passed but discovered zero tests. The targeted read-only probes confirmed all three behaviors above.

Not reviewed: broader application integration, browser configuration, deployment behavior, and modules outside `src/users.js`.
