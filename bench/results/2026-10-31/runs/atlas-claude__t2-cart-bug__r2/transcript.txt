The root cause was four separate bugs in `total()` in `src/cart.js`, and I fixed all four. The project suite now passes 7 of 7, including 5 new regression tests that failed on the old code.

## Phase 1: evidence

Everything here came from reading the code and running `npm test` (`node --test`).

| Symptom | Cause | Evidence |
|---|---|---|
| 3 × 19.90 shows 19.9 | Quantity is never used. The loop added only `item.price`. | `src/cart.js:16` (original). Confirmed by the failing test: `19.9 !== 59.7`. |
| TENOFF on 5.00 shows −5 | The fixed discount is subtracted with no floor at zero. | `src/cart.js:23` (original). Confirmed: `-5 !== 0`. |
| OFF20 on 100 shows 20 | The percent branch computes the discount amount, not the amount to pay. It should be `sum × (100 − value) / 100`. | `src/cart.js:21` (original). Confirmed: `20 !== 80`. |
| Long decimals such as 0.30000000000000004 | No rounding to cents anywhere. | Confirmed: `0.30000000000000004 !== 0.3`. |
| Unknown coupons should be ignored (not reported, but required) | `COUPONS[couponCode]` also finds inherited keys such as `toString`. That gives a truthy non-coupon, and `sum - undefined` is NaN. | Confirmed: `NaN !== 10`. |

Root cause: confirmed. Each symptom maps to one line in the original `total()`.

## Phase 2: fix

**`src/cart.js`**
- Line 16: `sum += item.price * item.qty`.
- Coupon lookup now checks own properties only, using `Object.prototype.hasOwnProperty.call(COUPONS, couponCode)`. Unknown and inherited names are ignored.
- Percent coupons compute `sum * (100 - coupon.value) / 100`.
- The return value is `Math.max(0, Math.round(sum * 100) / 100)`. This rounds to cents and clamps at zero.
- The `module.exports = { total }` API is unchanged.

**`test/cart.test.js`**: five regression tests were added: quantity, fixed coupon floor, percent coupon, cent rounding, and unknown/inherited coupon names. The two existing tests are unchanged.

## Verification

- `npm test` before the fix: 2 passed, 5 failed, with the failures listed above.
- `npm test` after the fix: 7 passed, 0 failed.

## Residual risks

- **HALF coupon:** its results are unchanged. 50% off gives the same answer under the old and new formulas.
- **Rounding is applied once, to the final total.** Per-line rounding would be a different policy. I did not change it.
- **Half-cent floats:** a value like 1.005 is stored as slightly less than 1.005, so `Math.round` gives 1.00. Real prices in cents should not hit this, but a per-line policy would need an explicit decision.
- **Missing `qty`:** an item without `qty` gives NaN. The original code ignored `qty` entirely, so this is a new input-validation case. I did not add validation because the task did not ask for it.

## Verification report: cart total fix (`src/cart.js`)

**Limit:** Bash is disabled in this session, so I could not run `npm test` or the regression tests. Everything below comes from reading the code and tracing it by hand. The package.json test script is `node --test`, and `test/cart.test.js` contains 7 `test()` calls, which matches the handoff's "7/7" claim. I have not executed that claim.

### Root cause (from the investigation, checked against the code)
`total()` had five defects:
1. Quantity was ignored, so `19.9 × 3` came out as `19.9`.
2. The OFF20 branch returned the discount instead of the amount to pay.
3. The fixed-coupon branch had no floor, so `5 − 10` gave `-5`.
4. Float sums were never rounded to cents.
5. A bare `COUPONS[code]` lookup let inherited names such as `toString` through, giving `NaN`.

### Fix as applied (`src/cart.js:13-27`)
- Line 16 multiplies `price * qty`, which addresses defect 1.
- Line 18 uses `hasOwnProperty.call`, which addresses defect 5.
- Lines 20-24 apply the percent formula `sum * (100 − value) / 100` and the fixed subtraction.
- Line 26 returns `Math.max(0, Math.round(sum * 100) / 100)`, which addresses defects 3 and 4 by rounding once at the end and clamping at zero.
- The export `module.exports = { total }` (line 29) and the signature are unchanged.

I checked that the cause is removed rather than masked. The three coupon and line-math paths are each fixed at their source, not patched on the output. The one thing I could not confirm is whether any caller outside this repo depends on the old behavior. Inside the repo, a grep for `cart` found no other file that uses `total()`, so the only consumer is the test file.

### Do the regression tests catch the bugs? (reasoned, not executed)
I traced each new test against the pre-fix code:
- Quantity test (`19.9 × 3`): old code gives `19.9`, so it fails. Good.
- TENOFF on 5: old code gives `-5`, so it fails. Good.
- OFF20 on 100: old code gives `20`, so it fails. Good.
- Cent rounding (`0.1 + 0.2`): old code gives `0.30000000000000004`, so it fails. Good.
- `toString`: old code gives `5 − undefined = NaN`, so it fails. Good.

The handoff says 5 of these failed before the fix. My trace agrees, but I did not observe it.

### Side effects and regression risks

**Medium: items without `qty` now return `NaN`.** `src/cart.js:16` computes `item.price * undefined`, which is `NaN`. The clamp then leaves it as `NaN` (`Math.max(0, NaN)` is `NaN`). The old code returned `10` for `[{ price: 10 }]`, so any caller that omits qty has regressed. The JSDoc says qty is required, so this is a contract issue, not a bug inside the fixed paths. Still, nothing guards it. Repro: `total([{ price: 10 }])`. Expected by old behavior: `10`. Now: `NaN`.

**Low: half-cent values round down because of float error.** `src/cart.js:26` does `Math.round(sum * 100)`. In JS, `1.005 * 100` is `100.49999999999999`, so `total([{ price: 1.005, qty: 1 }])` returns `1` rather than `1.01`. No test covers this. Whether it counts as a bug depends on the store's rounding rule, which the task does not specify.

**Low: negative quantity is silently accepted.** `total([{ price: 10, qty: -1 }])` gives `-10`, which the clamp turns into `0`. A bad quantity can therefore hide itself as an empty cart.

**Low: a non-finite price is not guarded.** A string or `NaN` price flows through the same arithmetic without any check.

### Test coverage gaps (`test/cart.test.js`)
- Nothing covers `HALF`, the third configured coupon.
- Nothing shows that TENOFF subtracts correctly above zero, for example `25 → 15`. The only TENOFF test hits the floor.
- Nothing combines quantity with a coupon, for example `[{ price: 10, qty: 2 }]` with OFF20 should give `16`.
- Nothing checks the missing-qty case, so the `NaN` regression is untested.
- Nothing checks that coupon codes are case-sensitive, for example `tenoff`, which the code currently ignores.
- Nothing checks percent rounding on a non-terminating value, for example `[{ price: 1.01, qty: 1 }]` with OFF20 should give `0.81`.
- Nothing checks the half-cent case above.

### Verdict
The fix removes the root causes for all five reported symptoms, the new tests would have failed on the old code, and the API is unchanged. I did not execute anything, so the passing run is unconfirmed. The medium `NaN` regression for items without `qty` is a real side effect and should be fixed or documented before release.
