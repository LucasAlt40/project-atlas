2. Normalisation runs in this order: `toLowerCase`, then `NFD`, then strip combining marks, then collapse `[^a-z0-9]+` to `-`, then trim dashes. For `' Olá, Mundo! '`: `ola-mundo`. For `'Ação & Reação'`: `acao-reacao`. Both match the spec.
3. maxLength (lines 20–26). Let `slug` be the normalised string.
   - If it fits, return it whole.
   - Otherwise search `slice(0, max+1)` for the last `-`. That window covers indices 0..max, so a dash at index `max` (end of a fitting word) is accepted and a dash at `max+1` is rejected.
   - Traces: `'hello big world'`, max 9 → window `hello-big-`, last dash at 9, result `hello-big`. Max 8 → window `hello-big`, last dash at 5, result `hello`. `'supercalifragilistic'`, max 5 → no dash in `super` + one char, hard cut `super`. All match the spec.

### Invariants I checked by reasoning

- **Length never exceeds max.** Cut results are at most `max`, and hard cuts are `slice(0, max)`.
- **No trailing dash.** The slug has no doubled dashes and no leading dash. So for a cut at `lastDash`, the character before it is a letter or digit. A hard cut never ends in `-`, because if index `max-1` were a dash the window would have found it.
- **Never empty when there is a dash cut.** Index 0 is never a dash, so `lastDash > 0` and the prefix is non-empty.
- **Surrogate pairs.** The slug is ASCII-only before any slicing, so `slice` is safe.

### Findings, by severity

1. **Low — the TypeError test does not prove the guard exists.** `test/slugify.test.js:59-63`. `slugify(null)`, `slugify(42)` and `slugify(undefined)` would throw a TypeError from `.toLowerCase()` on line 14 even without the explicit check on line 4. The test passes either way. It would miss a regression where the guard is removed and an object with a `toLowerCase` method slips through. *Recommendation:* assert the message, e.g. `assert.throws(() => slugify(42), { name: 'TypeError', message: /must be a string/ })`. *Repro idea:* remove lines 4–6 and run `slugify({ toLowerCase: () => 'x' })`.
