## Verdict: fail

`src/users.js` has two defects that must be fixed before acceptance: the HTML escaper only escapes the first occurrence of each character, which is an XSS risk, and the pagination offset contradicts its own docstring. The age check is also wrong near birthdays. All findings below rest on reading alone; I did not execute the code.

## Findings (most severe first)

**1. High · Security · `src/users.js:16-21` (`escapeHtml`)**
- **Why it's wrong:** `String.prototype.replace` with a string pattern replaces only the first match. `<`, `>` and `&` are escaped only once per string. Any later `<` or `>` passes through raw, so the escaper does not make text safe for HTML, although its docstring says it does.
- **Example (by reasoning):** `escapeHtml("<script>alert(1)</script>")` yields `&lt;script&gt;alert(1)</script>`. The closing tag's `<` is still raw, and `userRow` interpolates the result straight into a `<td>`, so a user name containing a second tag can inject markup.
- **Recommendation:** use global regexes, e.g. `.replace(/&/g, '&amp;').replace(/</g, '&lt;').replace(/>/g, '&gt;')`. Keep `&` first. Consider also escaping `"` and `'` (`&quot;`, `&#39;`) so the helper stays safe if it is ever used in an attribute.

**2. High · Correctness · `src/users.js:3-7` (`paginate`)**
- **Why it's wrong:** the docstring says page 1 is the first page, but `start = page * size` makes page 1 skip the first `size` items. Page 1 returns items `size..2*size-1`, and the first page is unreachable through the documented API. Page 0 returns the first page, which contradicts the docstring.
- **Evidence:** line 3 (docstring) vs line 5 (`const start = page * size;`).
- **Recommendation:** `const start = (page - 1) * size;`, and reject `page < 1` or non-integer `size` (throw a `RangeError`, or clamp deliberately). Without that check, a negative page gives a negative `start`, which `slice` treats as an index from the end and returns the wrong rows silently.

**3. Medium · Correctness · `src/users.js:9-13` (`isAdult`)**
- **Why it's wrong:** the age is the difference of calendar years only. Someone born 2008-12-31 is treated as 18 on 2026-01-01 when they are actually 17. The check ignores month and day, so it is off by one for part of every year.
- **Recommendation:** compute the year difference, then subtract one if the birthday has not happened yet on `today`: compare `today.getMonth()` and `today.getDate()` with `birthDate`'s values, or compute `age` from `today` and `birthDate` as full years.

**4. Low · Maintainability / Testing · whole file**
- **Why it matters:** `package.json:1` declares `"test": "node --test"`, but there is no test file in the repo (the glob returned only `src/users.js`, `package.json`, `README.md`). None of the defects above would be caught.
- **Recommendation:** add `test/users.test.js` covering: page 1 returns the first `size` items; `escapeHtml` escapes every occurrence; `isAdult` on the day before and the day of an 18th birthday.

**5. Low · Security (latent) · `src/users.js:16-21`**
- **Why it matters:** the helper is documented as "safe to put inside HTML", but it does not escape quotes. That is only safe in text content. Any future use inside an attribute value would be injectable. There is no attribute usage in this file today.
- **Recommendation:** fix together with finding 1 (escape `"` and `'`), or narrow the docstring to "safe as HTML text content".
