### Architectural impact
This is a leaf module with no imports and no coupling to other code. Its only dependency is the injected `now()` function. The project has no `src/` directory, so creating `src/` is the only structural change.

### Design decisions for the Developer
1. **Validation runs before any clock read.** `createLimiter` throws `RangeError` for `capacity` unless `Number.isInteger(c) && c > 0`. It throws `RangeError` for `refillPerSecond` unless `Number.isFinite(r) && r > 0`. `Number.isInteger` and `Number.isFinite` already reject strings, `NaN` and `Infinity`. `options` defaults to `{}`, so `createLimiter()` throws `RangeError` through the missing `capacity`. For `n`, `tryRemove` and `msUntil` use one shared check: `Number.isInteger(n) && n > 0`, else `RangeError`. Then `n > capacity` also throws `RangeError`.
2. **State.** Keep `tokens` (a float, starting at `capacity`), `last` (the reference time, set at creation) and the `now` function. Store `refillPerSecond` as given and divide by 1000 at the point of use.
3. **Refill.** `t = now()`. If `t > last`, set `tokens = min(capacity, tokens + (t - last) * refillPerSecond / 1000)`. Always set `last = t`. If the clock went backwards, `last` moves back and no tokens change, as the spec requires.
4. **Float tolerance.** Use `EPS = 1e-9` tokens. `tryRemove` compares `tokens + EPS >= n`. `available()` returns `Math.floor(tokens + EPS)`. `msUntil` returns 0 when `n - tokens <= EPS`, otherwise `Math.ceil((n - tokens) * 1000 / refillPerSecond - EPS)`. This prevents results like `2.9999999999999996` reporting 2 tokens, or `msUntil` returning 1 ms too many. After a successful removal, clamp with `Math.max(0, tokens - n)`.
5. **`reset()`** sets `tokens = capacity` and `last = now()`.
6. **Clock argument.** Default to `() => Date.now()`, which is not a bare reference. If `options.now` is given and is not a function, throw `TypeError`. The spec does not cover this case, so this is my choice.
7. **Non-finite clock readings.** In `refill`, if `t` is not a finite number, throw `TypeError`. Without this, a `NaN` from `now()` would poison `tokens` and `last`. Every later call would then return `NaN` or `false`. This guard is also beyond the spec, and I am proposing it.
