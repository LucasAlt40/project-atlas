**Architectural impact**
- This is a leaf module with no dependencies. Nothing else imports it yet, so it has no effect on other code.
- Time comes only through the injected `now` function (default `Date.now`). This keeps the module deterministic under test and is the only external dependency.
- State is O(1): `capacity`, `refillPerSecond`, `tokens` (float), and `last` (the reference timestamp in ms).

**Decisions the Developer must follow**
1. **Validation at creation.** `createLimiter(options = {})` must throw `RangeError` (not `TypeError`) when:
   - `capacity` is not an integer greater than 0, or
   - `refillPerSecond` is not a finite number greater than 0.

   Missing values count as invalid. Default `now` to `Date.now` when it is absent.
2. **Initial state.** `tokens = capacity` and `last = now()`.
3. **Single refill routine, used by every method.** It works like this:
   - `t = now()`.
   - If `t < last`, set `last = t` and add nothing.
   - Otherwise set `tokens = min(capacity, tokens + (t - last) * refillPerSecond / 1000)` and set `last = t`.
   - Do not round the stored `tokens`. Only `available()` floors it.
4. **Count validation** (for `tryRemove` and `msUntil`). `n` must be an integer greater than 0, or `RangeError`. If `n > capacity`, throw `RangeError` as well. The default `n` is 1.
5. **`tryRemove(n)`.** Refill, then if `tokens >= n` subtract `n` and return `true`; otherwise return `false` and change nothing.
6. **`available()`.** Refill, then return `Math.floor(tokens)`.
7. **`msUntil(n)`.** Refill, then return `0` if `tokens >= n`; otherwise return `Math.ceil((n - tokens) * 1000 / refillPerSecond)`.
8. **`reset()`.** Refill (to update the reference time), then set `tokens = capacity`.
9. Keep the module small: no classes, no helpers beyond what is needed, and the same comment density as a plain utility file.

**Files and contracts**
- `src/limiter.js` (new): exports `{ createLimiter }`. The returned object has `tryRemove`, `available`, `msUntil`, and `reset`.
- `test/limiter.test.js` (new): picked up by the existing `node --test` script, since Node's default patterns include `test/**/*.js`.

**Test plan** (use an injected fake clock; choose rates such as 1, 2, 0.5, and 4 so the floating-point arithmetic is exact)

- Starts full: `available()` equals `capacity`.
- `tryRemove` returns `true` when there are enough tokens, and `false` without removing anything when there are not.
- Refill with fractional rates: at 0.5/s, 1000 ms adds 0.5 tokens, so `available()` floors correctly.
- The bucket never exceeds `capacity` after a long idle period.
- `msUntil` returns 0 when tokens are available. Example: capacity 2, rate 0.5/s, empty bucket, `msUntil(1)` is 2000. After 500 ms it is 1500. Confirm rounding up.
- `n` validation for `tryRemove` and `msUntil` (0, -1, 1.5, and `capacity + 1`) throws `RangeError`.
- `reset()` makes the bucket full.
- Clock going backwards: move `now` back 5000 ms. No tokens are added or lost, and refill continues from the new reference.
- Default clock: `createLimiter({ capacity, refillPerSecond })` without `now` works (for example, `available()` returns `capacity`), without depending on real elapsed time.

**Risks**
- Floating-point error could make `msUntil` one millisecond off in rare cases. The tests avoid this by using exact rates. Accepted.
- `Date.now` can jump backwards, which the clock rule covers. The module is not monotonic-clock safe across processes, which is out of scope.

**Design choices**
- All four methods go through one `refill()`. It adds tokens only when the clock moves forward, caps them at capacity, and always sets the reference time to the latest reading. So a backwards clock adds nothing and loses nothing.
- `available()` is the only place that floors. `msUntil()` rounds up.
- A missing options object is treated as `{}`, so it fails the capacity check with a `RangeError`.
- `reset()` also re-reads the clock, so the next refill counts from now.
- `n` must be a positive integer and cannot exceed capacity, for both `tryRemove` and `msUntil`.

**What the tests cover**
- Creation rejects bad or missing options, and accepts fractional `refillPerSecond`.
- The bucket starts full, `tryRemove` is all-or-nothing, and `n` validation throws.
- Refill over time, the capacity cap, flooring, and fractional rates.
- `msUntil` returns 0 when tokens are available, rounds up, and counts pending fractional tokens.
- Backwards-clock behaviour and `reset()`.
