## Plan: token bucket limiter (`src/limiter.js` + `test/limiter.test.js`)

**Goal:** a dependency-free CommonJS token bucket, `module.exports = { createLimiter }`, with an injectable clock, tested with `node:test` and `node:assert`.

**Scope**
- In: `src/limiter.js` (new), `test/limiter.test.js` (new).
- Out: any other file, including `package.json`, README, and any `index.js`. `npm test` already runs `node --test`, which picks up `test/*.test.js`, so no config change is needed.

**Architectural impact:** none. This is a leaf module with no dependencies and no coupling to other modules. The only external dependency is the injectable `now()`, which keeps time out of the logic and makes tests deterministic.

**Decisions the Developer must follow**
1. **State:** `tokens` (float), `last` (ms reference time), `capacity`, `refillPerSecond`, `now`. Tokens start at `capacity`; `last = now()` at construction.
2. **Validation of options** (in `createLimiter`, default `options = {}` so a missing object yields RangeError, not a destructuring TypeError):
   - `capacity`: `Number.isInteger(c) && c > 0`, else RangeError.
   - `refillPerSecond`: `typeof r === 'number' && Number.isFinite(r) && r > 0`, else RangeError.
   - `now`: if provided and not a function, throw TypeError. This is outside the spec's enumerated errors, so flag it in the final report.
3. **Validation of `n`** (`tryRemove` and `msUntil`): `Number.isInteger(n) && n > 0`, else RangeError; `n > capacity` also RangeError. Validate **before** refilling so an invalid call has no side effects.
4. **Refill** (private helper): `elapsed = now() - last`. If `elapsed < 0` (clock went backwards), add nothing and set `last = t` (the earlier time becomes the reference). Otherwise `tokens = min(capacity, tokens + elapsed * refillPerSecond / 1000)` and `last = t`.
5. **Float tolerance:** use a named constant `EPSILON = 1e-9` in comparisons, so that `0.1`-style accumulation does not produce `2.9999999999` and wrongly floor to 2 or reject a request. Concretely: `available() = Math.floor(tokens + EPSILON)`; `tryRemove` succeeds when `tokens + EPSILON >= n`, then sets `tokens = Math.max(0, tokens - n)`; `msUntil` returns 0 when `n - tokens <= EPSILON`, otherwise `Math.ceil((n - tokens) * 1000 / refillPerSecond)`. Keeping `msUntil` and `tryRemove` on the same threshold is what makes "wait `msUntil` ms, then `tryRemove` succeeds" hold.
6. **`reset()`:** `tokens = capacity`, `last = now()`.
7. **Style:** match the repo's plain CommonJS. Use a single `'use strict'`-free style unless the Developer prefers otherwise; no classes required, a closure returning the object is enough.

**Files and contracts**
- `src/limiter.js`: `createLimiter({ capacity, refillPerSecond, now = Date.now })` → `{ tryRemove(n = 1), available(), msUntil(n = 1), reset() }`. `module.exports = { createLimiter };`
- `test/limiter.test.js`: uses `node:test` (`test`, `describe`/`it` optional) and `node:assert/strict`. Injected clock is a mutable `let t = 0; const now = () => t;`.

**Test coverage to write**
- Starts full: `available() === capacity`; `tryRemove` consumes, then fails on empty, returns `false` and removes nothing.
- Fractional refill: `refillPerSecond: 0.5` → one token per 2000 ms; `available()` floors partial tokens (e.g. at 1999 ms still 0).
- Cap: after a long idle period, `available() === capacity`, not more.
- `msUntil`: 0 when available; rounds up (e.g. `refillPerSecond: 3`, deficit 1 → `ceil(333.33) = 334`); consistency check: after waiting `msUntil(n)` ms, `tryRemove(n)` succeeds.
- Float tolerance: a case like `refillPerSecond: 0.1` over 10 000 ms yields exactly 1 token.
- `reset()`: refills to capacity and resets the reference time.
- Clock backwards: consume at t=1000, move to t=500 (no tokens added), then to t=1000 + 500 ms (only time since 500 counts). Also confirm no tokens are lost when the clock goes back.
- Invalid options (table-driven, `assert.throws(fn, RangeError)`): missing, `0`, negative, `NaN`, `Infinity`, `'5'`, capacity `1.5`; refill `0`, `-1`, `NaN`, `Infinity`.
- Invalid `n` for `tryRemove` and `msUntil`: `0`, `-1`, `1.5`, `n > capacity`, and default `n = 1` works.

**Verification:** run `npm test` (the project's own command, from the worktree) and confirm all tests pass. Nothing requires network or writes outside the worktree.

**Risks**

- `now` returning non-numbers (e.g. `NaN`) would poison the state; the spec does not cover this. Recommend leaving it unvalidated beyond the function check, to avoid overreach.
- Scope creep (queues, async waiting, per-key buckets): out of scope, and should be rejected at review.
