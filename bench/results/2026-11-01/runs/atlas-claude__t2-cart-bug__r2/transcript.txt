**Root cause: confirmed.** The bug is in `total()` in `src/cart.js`. It has five defects, and I reproduced each one by running the test suite before changing the code:

1. **Quantity ignored** (`src/cart.js:16`): the loop summed `item.price` and never used `item.qty`. 3 × 19.90 returned 19.9.
2. **Percent coupon computed the discount, not the total** (`:21`): `sum * value / 100` returned 20% of the cart. 100 with OFF20 returned 20.
3. **No floor at zero** (`:23`): the fixed coupon subtracted with no clamp. 5.00 with TENOFF returned −5.
4. **No rounding** (`:26`): the raw float was returned. 0.1 + 0.2 returned 0.30000000000000004.
5. **Unknown coupon names matched inherited properties** (`:18`): `COUPONS['toString']` is a truthy inherited function, so the code went down the fixed-coupon branch and returned NaN. This breaks "unknown coupons are ignored." It was not in the customer report, but it is the same code path and the same requirement.

**Fix:** I made a minimal change to `total()`. It multiplies price by qty, subtracts the percent discount, clamps the result to ≥ 0, rounds to cents, and checks that the coupon key is an own property. The API `module.exports = { total }` is unchanged, and `COUPONS` is unchanged.

**Regression tests:** I added five tests to `test/cart.test.js`, one per defect. Before the fix, five failed and the two existing tests passed. The failures were `19.9 !== 59.7`, `20 !== 80`, `-5 !== 0`, `0.30000000000000004 !== 0.3`, and `NaN !== 10`.

**Verification (run in the worktree):** `npm test` now prints `tests 7, pass 7, fail 0`.

**Files changed:**
- `src/cart.js`
- `test/cart.test.js`

**Residual risks:**
- Rounding happens only once, on the final total, not per line. This matches the spec for totals, but if the business needs per-line rounding, that changes the results.
- Inputs are not validated. A missing `qty` gives NaN, and negative prices or quantities are not rejected. The task did not ask for this, so I left it alone.
- `Object.hasOwn` needs Node 16.9 or later. The project uses `node --test`, which already needs a recent Node, so this should be fine. I did not check the exact Node version.
- The `Number.EPSILON` rounding trick is a common approach. It is not exact for every float, but it handles the values in the report and the tests.

**Verdict: pass.** The fix is in place, the suite passes, and the fix addresses the causes behind all four customer reports. Nothing was modified.

**Root cause (from the investigation, confirmed by reading the code):** `total()` in `src/cart.js` had five defects:
1. It summed `item.price` and ignored `qty`, so 3 × 19.90 gave 19.9.
2. A percent coupon returned the discount amount instead of subtracting it, so OFF20 on 100 gave 20.
3. A fixed coupon had no lower bound, so TENOFF on 5.00 gave -5.
4. The result was returned as a raw float, so 0.1 + 0.2 gave 0.30000000000000004.
5. `COUPONS[couponCode]` matched inherited `Object.prototype` members, so `toString` produced NaN.

**Fix applied (committed in HEAD `49c3a6a`, working tree clean):** `src/cart.js:16` multiplies price by qty. `src/cart.js:18` only looks up own properties via `Object.hasOwn`. `src/cart.js:21` subtracts the percent discount. `src/cart.js:26` clamps at 0. `src/cart.js:27` rounds to 2 decimals. The export is still `module.exports = { total }`. The regression tests are in `test/cart.test.js:13-33`.

**Validation evidence:**
- **Executed:** `npm test` ran `node --test`: 7 tests, 7 pass, 0 fail.
- **Read:** each reported bug maps to one test. Quantity is `test/cart.test.js:14`, OFF20 is `:18`, TENOFF floor is `:22`, cent rounding is `:26`, and inherited and unknown coupons are `:30-32`.
- **Read:** the regression tests would fail on the pre-fix code. The pre-fix code gives 19.9, 20, -5, 0.30000000000000004 and NaN for those inputs, so each assertion would fail. This is reasoned from the diff, not re-run against the base commit. I could not check out the old code in this read-only mode.
- **Read:** the only caller of `total` in the repo is the test file. No other code depends on the changed behaviour.
- **Read:** `package.json` has no `engines` field. `node --test` needs Node 18 or later, and `Object.hasOwn` is available from Node 16.9, so the runtime requirement is covered.

**Findings (low severity, outcome still pass):**
- **Low, rounding:** `Math.round((sum + Number.EPSILON) * 100) / 100` only corrects half-cent cases for small sums. Adding `Number.EPSILON` is smaller than the float spacing for totals of about 2 or more, so for larger values a true half-cent may round down. Example: a total near 1000.005 may come out as 1000.00 rather than 1000.01. I did not execute this. A scale-safe approach would be a tiny offset relative to the value, or a decimal-based calculation. Customer data probably only has two-decimal prices, but the decision belongs to the owner.
- **Low, validation:** an item with a missing `qty` makes `sum` NaN, and `Math.max(0, NaN)` returns NaN, so the result is not a valid number. The bug report does not mention it. Negative quantities are silently clamped to 0 rather than rejected.

**What I could not verify:**
- I could not re-run the regression tests against the pre-fix commit (read-only mode).
- I could not execute ad-hoc probes such as half-cent or large-sum rounding, or HALF coupons. The only permitted command is the project test command.
- The test suite has no case for HALF, large totals, or half-cent values, so those paths are not covered.
