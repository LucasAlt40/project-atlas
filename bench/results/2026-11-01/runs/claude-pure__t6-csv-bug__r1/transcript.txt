I rewrote the parser in `src/csv.js` and added regression tests in `test/csv.test.js`, but I could not run the test suite. Every shell command I tried was held for approval, so the new tests are unverified. I checked the parser against each test case by hand. Please run `node --test` to confirm.

**Root causes in the original `parseCsv`:**
- **Quoted commas and line breaks:** it split on every `,` and `\n` without tracking whether it was inside quotes. That caused both the "Lisbon, Portugal" split and the multi-line field being cut into two rows.
- **Doubled quotes:** it stripped the outer quotes but never turned `""` into `"`.
- **Trailing newline:** `text.split('\n')` produced a final empty line, which became an extra row.
- **CRLF:** it split only on `\n`, so the `\r` stayed at the end of each row's last field.
- **Unclosed quote:** there was no check, so malformed input was accepted silently.

**The fix:** `parseCsv` is now a single character-by-character pass with an in-quotes state. Quotes open a field only at its start, and `""` inside quotes becomes `"`. Both `\n` and `\r\n` end a row, and a row is pushed at end of input only if it has content. An unclosed quote throws `SyntaxError`. `module.exports = { parseCsv }` is unchanged.

**Tests added:** comma inside quotes (the Lisbon case), doubled quotes, a line break inside a quoted field, a trailing newline adding no row, CRLF endings, empty fields kept as `""`, empty input giving `[]`, and an unclosed quote throwing. The two existing tests are untouched.

**Choices to check:**
- A blank line in the middle of the input (for example `a\n\nb`) still produces a row with one empty field, `[""]`, which matches the old behavior.
- A bare `\r` that is not followed by `\n` is kept as content. Only CRLF and LF end a row.
