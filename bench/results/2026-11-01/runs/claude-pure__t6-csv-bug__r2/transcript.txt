I rewrote `parseCsv` in `src/csv.js` and added regression tests, but I could not run the test suite. Bash commands were refused approval in this session, including `node --test`, so the new tests are checked by tracing the code by hand, not by execution.

**Root causes.** The old parser split the text on every `\n`, then on every `,`, and removed quotes with `startsWith`/`endsWith`. It had no notion of quoted state, so each reported bug follows from that:
- Commas inside quotes split fields ("Lisbon, Portugal").
- `""` was never unescaped.
- A trailing newline produced an extra row with one empty field.
- `\r\n` left a `\r` on the last field of each row.
- A line break inside quotes ended the row.

**The fix.** `parseCsv` is now a single-pass state machine:
- A quote at the start of a field opens a quoted field. Inside it, commas and line breaks are data, and `""` becomes `"`.
- An unclosed quote throws `SyntaxError`.
- `,` ends a field. `\n` or `\r\n` ends a record.
- At end of input, a record is added only if it has content, so a trailing newline adds no row and empty input gives `[]`.
- `module.exports = { parseCsv }` is unchanged.

**Choices I made where the request was silent:**
- A bare `\r` outside quotes is treated as data, not a line break. Only `\r\n` and `\n` end a record.
- A quote in the middle of an unquoted field, such as `ab"c"`, is kept as a literal character, as the old parser did. Text after a closing quote is appended to the field, such as `"a"b` giving `ab`.
- A blank line in the middle of a file becomes a row with one empty field.

**Tests.** I added tests to `test/csv.test.js` for each reported bug and for empty input, empty fields, and the unclosed-quote error. The three original tests are unchanged. Tracing each test through the new code gives the expected output.

To confirm, run `node --test` in the project root. I did not commit anything.
