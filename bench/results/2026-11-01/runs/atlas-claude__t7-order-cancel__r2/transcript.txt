## Plan: order cancellation

**Goals.** Add `orders.cancel(orderId, reason)` so a placed order can be cancelled. Stock is restored, the order records `status: 'cancelled'` and its reason, one `order.cancelled` event is emitted, and reports stop counting cancelled orders. Existing behaviour and the 3 current tests stay unchanged.

**Out of scope.** Partial cancellation, refunds or payments, a cancel-after-fulfilment rule, un-cancel, and changes to `events.js` (the bus already supports what is needed).

### Architecture and dependencies

- `src/shop.js` wires `bus`, `inventory`, `orders` and `reports`. `orders` depends on `inventory` and `bus`. `reports` depends only on `orders.all()`. Cancellation adds no new dependency edges.
- The only new cross-module contract is inventory gaining a way to put stock back. `inventory.js` currently exposes `quantity` and `take` only.
- The status string `'cancelled'` becomes a value that `reports.js` reads. That coupling is small and matches the project's existing string-status style (`'placed'`), so I'm not introducing a constants module.

### Decisions for the Developer

1. **Inventory restock method.** Add `inventory.restore(sku, qty)` to `src/inventory.js`. It adds `qty` to `stock.get(sku) ?? 0`, mirroring `take`. Do not reuse `take` with a negative quantity.
2. **Validation order in `cancel`.** Validate arguments first, then look up the order, then check the status. The sequence is:
   1. `reason` is not a string, or is empty after `trim()`, throws `TypeError`.
   2. Unknown `orderId` throws `Error('order … not found')`.
   3. Already cancelled throws `Error('order … already cancelled')`.
   
   Each failure happens before any mutation, so nothing changes on error.
3. **"Non-empty" means non-blank.** Whitespace-only reasons are rejected. The spec says "non-empty", and treating `'   '` as a real reason would be a worse outcome.
4. **Order state.** Set `order.status = 'cancelled'` and `order.reason = reason` on the stored record. Placed orders keep no `reason` field. `total` and `items` are not changed, so history stays intact.
5. **Restock source.** Restore from the stored `order.items`, which are copies made at placement time, so the caller cannot tamper with them.
6. **Event.** Emit `bus.emit('order.cancelled', { orderId, reason })` exactly once, after the state change. The bus is synchronous, so a throwing subscriber would propagate; the existing `place` has the same property and I'm not changing it.
7. **Return value.** Return a copy of the cancelled order, in the same shape `get()` returns.
8. **Reports.** Filter `o.status !== 'cancelled'` inside `revenue()` and `unitsSold()` in `src/reports.js`. Keep `orders.all()` returning everything, since the order history must remain queryable.

### Files to change

- `src/inventory.js`: add `restore(sku, qty)`.
- `src/orders.js`: add `cancel(orderId, reason)`.
- `src/reports.js`: exclude cancelled orders in `revenue` and `unitsSold`.
- `test/shop.test.js`: append tests. One file is kept to match the current layout.

### Test plan (added to `test/shop.test.js`, reusing the `setup()` helper)

### Risks

- **Event subscriber failure after mutation.** If an `order.cancelled` handler throws, the order is already cancelled and stock restored. This matches `place`; a transactional bus is out of scope.
- **Inventory of unknown SKUs.** `restore` on a SKU absent from initial stock creates it. That is acceptable, but worth noting.
- **Status drift.** `reports.js` now depends on the literal `'cancelled'`. A typo would silently double count, so the test for reports guards this.
