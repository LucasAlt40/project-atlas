## Plan: order cancellation

**Size: moderate**

### Goals
- `orders.cancel(orderId, reason)` returns the cancelled order, restocks its items, sets `status: 'cancelled'` with the `reason`, and emits one `order.cancelled` event with `{ orderId, reason }`.
- Error behaviour is as specified in the task. Validation runs before any state change.
- `reports.revenue()` and `reports.unitsSold(sku)` ignore cancelled orders.
- Existing behaviour and the existing tests in `test/shop.test.js` stay unchanged.

### Out of scope
- Refunds or payment handling. Prices and totals on the order record stay as they are.
- Cancelling orders from other statuses. Only `placed` exists today, and anything that is not `cancelled` is treated as cancellable.
- Changing the event bus, `shop.js` wiring, or the `place` / `get` / `all` return shapes.
- Coercing `orderId` types. The Map uses strict equality, as it does today.

### Modules and dependencies
- `src/orders.js` (`createOrders`) already receives `inventory` and `bus`, so `cancel` needs no new dependencies.
- `src/inventory.js` (`createInventory`) has no way to add stock back. Orders must not write to the stock Map directly, so inventory gets the new method.
- `src/reports.js` (`createReports`) depends only on `orders.all()`. Filtering there keeps all sales logic in one place.
- `src/shop.js` needs no change. Orders, inventory, bus and reports are already wired.

### Decisions for the Developer
1. **Inventory restock:** add `give(sku, qty)` to `createInventory`, next to `take`. It sets `stock.get(sku) ?? 0` plus `qty`.
2. **Validation order in `cancel`:** check the reason first (`TypeError`), then look up the order (`Error` with "not found"), then check `status === 'cancelled'` (`Error` with "already cancelled"). Only after all checks pass do anything else. The spec does not give the order, so this is my choice; a call with both a bad reason and a missing order throws the `TypeError`.
3. **"Non-empty" reason:** reject non-strings and strings where `reason.trim() === ''`. Whitespace-only is treated as empty. This is also my choice, and the Developer should follow it unless the user says otherwise.
4. **Internal record:** `cancel` works on the stored record in the `orders` Map, not on the copy returned by `get`. It then sets `status` and `reason` on that record, restocks each item with `inventory.give(sku, qty)`, emits `order.cancelled`, and returns a copy in the same shape as `place` (`{ ...order, items: copies }`).
5. **Ordering inside `cancel`:** restock all items, then set status, then emit. This matches the existing `place`, which takes stock, records the order, then emits.
6. **Reports:** `revenue()` and `unitsSold(sku)` filter with `o.status !== 'cancelled'` before summing. They do not compare with `'placed'`, so any future status keeps counting as sold until it is explicitly excluded.
7. **Tests:** add them to `test/shop.test.js`, which already holds all the tests, using the existing `setup()` helper and `node:test` style.

### Files and contracts to change
- `src/inventory.js`: new `give(sku, qty)`. Existing `quantity` and `take` are unchanged.
- `src/orders.js`: new `cancel(orderId, reason)`. The returned order gains `reason` only when cancelled. `place`, `get`, and `all` return the same shapes as before.
- `src/reports.js`: `revenue` and `unitsSold` each add a filter on cancelled orders.
- `test/shop.test.js`: new tests.
- `README.md`: optional one-line mention of `orders.cancel`. Not required.

Event contract: `order.cancelled` with payload `{ orderId, reason }`, emitted once per successful cancel and never on failure.

### Tests to add
- Cancelling a placed order restores stock (`inventory.quantity` back to the original value for each SKU).
- The returned order and `orders.get(id)` both have `status: 'cancelled'` and the `reason`.
- `order.cancelled` is emitted exactly once with `{ orderId, reason }`, and no `order.placed` is emitted.
- A missing id throws an `Error` whose message contains "not found", and no stock or event changes.
- Cancelling twice throws an `Error` whose message contains "already cancelled", and stock and events stay the same after the failed second call.
- `reason` as `''`, `'   '`, `undefined`, or `42` throws a `TypeError`, and nothing changes.
- After cancelling one of two orders, `revenue()` and `unitsSold(sku)` count only the remaining order.

### Risks
- **Partial updates:** `cancel` mutates in several steps. Validation runs first, and `give` cannot fail for a valid stored quantity, so the window is small. If a bus handler throws during `emit`, the state is already changed. `place` has the same property, so I am keeping that behaviour rather than inventing a new rule.
- **Shared mutable records:** the `orders` Map holds the live objects. Any new code path must copy on the way out, as `get` and `all` already do, or callers can change stored orders.
- **Handler failures:** the bus is synchronous and has no error isolation. A failing `order.cancelled` handler will propagate to the caller after the stock is restored. This is consistent with `place`, but worth knowing.

- Run `npm test` (this is `node --test` per `package.json`). All existing tests and the new cancellation tests should pass.
- Check that no test in the existing file was edited to make it pass.
