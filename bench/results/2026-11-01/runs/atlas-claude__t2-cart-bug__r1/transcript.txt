The cart bugs are fixed in `src/cart.js`. All 9 tests pass with `npm test`, including the 7 new regression tests. Five of the new tests failed on the original code with the reported values (19.9, 20, -5, 0.30000000000000004), and the sixth (`constructor`) failed with NaN.

**Root causes (confirmed by reading the code and by the failing tests):**
1. **Quantity ignored.** The loop added `item.price` and never multiplied by `item.qty`, so 3 × 19.90 gave 19.9.
2. **Percent coupon returned the discount, not the total.** `(sum * value) / 100` is the discount amount, so 100 with OFF20 gave 20.
3. **Fixed coupon could go negative.** Nothing clamped the result, so 5.00 − 10 gave −5.
4. **No rounding.** The sum was returned unrounded, which produced values like 0.30000000000000004.
5. **Unknown coupon names could hit inherited properties.** `COUPONS[couponCode]` with `'constructor'` returned a function, which then produced NaN. This was not in the bug report, but it breaks the "unknown coupons are ignored" rule, so I fixed it too.

**Changes:**
- `src/cart.js`: multiply price by qty; compute the percent as `sum * (100 - value) / 100`; look up coupons with `hasOwnProperty`; return `Math.max(0, Math.round(sum * 100) / 100)`. The export `module.exports = { total }` is unchanged.
- `test/cart.test.js`: added 7 regression tests covering quantity, the OFF20 total, the TENOFF floor at zero, a normal TENOFF subtraction, cent rounding, an unknown coupon, and an inherited property name. The 2 original tests are unchanged.

**Evidence to re-validate:** run `npm test`. Expected: `tests 9`, `pass 9`, `fail 0`.

**Residual risks:**
- Rounding uses `Math.round` on the binary float. Half-cent cases like 1.005 may round either way; a cent-integer implementation would remove that, but it is a larger change than this fix.
- Quantity is assumed to be a number. Negative prices or quantities are not validated.
- Coupon lookup only uses own properties of `COUPONS`. A new coupon must be added to that object to take effect.

**Root cause (from the original code, read from the handoff and the diff):**
1. `sum += item.price` ignored `qty`, so 3 × 19.90 showed 19.9.
2. The percent branch computed `sum * value / 100`, which is the discount, not the discounted total (100 with OFF20 gave 20).
3. The fixed branch subtracted with no floor, so 5.00 − 10 gave −5.
4. There was no cent rounding, so float sums like 0.1 + 0.2 leaked as 0.30000000000000004.
5. `COUPONS[couponCode]` matched inherited properties. `'constructor'` resolved to `Object`, so `sum - coupon.value` became `NaN`.

**Fix applied (`src/cart.js:13-27`):**
- Line 16 multiplies by `qty`.
- Line 18 uses `hasOwnProperty.call` for the coupon lookup.
- Line 21 uses `sum * (100 - value) / 100` for percent coupons.
- Line 26 returns `Math.max(0, Math.round(sum * 100) / 100)`, which clamps and rounds once at the end.
- The export is unchanged: `module.exports = { total }`.

**Validation evidence:**

**Findings (low severity, all outcome-neutral):**
