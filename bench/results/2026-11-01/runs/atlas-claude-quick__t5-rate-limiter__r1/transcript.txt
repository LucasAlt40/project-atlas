**Decisions for the Developer**
1. **Closure state, not a class.** Keep `tokens` (float) and `last` (ms reference) in the `createLimiter` closure. Return a plain object with the four methods.
2. **Validation at construction.** `options` defaults to `{}`, so `createLimiter()` throws `RangeError` rather than a `TypeError` from destructuring. `capacity`: `Number.isInteger(c) && c > 0`. `refillPerSecond`: `typeof r === 'number' && Number.isFinite(r) && r > 0`. Any failure throws `RangeError`. Do not add a check for `now`, since the spec does not require one.
3. **Refill.** `t = now()`. If `t < last`, set `last = t` and add nothing. Otherwise `tokens = Math.min(capacity, tokens + (t - last) * refillPerSecond / 1000)` and `last = t`. This makes the spec's clock-backwards rule explicit: the earlier time becomes the new reference, and no tokens are lost or gained.
4. **Float tolerance.** Accumulated refills can land just below an integer (for example ten additions of 0.1 sum to 0.9999999999999999). Use a single named constant `EPS = 1e-9`. Compare with `tokens >= n - EPS`, and compute `available()` as `Math.floor(tokens + EPS)`. This is the one place where the Developer must not skip the spec's "rounded down" rule. Without it, the accumulation test below fails.
5. **`n` validation** (shared helper used by `tryRemove` and `msUntil`). `n` defaults to 1. Throw `RangeError` unless `Number.isInteger(n) && n > 0`, and also if `n > capacity`. Do this check before refilling.
6. **`msUntil(n)`.** Refill first. `deficit = n - tokens`. If `deficit <= EPS`, return 0. Otherwise return `Math.ceil(deficit * 1000 / refillPerSecond)`.
7. **`tryRemove(n)`.** Refill, validate, then if `tokens >= n - EPS` subtract `n` and return `true`; else return `false` with no change.
8. **`reset()`.** Set `tokens = capacity` and `last = now()`. Setting `last` avoids a stale reference after reset.

**Test plan (`test/limiter.test.js`)**
- Use an injected clock: `let t = 0; const now = () => t;`.
- Validation: each invalid `capacity` (0, -1, 1.5, NaN, Infinity, `'5'`, missing) and each invalid `refillPerSecond` (0, -1, NaN, Infinity, `'1'`, missing), plus `createLimiter()` with no arguments, all throw `RangeError`.
- Starts full: `available() === capacity`.
- `tryRemove` success removes tokens and returns `true`. A failed attempt returns `false` and leaves `available()` unchanged.
- `tryRemove(n)` with `n = capacity` succeeds. `n` of 0, -1, 1.5, NaN, `'2'`, and `capacity + 1` throw `RangeError`.
- Continuous refill with `refillPerSecond = 0.5`: drain to 0, advance 1000 ms, `available() === 0`; advance another 1000 ms, `available() === 1`.
- Cap: advance a very long time, then `available() === capacity`.
- Accumulation (float tolerance): capacity 5, refill 1/s, drain to 0, then ten steps of 100 ms each. Expect `available() === 1`. This fails without `EPS`.
- `msUntil`: returns 0 when tokens are available. With tokens 0 and refill 3/s, `msUntil(1) === 334` (rounded up). With refill 0.5/s, `msUntil(1) === 2000`. `msUntil(capacity + 1)` throws `RangeError`.
- Clock backwards: capacity 10, refill 1/s. Drain at `t = 5000`, set `t = 3000`, and expect `available() === 0`. Set `t = 4000` and expect `available() === 1`. This confirms no tokens are added on the backwards step and that 3000 became the reference.
- `reset()` restores `available() === capacity` after a drain.
- Smoke test: `createLimiter({ capacity: 2, refillPerSecond: 1 })` without `now` returns `available() === 2`.

**Risks**
