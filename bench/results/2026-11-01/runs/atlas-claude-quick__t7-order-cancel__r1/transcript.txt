# Plan: order cancellation

**Size: moderate**

## Goals
- Add `orders.cancel(orderId, reason)` with the behaviour in the task.
- Return stock on cancellation, using the same inventory boundary that `place` uses.
- Keep `reports.revenue()` and `reports.unitsSold(sku)` counting only non-cancelled orders.
- Leave the existing tests passing unchanged and add tests for the new behaviour.

## Current state (what I read)
- `src/orders.js`: `createOrders({ inventory, bus, prices })` keeps orders in a `Map` keyed by numeric id. `place` checks stock, calls `inventory.take`, records `{ id, items, total, status: 'placed' }`, and emits `order.placed`. `get` and `all` return copies, and `items` is copied per entry.
- `src/inventory.js`: only `quantity(sku)` and `take(sku, qty)`. **There is no way to put stock back.**
- `src/reports.js`: both reports iterate `orders.all()` with no status filter.
- `src/events.js`: synchronous `on`/`emit`, with no error isolation.
- `src/shop.js`: already injects `inventory` and `bus` into `createOrders`, so no wiring change is needed.
- `test/shop.test.js`: a single file using `node:test`, with a `setup()` helper and `npm test` as `node --test`.

## In scope
- `src/inventory.js`: add a `restock(sku, qty)` method.
- `src/orders.js`: add `cancel`.
- `src/reports.js`: exclude cancelled orders in both reports.
- `test/shop.test.js`: new test cases.

## Out of scope
- Changing `place`, `get`, `all`, or `shop.js`.
- Partial cancellation, refunds, or re-placing a cancelled order.
- Making the event bus isolate handler errors.

## Decisions for the Developer
1. **Check order in `cancel`:** validate `reason` first (`TypeError`), then look up the order (`Error` containing "not found"), then check status (`Error` containing "already cancelled"). Only after all checks pass, change state.
2. **"Non-empty" means `typeof reason === 'string' && reason.trim() !== ''`.** Whitespace-only counts as empty. The stored reason is kept as given, not trimmed.
3. **Inventory method name is `restock(sku, qty)`.** It does `stock.set(sku, (stock.get(sku) ?? 0) + qty)`, which mirrors `take`. It does not throw.
4. **Mutate the internal record, then return a copy.** The method reads the stored record from the `orders` Map directly, sets `status = 'cancelled'` and `reason`, restocks each item from `order.items`, emits `order.cancelled` with exactly `{ orderId, reason }`, and returns `{ ...order, items: copies }`, matching `place`.
5. **Filter in reports, not in `orders.all()`.** Both reports call `orders.all().filter((o) => o.status !== 'cancelled')`. `all()` keeps returning every order, so callers can still see cancelled ones. The filter sits in one helper inside `createReports`, used by both methods.
6. **Keep the `status` string literal `'cancelled'`** (no constants module), matching the existing `'placed'` literal.

## Files and contracts
- `src/inventory.js`: new `restock(sku, qty)` method. `take` and `quantity` are unchanged.
- `src/orders.js`: new `cancel(orderId, reason)`. Throws `TypeError`, or `Error` with "not found" or "already cancelled". Emits `order.cancelled` once, with `{ orderId, reason }`. Returns the cancelled order. Order records gain an optional `reason` field, set only on cancel.
- `src/reports.js`: `revenue()` and `unitsSold(sku)` skip cancelled orders.
- `test/shop.test.js`: add cases alongside the existing three. Keep the existing ones as they are.

## Test plan
- **Cancel restores stock and records state:** place an order, cancel it, then check `inventory.quantity` for each SKU is back to its original value, the return value has `status: 'cancelled'` and the `reason`, and `order.cancelled` fired once with `{ orderId, reason }`.
- **Unknown id:** throws an `Error` matching `/not found/`, with no stock change and no event.
- **Already cancelled:** the second cancel throws an `Error` matching `/already cancelled/`, with no stock change and no second event.
- **Invalid reason** (`''`, `'   '`, `undefined`, `42`): throws `TypeError`, and nothing changes (status, stock, events).
- **Reports exclude cancelled orders:** after cancelling one of two orders, `revenue()` and `unitsSold(sku)` count only the remaining order.
- **Regression:** the three existing tests pass unchanged.
- Run `npm test` from the worktree.

## Risks
- **Event after mutation:** as with `place`, state changes before `emit`. If a handler throws, the cancel has already happened. This matches the existing design, so I accept it, and the Developer should not reorder it to try to fix this.
- **Two inventory mutators now:** `take` and `restock` both write the same `Map`. That's fine in a synchronous single-process module, but a future persistence layer would need to handle both.
- **Numeric ids:** `cancel('1')` returns "not found", the same as `get('1')`. This is consistent, but callers must pass numbers.

## Verification
- `npm test` passes with the existing tests and the new cases.
- Read-through: no change to the `place` path, and `shop.js` is untouched.

Scope is clear and no decision depends on information only the person has, so I'm not asking a question.
