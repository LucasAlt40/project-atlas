Review complete. I found three correctness defects in `src/users.js`, plus a testing gap. Nothing was modified.

## Findings (most severe first)

**1. High — `escapeHtml` escapes only the first occurrence of each character**
- **File:** `src/users.js:16-21`
- **Why it is wrong:** `String.prototype.replace` with a string pattern replaces only the first match. Any input containing a second `<`, `>` or `&` passes through unescaped. This is an HTML injection / XSS path, since `userRow` (line 25) puts `user.name` into the table markup.
- **Example:** `name = "<img src=x onerror=alert(1)><b>"` becomes `&lt;img src=x onerror=alert(1)&gt;<b>`. The trailing `<b>` is live markup.
- **Fix:** Use global replacement, e.g. `.replace(/&/g, '&amp;').replace(/</g, '&lt;').replace(/>/g, '&gt;')`. Also add `.replace(/"/g, '&quot;').replace(/'/g, '&#39;')`. The quote escapes are not needed for the current element-content use, but they are needed as soon as the output goes into an attribute.
- **Evidence basis:** Read-only analysis of the code. I did not run it.

**2. High — `paginate` skips the first page for 1-indexed input**
- **File:** `src/users.js:3-7`
- **Why it is wrong:** The doc comment says "`page` (1 is the first page)", but `start = page * size`. Page 1 returns items `[size, 2*size)`, so the first `size` items are never reachable as page 1. Page 0 returns the first page, which contradicts the contract. Non-integer, negative or NaN `page`/`size` values are not validated.
- **Fix:** `const start = (page - 1) * size;`, and validate that `page` and `size` are positive integers, throwing a `RangeError` otherwise.
- **Evidence basis:** Read-only analysis of the code. I did not run it.

**3. Medium — `isAdult` ignores month and day**
- **File:** `src/users.js:9-13`
- **Why it is wrong:** It compares only the calendar years. Someone born 2008-06-15 is counted as adult on 2026-03-01, when they are actually 17. Anyone born in the last months of the year is misclassified for part of each year.
- **Fix:** Compute the age correctly: subtract one if the birthday has not yet occurred on `today`. Compare `(today.getMonth(), today.getDate())` with `(birthDate.getMonth(), birthDate.getDate())`. Add a test for a date just before the 18th birthday.
- **Evidence basis:** Read-only analysis of the code. I did not run it.

**4. Low — No tests exist for this module**
- **File:** `package.json:1` (`"test": "node --test"`); the worktree has no test files.
- **Why it matters:** Every defect above would be caught by a basic unit test. The project already has a test script wired up, so the gap is in coverage, not tooling.
- **Fix:** Add `test/users.test.js` covering: `paginate` page 1 returning the first page, out-of-range pages, `escapeHtml` with multiple special characters, `isAdult` on birthdays before and after the 18th birthday, and `userRow` with an admin and a non-admin user.

## Verdict
**Fail.** Two defects (`escapeHtml`, `paginate`) are concrete correctness and security problems, and `isAdult` is a correctness error. These must be fixed before the work is accepted.
