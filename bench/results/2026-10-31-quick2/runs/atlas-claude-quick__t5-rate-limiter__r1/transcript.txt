# Plan: token bucket limiter (`src/limiter.js` + `test/limiter.test.js`)

**Size: moderate**

## Goals
- Export exactly `module.exports = { createLimiter }` from `src/limiter.js`.
- Implement a continuous-refill token bucket with an injectable clock.
- Cover the contract with `node:test` and `node:assert` tests in `test/limiter.test.js`.
- Touch no other file. `package.json` and `README.md` stay as they are.

## Out of scope
- No dependencies, no TypeScript, no ESM, no extra exports, no persistence, no concurrency handling beyond single-threaded JS.
- No validation of `now` beyond using it. The spec does not require it, so I won't add it.

## Modules and architecture impact
- Single leaf module. It depends only on the injected `now` (default `Date.now`). Nothing else in the project imports it yet, so impact is contained.
- Pure in-memory state in a closure: `capacity`, `refillPerMs = refillPerSecond / 1000`, `tokens` (float), `last` (reference time in ms). Closure rather than a class keeps the surface identical to the `{ createLimiter }` contract.

## Decisions the Developer must follow
1. **Construction:** validate before anything else. `capacity`: `Number.isInteger(c) && c > 0`. `refillPerSecond`: `typeof r === 'number' && Number.isFinite(r) && r > 0`. Otherwise `throw new RangeError(...)`. Start with `tokens = capacity` and `last = now()`.
2. **Refill (one private function, called first by every public method):**
   - `t = now()`.
   - If `t < last`: set `last = t` and leave `tokens` unchanged (no gain, no loss).
   - Else: `tokens = Math.min(capacity, tokens + (t - last) * refillPerSecond / 1000)` and `last = t`.
   - Multiply before dividing to limit float error.
3. **Float tolerance (the main numeric risk).** A value such as 0.1 tokens/s over exactly 10 000 ms can land at `0.9999999999` and wrongly show 0 tokens. Use one shared epsilon, `EPS = 1e-9`:
   - `available()` = `Math.floor(tokens + EPS)`.
   - `tryRemove(n)` succeeds when `tokens + EPS >= n`. On success, subtract `n` and clamp at 0 (`Math.max(0, tokens - n)`).
   - `msUntil(n)`: `deficit = n - tokens`. If `deficit <= EPS` return 0. Otherwise `Math.ceil((deficit * 1000 / refillPerSecond) - EPS)`, so it never reports one extra millisecond.
4. **`n` validation (shared helper for `tryRemove` and `msUntil`):** `Number.isInteger(n) && n > 0`, else `RangeError`. Also `n > capacity` gives `RangeError`, because the spec says it can never succeed. This applies to `msUntil` as well, since it has the "same RangeError rules". Defaults: `n = 1`.
5. **`reset()`:** set `tokens = capacity` and `last = now()`. Setting `last` directly makes the current clock reading the new reference.
6. **Style:** match the repo: CommonJS `require`/`module.exports`, 2-space indent, semicolons, single quotes, no comments beyond what is needed to explain the epsilon and the clock-backwards rule.

- **Create** `test/limiter.test.js`. Use `const { test } = require('node:test')` and `const assert = require('node:assert')`. Inject a fake clock: `let t = 0; const now = () => t;`.

## Test cases
1. Starts full: `available() === capacity`.
2. `tryRemove` removes tokens and returns true. An insufficient request returns false and removes nothing (check `available()` afterwards).
3. Refill is capped at capacity: advance time far past full, `available() === capacity`.
4. Fractional rate `refillPerSecond = 0.5`: no token at 1 999 ms, one token at 2 000 ms.
5. `available()` floors fractional tokens.
6. `msUntil`: returns 0 when already available; otherwise rounds up (e.g. rate 3/s, empty bucket, `msUntil(1) === 334`).
7. Float edge: rate `0.1`, capacity 1, empty, advance exactly 10 000 ms, then `available() === 1` and `tryRemove()` is true.
8. Invalid constructor options throw `RangeError`: missing options, capacity `0`, `-1`, `1.5`, `NaN`, `Infinity`, `'5'`; refill `0`, `-1`, `NaN`, `Infinity`, missing, `'1'`.
9. Invalid `n` throws `RangeError` in both `tryRemove` and `msUntil`: `0`, `-1`, `1.5`, `'2'`, `NaN`, and `n > capacity`.
10. Clock goes backwards: capacity 10, rate 1/s. At t=0 remove 10 (empty). At t=5000 `available() === 5`. Set t=1000: `available()` still 5 (no tokens added or lost). At t=2000: `available() === 6`.
11. `reset()` restores full capacity after draining.
12. Default clock: `createLimiter({ capacity: 1, refillPerSecond: 1 })` without `now` works and `available() === 1` immediately.

5. A non-numeric `now()` result (for example `undefined` or `NaN`) makes `tokens` NaN, so `tryRemove` returns `true` forever. This is outside the contract; a guard would help.
