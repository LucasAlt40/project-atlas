## Plan: token bucket in `src/limiter.js` with tests in `test/limiter.test.js`

**Goal:** a CommonJS `createLimiter(options)` module, exported as `module.exports = { createLimiter }`, implementing a continuously refilling token bucket with an injectable clock.

**In scope**
- `src/limiter.js` (new): config validation, bucket state, `tryRemove`, `available`, `msUntil`, `reset`.
- `test/limiter.test.js` (new): `node:test` plus `node:assert`, using a fake `now` for deterministic time.

**Out of scope**
- README, `package.json`, and any other file. The task says to touch no other file.
- Async waiting helpers, per-key limiters, persistence, TypeScript types. `msUntil` only reports the wait; it does not sleep.

**Architectural impact:** greenfield and self-contained. The module has no dependencies and no coupling to other code. It introduces the `src/` and `test/` layout that the README's `node --test` setup already implies.

**Decisions the Developer must follow**
1. **Closure state, no class.** `createLimiter` returns an object of functions that close over `capacity`, `refillPerSecond`, `now`, `tokens` and `last`. This matches the single export.
2. **Fractional token count.** `tokens` is a float. One private `refill()` is the only place time is read and converted to tokens. `tryRemove`, `available`, `msUntil` and `reset` all call it first.
3. **Refill rule.** Let `t = now()`. If `t > last`, set `tokens = min(capacity, tokens + (t - last) * refillPerSecond / 1000)`. In every case, set `last = t`. If `t < last`, nothing is added or removed and the earlier time becomes the reference, as the spec requires.
4. **Float tolerance.** Use one named constant, `EPS = 1e-9`. Compare `tokens + EPS >= n` in `tryRemove`. Return `Math.floor(tokens + EPS)` from `available`. In `msUntil`, if `n - tokens <= EPS` return 0, otherwise return `Math.ceil(ms - EPS)`, where `ms = (n - tokens) * 1000 / refillPerSecond`. After a successful removal, store `Math.max(0, tokens - n)` so no tiny negative value survives.
5. **Validation first.** `createLimiter` treats a missing `options` as `{}`, so the call throws `RangeError` and never `TypeError`. Capacity must satisfy `Number.isInteger(c) && c > 0`. Refill must satisfy `typeof r === 'number' && Number.isFinite(r) && r > 0`. Any `n` must satisfy `Number.isInteger(n) && n > 0 && n <= capacity`, otherwise `RangeError`. Validation happens before any state change.
6. **`now` default.** Use `now = Date.now` when undefined. Do not validate it, because the spec does not require that.
7. **`reset()`.** Call `refill()` to refresh the reference time, then set `tokens = capacity`.
8. **Style.** There is no existing JS code and no lint config, so I suggest `'use strict';`, semicolons, single quotes, 2-space indent, and a short comment on the clock-backwards rule.

**Files and contracts**
- `src/limiter.js` exports exactly `{ createLimiter }`. Its contract is the one in the task statement.
- `test/limiter.test.js` covers:
  - export shape
  - starts full
  - `tryRemove` success and failure, with no removal on failure
  - refill over time, including the 2s-per-token case at 0.5/s
  - capped at capacity after a long wait
  - `available` floors fractional tokens
  - `msUntil` rounds up (e.g. `msUntil(1)` at 3/s from empty is 334) and returns 0 when tokens are available
  - clock going backwards: no tokens added, none lost, reference moved back
  - `reset`
  - float drift: 100 steps of 100 ms at 0.1/s yields exactly one token at 10 s
  - every invalid `capacity`, `refillPerSecond`, and `n` throws `RangeError`, including `n > capacity`, and `createLimiter()` with no argument
  - default `now` works without an injected clock

**Risks**
- **Float drift (medium).** Summed fractional refills can land just below an integer. Decision 4 is the mitigation, and the float-drift test checks it.
- **Backwards-clock over-credit (low).** Because the reference moves back, the span between the new and old reference can be credited a second time later. The spec requires this behaviour, so I have not changed it. A monotonic clock such as `performance.now()` would avoid the issue, but the spec fixes the default to `Date.now`.
