**Decisions the Developer must follow**
1. Normalize in this order: `text.normalize('NFD').replace(/[\u0300-\u036f]/g, '').toLowerCase().replace(/[^a-z0-9]+/g, '-').replace(/^-+|-+$/g, '')`. The NFD step strips combining marks, so ç, ã, é, and ü become c, a, e, and u.
2. Characters with no decomposition (ß, ø, æ, ł) are not a-z or 0-9, so rule 3 turns them into `-`. This follows the spec literally. Example: `'Straße'` becomes `'stra-e'`. I am flagging this as a loss of information, not changing it.
3. Check `typeof text !== 'string'` first and throw `TypeError`.
4. Truncate only after normalization, so the length counts the final slug. If `slug.length > maxLength`, take `dash = slug.lastIndexOf('-', maxLength)`. If `dash > 0`, use `slug.slice(0, dash)`. Otherwise use `slug.slice(0, maxLength)` (hard cut). `lastIndexOf` includes index `maxLength`, so a dash exactly at that position still counts as a word boundary. Checked against the examples: `'hello-big-world'` with 9 gives `'hello-big'`, with 8 gives `'hello'`, and `'supercalifragilistic'` with 5 gives `'super'`.
5. Validate `maxLength` when it is not `undefined`: it must be a positive integer, otherwise throw `TypeError`. The spec does not cover this case; without the check, `null` would silently produce `''`. This is my choice and you can redirect it.
6. Empty result (text with no a-z/0-9) returns `''`. The spec does not say otherwise.
7. The file uses CommonJS with no default export, and the export line is exactly `module.exports = { slugify };`.
8. Test file uses `require('node:test')` and `require('node:assert')`, with `require('../src/slugify')`. Keep it small and in the style of the README.
