# Plan: order cancellation

## Goals
- `orders.cancel(orderId, reason)` restores stock, sets `status: 'cancelled'`, stores the reason, emits `order.cancelled` once, and returns the cancelled order.
- Invalid calls throw without changing anything.
- `reports.revenue()` and `reports.unitsSold(sku)` ignore cancelled orders.
- Existing behaviour and the 3 current tests stay green.

## In scope / out of scope
- **In:** `src/inventory.js`, `src/orders.js`, `src/reports.js`, `test/shop.test.js`.
- **Out:** `src/events.js` (no change; `createBus().emit` already does what is needed), `src/shop.js` (no wiring change; `orders` already gets `inventory` and `bus`), `README.md` (optional one-line API note, not required).

## Architectural impact
- Dependency direction is unchanged: `orders` → `inventory`, `bus`; `reports` → `orders` (via `all()`). No new modules, no new injected dependencies.
- The one new contract is an inventory method to return stock. `inventory` currently has only `quantity` and `take`, so it needs a counterpart.
- `orders` stays the only owner of order status. `reports` reads status through `orders.all()`, so it needs no new API.

## Decisions for the Developer to follow
1. **Inventory:** add `add(sku, qty)` to `createInventory`. It sets `stock.get(sku) ?? 0` plus `qty`. It is the mirror of `take`, and it does not throw.
2. **Check order in `cancel`:**
   1. Validate `reason`: if `typeof reason !== 'string' || reason.trim() === ''`, throw `TypeError('reason must be a non-empty string')`. Whitespace-only counts as empty. This is my reading of "non-empty"; flag it if you want the literal `length === 0` instead.
   2. Look up the order. If missing, throw `Error('order ${orderId} not found')`.
   3. If `status === 'cancelled'`, throw `Error('order ${orderId} already cancelled')`.
   4. Only then mutate: restore every item with `inventory.add`, set `status` and `reason` on the stored record, then `bus.emit('order.cancelled', { orderId, reason })`.
   
   Validating everything before the first mutation keeps the function atomic. Argument validation comes before the lookup, so an invalid reason on a missing order gives the `TypeError`.
3. **Stored field name:** `reason` on the order record, since the spec says the order "keeps the reason".
4. **Return value:** a copy of the order, built the same way `get` builds one (copied `items`), so callers can't mutate the store.
5. **Reports:** in `src/reports.js`, filter `o.status !== 'cancelled'` before summing in both `revenue()` and `unitsSold()`. Do not add an `orders.active()` helper; that would be an abstraction the task doesn't need.
6. **Tests:** append to `test/shop.test.js`, reusing its `setup()` helper and `node:test` style. Do not create a new test file.

## Files and contracts to change
- `src/inventory.js`: new `add(sku, qty)`.
- `src/orders.js`: new `cancel(orderId, reason)`. Public contract: returns an order object with `status: 'cancelled'` and `reason`. Emits `order.cancelled` with `{ orderId, reason }` only.
- `src/reports.js`: `revenue()` and `unitsSold(sku)` exclude cancelled orders.
- `test/shop.test.js`: new tests (listed below).

## Verification
Tests to add:
- Cancel restores stock, sets status and reason, returns the cancelled order, and `get()` reflects the change.
- The event fires exactly once with `{ orderId, reason }`. Use a `bus.on` collector, as the existing test does.
- Missing order throws an `Error` whose message contains `not found`, and nothing changes.
- Cancelling twice throws an `Error` containing `already cancelled`. Stock and the event count are unchanged after the second attempt.
- Invalid reasons (`''`, `'   '`, `undefined`, `42`) throw `TypeError`, and nothing changes, including stock and events.
- After cancelling one of two orders, `revenue()` and `unitsSold(sku)` count only the remaining order.

Run `npm test`. The 3 existing tests must still pass, and the new tests must pass. I'll report the test output in the Developer's final message.

## Risks
- **Handler throws during emit.** The bus is synchronous and does not catch handler errors, so a throwing `order.cancelled` handler would leave the cancellation applied but the error propagated. `place` has the same behaviour today, so I'm keeping it consistent rather than changing the bus.
- **Pre-existing shallow copy in `place`.** `place` returns `{ ...order }`, which shares the `items` array with the store. Callers can mutate stored items through it. This is outside this task, so I'm not changing it. `cancel` must copy `items`, not reuse that pattern.
- **Floating-point totals.** Revenue sums floats (`1.5 * 2`, etc.). Removing a cancelled order can leave tiny rounding differences. The tests use values that are exact in binary, so they are unaffected.
