## Plan: token-bucket limiter (`src/limiter.js`) and tests

**Current state:** The project is a dependency-free CommonJS package (`package.json`: `"type": "commonjs"`, `"test": "node --test"`). It has no `src/` or `test/` yet. The README only states these conventions. Nothing in the repo needs to change to host a new leaf module.

### Goals
- A standalone `createLimiter(options)` token bucket, exported as `module.exports = { createLimiter }`.
- Deterministic tests through an injected `now()` clock, run by `npm test`.

### Out of scope
- Any other file, including README, `package.json`, or a `src/index.js` barrel.
- Keyed or multi-bucket limiting, async waiting, or persistence.
- Changing the `Date.now` default.

### Architectural impact
- A single leaf module with no dependencies and no imports. It creates no coupling with the rest of the project.
- The only seam is the injected `now` function. Keep all state in the closure of `createLimiter`, with no module-level state, so each limiter is independent.

### Design decisions for the Developer
1. **Options handling.** Default `options` to `{}`, so a missing object yields a `RangeError` rather than a `TypeError`. Validate with:
   - `capacity`: `Number.isInteger(c) && c > 0`
   - `refillPerSecond`: `typeof r === 'number' && Number.isFinite(r) && r > 0`
   - `now`: `options.now || Date.now`. Do not add extra validation for it.
2. **State.** Keep three closure variables: `tokens` (a float, starting at `capacity`), `last` (the reference time, set to `now()` at creation), and the constants `capacity` and `refillPerSecond`.
3. **Refill (single private function, called first by every public method).**
   - `t = now()`.
   - If `t < last`, set `last = t` and add nothing. The earlier time becomes the reference, and no tokens are lost.
   - Otherwise `tokens = min(capacity, tokens + (t - last) * refillPerSecond / 1000)`, then `last = t`.
4. **Count validation (shared helper for `tryRemove` and `msUntil`).** `n` must be an integer greater than 0, and `n <= capacity`. Otherwise throw `RangeError`. The default `n = 1` comes from the parameter default, so only `undefined` gets the default. `null` and `0` throw.
5. **Floating-point tolerance.** Use a named constant `EPS = 1e-9` in the comparisons:
   - `tryRemove`: succeed when `tokens + EPS >= n`.
   - `available`: return `Math.floor(tokens + EPS)`.
   - `msUntil`: return `0` when `tokens + EPS >= n`. Otherwise return `Math.max(0, Math.ceil((n - tokens) * 1000 / refillPerSecond - EPS))`.
   This keeps `msUntil(n) === 0` exactly when `tryRemove(n)` would succeed, and it stops accumulated float error from losing or adding a token.
6. **`reset()`.** Set `tokens = capacity` and `last = now()`, so a clock that went backwards does not affect the next refill.
7. **Style.** Match the project's terse CommonJS style. Use `'use strict'` only if the Developer finds it consistent with the existing code, and there is none yet, so no comment or header is required.

### Files and contracts
- **New:** `src/limiter.js`. Exports exactly `{ createLimiter }`. Each returned method has the documented signature: `tryRemove(n = 1)`, `available()`, `msUntil(n = 1)`, `reset()`.
- **New:** `test/limiter.test.js`, using `node:test` and `node:assert`. Node's runner picks it up through `node --test`.
- **Untouched:** `README.md`, `package.json`, and everything else.

### Test plan (`test/limiter.test.js`)
- **Validation.** Each invalid `capacity` value (missing, string, `0`, `-1`, `1.5`, `NaN`, `Infinity`) and each invalid `refillPerSecond` value (missing, `0`, negative, `NaN`, `Infinity`) throws `RangeError`. Also a missing options object.
- **Initial state.** The bucket starts full: `available() === capacity`.
- **`tryRemove`.** Success removes exactly `n`. Failure returns `false` and removes nothing. Default `n` is 1. Invalid `n` (`0`, `-1`, `1.5`, `null`, `NaN`) throws. `n > capacity` throws `RangeError`.
- **Refill.** Fractional rate `0.5`: after 2000 ms one token is back, and after 1000 ms none. Tokens never exceed `capacity` after a long idle period.
- **`available`.** Floors a fractional token count.
- **`msUntil`.** Returns `0` when enough tokens exist. Rounds up a fractional wait. Returns the same boundary as `tryRemove`: when `msUntil` says 0, `tryRemove` succeeds, and vice versa.
- **`reset`.** Refills the bucket to `capacity` after it was drained.
- **Clock regression.** Set `now` backwards: no tokens are added and none are lost. The earlier time becomes the reference, so a later forward step refills from that point.
- **Default clock.** Without `now`, a fresh bucket (full) allows `tryRemove()` to succeed. Do not assert on timing.

### Risks
- **Float drift** is the main correctness risk. Mitigated by the `EPS` rule in decision 5. Include a test where a fractional rate lands exactly on a token boundary, such as `refillPerSecond = 0.1` after `10000` ms.
- **`Date.now` is wall-clock time**, so it can jump. This is why the regression rule exists. A monotonic source would be safer, but the spec fixes `Date.now` as the default, so I am not changing it.
- **Edge `n > capacity` in `msUntil`.** It must throw rather than return a number, or callers can wait forever. Covered by the test plan.

### Choices I made beyond the spec
- A missing `options` argument is treated as `{}`, so it throws `RangeError`.
- The `EPS = 1e-9` tolerance is an implementation choice. The spec does not require it.
- `reset()` also re-anchors `last`, so the next refill starts from the reset time.
