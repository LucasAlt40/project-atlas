Análise

Leitura dos números desta rodada, escrita à mão em findings.json.

  1. Juízes em paralelo funcionam: no Implement, o Validador e o QA rodaram lado a lado em todas as 8 execuções (sobreposição de 18 a 43 s). A fase de julgamento caiu de 68 s para 40 s (−41%), com o mesmo trabalho dos dois juízes (69 s somados).

    O que fazer: Manter. É o ganho de tempo que a junção no motor tornou possível.

  2. O tempo total do Implement caiu menos, de 139 s para 130 s (−7%), e o custo subiu de US$ 0,0278 para 0,0330. Duas das 8 execuções rodaram o Desenvolvedor duas vezes porque o haiku fechou o bloco de resultado com JSON inválido (`","}` no fim), e uma (T5) teve uma volta de correção.

    O que fazer: Próximo item: reparar esse defeito de JSON no leitor do resultado em vez de repetir o passo inteiro (cerca de 20 s e 3 mil tokens de saída por repetição).

  3. Cache: a opção que tira do prompt de sistema as partes que mudam não mexeu na taxa de cache (Implement 81% → 80%, Quick 81% → 83%). O que fica fora do cache é o brief e as saídas das ferramentas de cada passo, não o prompt de sistema da CLI.

    O que fazer: Manter a opção (não custa nada), mas não contar com ela. Ganho de cache, se houver, está em reaproveitar a sessão entre passos.

Como foi medido

O mesmo texto de tarefa vai para todos os braços; a avaliação não chama modelo nenhum.

Braços

  • Claude puro: claude -p com o modelo haiku, numa cópia do projeto, como no uso direto.
  • Atlas + Claude: o template de produto do Atlas para o tipo de tarefa (backend real, CLI real, worktree isolado), todos os agentes no mesmo modelo; planos aprovados automaticamente.
  • Atlas Quick: o template Quick change nas tarefas de feature, com um agente a menos.

Tarefas

  • T1 · Feature nova: slugify: template Implement; testes ocultos em node --test.
  • T2 · Bug por sintoma: carrinho: template Debug & fix; testes ocultos em node --test.
  • T3 · Feature em 2 arquivos: prioridades: template Implement; testes ocultos em node --test.
  • T4 · Revisão: 3 defeitos plantados: template Review & audit; testes ocultos em node --test.
  • T5 · Limitador de taxa: template Implement; testes ocultos em node --test.
  • T6 · Bug: CSV com 5 defeitos: template Debug & fix; testes ocultos em node --test.
  • T7 · Cancelar pedido em 3 arquivos: template Implement; testes ocultos em node --test.
  • T8 · Bug real: doação recorrente (Oficina): template Debug & fix; testes ocultos em JUnit/Mockito com Maven offline.

Qualidade

  • Testes ocultos: ficam fora do projeto que o agente vê e só entram na avaliação. Foram validados contra uma solução de referência e falham no código original.
  • Testes próprios: os que o agente escreveu, rodados no código final.
  • Escopo: arquivos alterados fora do que a tarefa permite.

Tokens, custo e tempo

  • Entrada inclui o que veio do cache do provedor (mais barato); a planilha separa as duas partes.
  • Custo é o preço de API que a CLI do Claude informa; no plano de assinatura sai da cota, não da fatura. O Codex não informa custo.
  • Tempo é o relógio da execução inteira, no Atlas incluindo a montagem do worktree.

Limites

  • Amostra pequena: 2 rodadas por tarefa. Diferenças de poucos segundos ou centavos podem ser ruído.
  • Modelo barato (haiku) e tarefas bem especificadas, o terreno onde um agente sozinho já vai bem.
  • O Codex não rodou nesta rodada.
