## Plan: order cancellation

**Goals.** Add `orders.cancel(orderId, reason)` with the behaviour in the task. Keep `place`, `get`, `all`, and `reports` behaving as before for non-cancelled orders. Add tests in `test/`.

**In scope.** `src/inventory.js`, `src/orders.js`, `src/reports.js`, `test/shop.test.js`.
**Out of scope.** `src/events.js` (no change; `bus.emit` already does what is needed), `src/shop.js` (the wiring already passes `inventory`, `bus` and `orders` through, so nothing new needs wiring), README, and any async or persistence work.

**Architectural impact.** `orders` gains a dependency on the inventory's restore operation, which it already has through `inventory.take`. `reports` gains a dependency on the `status` field of an order. Both are small, one-way, and in line with the existing shape: `shop.js` composes, and modules receive their collaborators as arguments.

**Steps and decisions for the Developer.**

1. **`src/inventory.js`.** Add `restore(sku, qty)`, the inverse of `take`: `stock.set(sku, (stock.get(sku) ?? 0) + qty)`. It does not need a guard, because it only adds stock.

2. **`src/orders.js`.** Add `cancel(orderId, reason)`. Checks run in this order, before any state changes:
   - `reason` must be a string and non-empty after `trim()`. Otherwise throw `TypeError`. I chose `trim()` so that whitespace-only reasons are rejected; the task says "non-empty", and this is a judgment call, so tell me if you want the literal `reason === ''` check instead.
   - The order must exist. Otherwise throw `Error('order ${orderId} not found')`.
   - `status` must not be `'cancelled'`. Otherwise throw `Error('order ${orderId} already cancelled')`.
   - Only then: for each item, `inventory.restore(sku, qty)`; set `order.status = 'cancelled'` and `order.reason = reason`; `bus.emit('order.cancelled', { orderId, reason })`; return a copy of the order, built the same way `get` builds it.

   When the reason is invalid and the order is also missing, the `TypeError` wins. The task does not say which error takes priority in that case, so I picked argument validation first, the usual convention.

3. **`src/reports.js`.** In `revenue()` and `unitsSold(sku)`, filter out orders with `status === 'cancelled'` before summing. Filter in the reports module, not in `orders.all()`, so `all()` still returns every order and the change stays visible where the rule applies.

4. **`test/shop.test.js`.** Append tests in the existing style (`node:test`, `assert`, the `setup()` helper):
   - cancel restores stock, sets status and reason, returns the cancelled order, and emits `order.cancelled` once with `{ orderId, reason }`;
   - unknown id throws an Error containing "not found" and changes nothing;
   - cancelling twice throws an Error containing "already cancelled", and the second call changes no stock and emits no event;
   - an empty or non-string reason throws `TypeError` and changes nothing;
   - after a cancel, `revenue()` and `unitsSold()` exclude that order.

**Files and contracts.**
- `inventory.restore(sku, qty)`: new.
- `orders.cancel(orderId, reason)`: returns the cancelled order copy, with `status: 'cancelled'` and `reason`.
- Event `order.cancelled`: payload `{ orderId, reason }`.
- `reports.revenue()` and `reports.unitsSold(sku)`: count only non-cancelled orders.
- Existing `place`, `get`, `all`, and the `order.placed` payload stay the same.

**Risks.**
- `bus.emit` runs after the state change, as in `place`. If a subscriber throws, the cancel has already happened. This matches the existing pattern, so I'm not changing it here.
- Cancelling an order's items relies on the stored `items` being the same as what was taken. That holds because `place` copies items at creation and nothing else changes them.
- `orderId` is matched as a number, as the ids are generated. A string id such as `"1"` will report "not found". Expected, but worth knowing.

**Verification.** Run `npm test` (`node --test`). All three existing tests must still pass, and the new tests must pass. Read the diff to check that every error path returns before any mutation.
