The root cause is confirmed, and all 8 tests pass after the fix.

**Phase 1 (evidence):** I read `src/cart.js` and `test/cart.test.js`, and ran `npm test` after adding the regression tests. The original code had five defects, and each one reproduced in a failing test:

1. **Quantity ignored** (`src/cart.js:16`): the loop summed `item.price` and never used `item.qty`. Reproduced as `19.9 !== 59.7`.
2. **Percent coupon inverted** (`src/cart.js:21`): `sum * value / 100` returned the discount amount, not the amount after the discount. Reproduced as `20 !== 80`.
3. **No floor at zero** (`src/cart.js:23`): the fixed coupon subtracted with no clamp. Reproduced as `-5 !== 0`.
4. **No cent rounding**: the total was returned unrounded. Reproduced as `0.30000000000000004 !== 0.3`.
5. **Unknown-coupon check is wrong** (`src/cart.js:18`): `COUPONS[couponCode]` also matches inherited properties such as `constructor`, which produced `NaN`. This was not in the report but fits the "unknown coupons are ignored" requirement, so I fixed it too.

The git history has one commit touching this file (`73cf104 fixture`), so there was no recent change to blame. The root cause is in the code as written.

**Phase 2 (fix):**

- `src/cart.js`:
  - Sums `item.price * item.qty`.
  - Percent coupons compute `sum - sum * value / 100`.
  - Coupon lookup uses `Object.hasOwn`, so only the defined coupons match.
  - The result is `Math.round(Math.max(0, sum) * 100) / 100`, which clamps at zero and rounds to cents.
  - The `module.exports = { total }` API is unchanged.
- `test/cart.test.js`: added six regression tests covering quantity, percent coupon, fixed-coupon floor, cent rounding, unknown coupon, and the inherited-property case. The existing two tests are untouched.

**Test run (`npm test`, after fix):** 8 tests, 8 pass, 0 fail. Before the fix, 5 of the 8 failed.

**Residual risks:**

- `Object.hasOwn` needs Node 16.9 or newer. The project's test runner is `node --test`, so this should be fine, but older runtimes would break.
- Rounding is `Math.round` on the value times 100. Binary floating point can still land on the lower cent for some half-cent values (for example, 1.005 rounds to 1.00). Exact decimal arithmetic would need a different approach.
- Negative prices or quantities are not validated. The report did not ask for this, so I left it alone.

**Files changed:** `src/cart.js`, `test/cart.test.js`.

## QA verdict: pass

The fix is already committed in `ddc8821` (the handoff said uncommitted; `git diff` is empty). It removes the causes, not just the symptoms, and `npm test` passes 8/8. I found no regression in the code paths I traced. The findings below are low severity.

**Root cause (read: `git show 73cf104:src/cart.js`):** `total()` had four independent defects:
1. It summed `item.price` and ignored `item.qty`.
2. For percent coupons it returned the discount (`sum * value / 100`), not the remainder.
3. Fixed coupons had no floor at zero.
4. There was no rounding, and `COUPONS[couponCode]` matched inherited keys like `constructor`, so `sum - undefined` produced `NaN`.

**Fix applied (read: current `src/cart.js:13-27`):** the sum uses `price * qty`. The coupon is looked up with `Object.hasOwn`. Percent coupons subtract the discount from the subtotal. The total is clamped with `Math.max(0, sum)` and then rounded once with `Math.round(x * 100) / 100`. `module.exports = { total }` is unchanged.

**Validation:**
- *Executed:* `npm test` gives 8 pass, 0 fail, including the six new regression tests in `test/cart.test.js:13-41`.
- *Read:* each regression test maps to one defect. Against the pre-fix code, the multiply test gives 19.9 vs 59.7, the OFF20 test gives 20 vs 80, the TENOFF test gives -5 vs 0, the rounding test gives 0.30000000000000004 vs 0.3, and the `constructor` test gives NaN vs 10. The `NOPE` and empty-cart tests already passed before the fix, so they are guards, not regression tests.
- *Read:* the only caller is the test file, so no other code depends on `total`. No shared state is mutated.
- *Not executed:* I did not run the tests against the old code to confirm the failures. Running them would mean writing a file, and my sandbox does not allow that. The pre-fix failures are from my trace and the earlier step's report.

**What remains unverified or untested:**
- Half-cent rounding: `Math.round(x * 100)` inherits binary float error. For example `1.005 * 100` is `100.49999999999999` in IEEE 754, so `total([{price:1.005, qty:1}])` should give `1` (reasoned, not executed).
- Negative `price` or `qty` is not validated, and a negative price is silently clamped to 0.
- An item without `qty` now makes the total `NaN` (`Math.max(0, NaN)` stays `NaN`). The old code ignored `qty`, so this is a behaviour change. The JSDoc requires `qty`, so it is a contract issue, not a bug in the fix.
- `Object.hasOwn` needs Node 16.9+. `node --test` needs Node 18+ anyway, so this is not a real constraint.
- No tests cover HALF, `__proto__`/`toString` keys, `qty: 0`, or half-cent results.

**Decision for the person:** whether to validate or reject negative and non-numeric inputs, and whether half-cent rounding should be half-up in decimal arithmetic. Both are hardening beyond the reported bug, so I rated them low and left the outcome at pass.
