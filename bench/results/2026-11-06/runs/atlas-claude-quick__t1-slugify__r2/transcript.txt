**Decisions the Developer must follow**
1. Pipeline, in this order: `toLowerCase()` → `normalize('NFD')` → remove `/[\u0300-\u036f]/g` → replace `/[^a-z0-9]+/g` with `-` → trim leading and trailing `-` with `/^-+|-+$/g`. Lowercasing comes first so that `İ` decomposes to `i` plus a combining dot, which is then stripped.
2. Type check first: if `typeof text !== 'string'`, throw `TypeError`.
3. `maxLength` (applied to the finished slug, which is ASCII, so length is in characters):
   - If `slug.length <= max`, return the slug unchanged.
   - Otherwise take `prefix = slug.slice(0, max + 1)` and `idx = prefix.lastIndexOf('-')`. If `idx > 0`, return `slug.slice(0, idx)`. If `idx === -1`, the first word does not fit, so return `slug.slice(0, max)`.
   - The `max + 1` window is what makes a dash at position `max` count as a valid cut. This keeps `'hello big'` with `max 5` at `'hello'`.
4. Options: `const { maxLength } = options ?? {};`. `undefined` means no limit. A non-number throws `TypeError`. A number that is not a positive integer throws `RangeError`. The spec does not define invalid values, so this is my choice; the user can redirect it.
5. No new dependencies. No abstractions beyond the one function.
