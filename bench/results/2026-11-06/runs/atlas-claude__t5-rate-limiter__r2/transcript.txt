### Decisions the Developer must follow
1. **State:** keep `tokens` as a float, `last` (the last reference time in ms) and `capacity`/`refillPerSecond` in a closure. The bucket starts full, with `last = now()` at creation.
2. **Refill:** `refill()` reads `t = now()`. If `t < last`, it sets `last = t` and adds nothing, so no tokens are added or lost. Otherwise it sets `tokens = min(capacity, tokens + (t - last) * refillPerSecond / 1000)` and then `last = t`.
3. **Validation in `createLimiter`:** `capacity` must satisfy `Number.isInteger(capacity) && capacity > 0`. `refillPerSecond` must satisfy `typeof === 'number' && Number.isFinite(x) && x > 0`. Any failure throws `RangeError`. Missing values fail the same checks.
4. **Count validation:** every method that takes `n` (`tryRemove`, `msUntil`) uses the same check, `Number.isInteger(n) && n > 0`, which throws `RangeError`. If `n > capacity`, it also throws `RangeError`. Defaults are `n = 1`. Validation runs before refill.
5. **`tryRemove(n)`:** refill, then if `tokens >= n`, subtract `n` and return `true`; otherwise return `false` and change nothing.
6. **`available()`:** refill, then return `Math.floor(tokens)`.
7. **`msUntil(n)`:** refill, then `deficit = n - tokens`. If `deficit <= 0` return `0`. Otherwise return `Math.ceil(deficit * 1000 / refillPerSecond)`. Guard against floating-point drift by subtracting a small epsilon (about `1e-9`) before the ceiling, so an exact value like 3000 ms is not reported as 3001.
8. **`reset()`:** set `tokens = capacity` and `last = now()`.
9. **`now` option:** if it is `undefined`, use `Date.now`. Do not add extra validation of `now`, because the spec does not ask for it. This is an open point; see the note below.
10. **Style:** plain functions in a closure, no classes. Match the project's existing CommonJS style: `'use strict'` is optional and the project has no lint config to follow.

### Test plan (`node:test`, `node:assert/strict`, injected `now`)
- Starts full: `available()` equals `capacity`.
- `tryRemove` succeeds while tokens last and returns `false` once empty, without changing the count on failure.
- Continuous refill with `refillPerSecond = 0.5`: after 1000 ms exactly 0.5 tokens are added, so `available()` stays 0 and a second later it is 1.
- Refill never exceeds `capacity`, even after a long gap.
- `available()` floors fractional tokens.
- `msUntil` returns `0` when available, and rounds up otherwise (for example, deficit 0.3 at 0.1/s gives 3000 ms, not 3001).
- `msUntil` and `tryRemove` agree: after waiting exactly `msUntil(n)` ms, `tryRemove(n)` succeeds.
- `n` validation: `0`, `-1`, `1.5`, `'2'`, `NaN` and `undefined` in `tryRemove` and `msUntil` throw `RangeError`. `n > capacity` throws `RangeError`.
- Constructor validation: missing, `'1'`, `0`, negative, `NaN`, `Infinity` for `refillPerSecond`. For `capacity`: `0`, `1.5`, negative, `NaN`, `Infinity`, missing. All throw `RangeError`.
- Clock going backwards: after the clock moves back, no tokens are added; when time moves forward again, refill counts only from the new reference.
- `reset()` restores a full bucket after the bucket has been drained.
- Default clock: `createLimiter({ capacity, refillPerSecond })` works without `now`.

### Risks
- **Floating-point drift:** fractional refill can leave `tokens` a hair under an integer, which makes `available()` or `tryRemove` off by one. The epsilon in `msUntil` and the exact-value tests above are the mitigation. Also check `available()` at boundaries.
- **Clock backwards with `reset()`:** `reset()` reads `now()`, so a backwards clock at reset just moves `last` back. This is consistent with the rule, but it should be tested.
- **Open point:** the spec does not say what happens when `now` is provided but is not a function, or when it returns a non-number. This plan does not validate either, so a bad `now` may surface as `NaN` arithmetic. If the person wants a `TypeError` for a non-function `now`, that is a one-line addition.
