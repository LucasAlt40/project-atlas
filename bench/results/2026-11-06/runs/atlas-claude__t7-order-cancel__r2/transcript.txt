## Plan: order cancellation

**Goal:** add `orders.cancel(orderId, reason)` so a placed order is cancelled, its stock is returned, the order records status `'cancelled'` and its reason, one `order.cancelled` event fires, and `reports` ignores cancelled orders. Existing behaviour and the three tests in `test/shop.test.js` stay unchanged.

**In scope**
- `src/inventory.js`: a stock-return operation.
- `src/orders.js`: `cancel` and its validation.
- `src/reports.js`: exclude cancelled orders from `revenue()` and `unitsSold()`.
- `test/`: new tests for the new behaviour, in the existing `node:test` style.

**Out of scope**
- `src/shop.js` needs no change. `createShop` already passes `inventory` and `bus` into `createOrders`, so `cancel` gets both.
- `src/events.js` needs no change.
- No new dependencies, no new modules, no refunds or payment logic (there is none in the code).

**Modules and dependencies and architectural impact**
- `orders` already depends on `inventory` (for `take`) and `bus` (for `emit`). `cancel` uses the same two dependencies and adds no new edges.
- `reports` reads `orders.all()` on every call and has no subscription to the bus. Filtering in `reports` therefore keeps it consistent with whatever `orders` holds, with no extra state to sync.
- Impact is small. The one new inventory operation is the mirror of `take`.

**Decisions the Developer must follow**
1. **Inventory:** add `give(sku, qty)` to `createInventory`. It does `stock.set(sku, (stock.get(sku) ?? 0) + qty)`. It does not validate, because cancelling must not fail partway through the stock return. It must not be called with a negative qty.
2. **Order record:** on cancel, set `status = 'cancelled'` and `reason = reason` on the stored order. Do not add a `cancelledAt` or other fields; the spec does not ask for them.
3. **Check order in `cancel`:** (a) validate `reason` first, (b) look up the order, (c) reject if already cancelled, (d) return the stock, (e) update status and reason, (f) emit, (g) return a copy. Every throw happens before any mutation, so a failed call changes nothing.
4. **Validation:** `reason` must satisfy `typeof reason === 'string' && reason.trim() !== ''`. Otherwise throw `TypeError`. I chose to treat whitespace-only as empty. The spec only says "non-empty"; if you want the literal reading, drop the `.trim()`.
5. **Errors:**
   - Missing order: `Error` with a message containing `not found`, for example `order ${orderId} not found`.
   - Already cancelled: `Error` with a message containing `already cancelled`, for example `order ${orderId} already cancelled`.
   - Use `if (!order)`, not `=== undefined`, because `get` returns `undefined` for missing orders.
6. **Event:** emit exactly once, `bus.emit('order.cancelled', { orderId, reason })`, after the state change, and with exactly that payload shape.
7. **Return value:** a copy shaped like `get()` (`items` cloned), so callers cannot mutate internal state. This matches the existing `place`/`get`/`all` pattern.
8. **Reports:** add `o.status !== 'cancelled'` as a filter before the reduce in `revenue()` and before the flatMap in `unitsSold()`. Put the filter in `reports.js`, not in `orders.all()`, so the `orders` API stays unchanged.
9. **Style:** keep the existing comment-per-file style, 2-space indent, single quotes, and the `.js` `require` paths.

**Files and contracts to change**
- `src/inventory.js`: new `give(sku, qty)`. Contract: increases stock, never throws.
- `src/orders.js`: new `cancel(orderId, reason)`. Contract: returns the cancelled order copy; throws `TypeError` for a bad reason, `Error` ("not found" / "already cancelled") for bad state; emits `order.cancelled`.
- `src/reports.js`: `revenue()` and `unitsSold(sku)` exclude `status === 'cancelled'`.
- `test/shop.test.js` (or a new `test/cancel.test.js`): new cases, listed below.

**Tests to add**
- Cancel restores stock: place, cancel, and check `inventory.quantity` returns to its original value for each SKU.
- Status and reason: the returned order and `orders.get(id)` both have `status === 'cancelled'` and `reason === 'changed mind'`.
- Event: one `order.cancelled` event with `{ orderId, reason }`, and no event on failed calls.
- Unknown order throws `Error` matching `/not found/`, with no stock change and no event.
- Already cancelled throws `Error` matching `/already cancelled/`, with no stock change and no second event.
- Bad reason (`''`, `'   '`, `undefined`, `42`) throws `TypeError`, with no state change and no event.
- Reports: after cancelling one of two orders, `revenue()` and `unitsSold('pen')` count only the remaining order.
- Keep the three existing tests unchanged.

**Verification**
- Baseline before changes (run in this worktree): `npm test` gives 3 pass, 0 fail.
- After implementation: `npm test` must show the 3 existing tests plus the new ones all passing.
- Each new test checks state before and after the failing call, so "nothing changes" is tested rather than assumed.

**Risks and observations**
- **Existing, out of scope:** `place()` checks each line against stock independently. If a cart has two lines with the same SKU, both checks can pass, and then `take` can throw partway through and leave earlier takes applied. `cancel` avoids this because `give` cannot fail, but the defect remains in `place`. I recommend a separate fix.
- **Existing, out of scope:** `place()` does not reject non-positive `qty`. A negative qty passes the stock check and increases stock. Cancel does not add this risk, but the cancelled order would then restock a negative amount. Worth a separate fix.
- **Event handlers:** `bus.emit` runs handlers synchronously after the state change. If a handler throws, the cancellation has already happened. This is the same as `place` today, and it is acceptable for a minimal bus.
- **Ordering of checks:** when both `reason` and `orderId` are wrong, `reason` is reported first. Tests should not depend on which error wins in that case.
