## Plan

**Goals**
- Priorities are stored, validated, filterable and sorted as specified.
- `formatList` shows `!` only for `high`.
- All four existing tests pass unchanged.

**Steps (for the Developer)**
1. **store.js, `add(title, options)`:**
   - Keep the existing title validation first.
   - Read `options` with a default of `{}`.
   - If `options.priority` is `undefined`, use `'normal'`.
   - Otherwise, if it is not one of the three strings, throw `RangeError`. This is case-sensitive, so `'High'` is rejected.
   - Store `priority` on the todo object alongside `id`, `title`, `done`.
2. **store.js, `list(filter)`:**
   - Build a copy of the todos (the existing `{...t}` mapping).
   - If `filter` has a `priority`, validate it the same way (throw `RangeError` if invalid) and keep only matching todos.
   - Sort the copy by rank (high 0, normal 1, low 2), with `id` as the tiebreak, so insertion order is kept within a priority.
   - Sort the copy, not `todos`, so the internal array is never reordered.
3. **format.js, `formatList`:** when `t.priority === 'high'`, output `[ ] !Pay rent` (or `[x] !…` when done). Other values, including `undefined`, render exactly as before. Keep the literal `'high'` in format.js and do not import from store.js.
4. **test/store.test.js:** append tests (keep the single-file layout):
   - default priority is `normal`;
   - each valid value is stored;
   - invalid values (`'urgent'`, `'High'`, `null`) throw `RangeError`;
   - `list({ priority })` filters, and an invalid filter value throws;
   - no-filter `list()` orders high, normal, low, with insertion order kept within a level;
   - `formatList` adds `!` for high only, and still formats todos without a `priority` field.

**Decisions the Developer must follow**
- `list()` with an invalid `filter.priority` throws `RangeError`. The spec is silent here. Throwing matches `add` and avoids silent empty results on typos.
- `options.priority === null` throws, because only `undefined` means "use the default".
- Sorting uses a rank map and the `id` tiebreak. Do not rely on `Array.prototype.sort` stability alone.
- No new modules, exported constants or abstractions.

**Files and contracts**
- `src/store.js`: `add` gets an optional second argument. Its return value gains a `priority` field. `list` accepts an optional filter. Its order changes when priorities differ, which is the requested behaviour.
- `src/format.js`: output changes only for `high` todos.
- `test/store.test.js`: new tests added, existing ones untouched.

**Risks**
- The changed `list()` order affects any caller that assumed insertion order. Within this repo, the only caller is the existing test, which uses one priority only.
- Titles that start with `!` will look like high-priority ones in text output. This is acceptable for plain text, so I'm noting it rather than handling it.

**Verification**

- Check by reading that `complete()` and the title validation are unchanged.
