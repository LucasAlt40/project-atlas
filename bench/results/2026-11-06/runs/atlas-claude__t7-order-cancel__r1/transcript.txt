## Plan: order cancellation (analysis for the Developer)

**Goal:** add `orders.cancel(orderId, reason)` so that a placed order returns its stock, becomes `cancelled` with its reason, emits one `order.cancelled` event, and drops out of revenue and units-sold reports.

**In scope**
- `src/orders.js`: new `cancel` method, and storing the reason on the order.
- `src/inventory.js`: a method to return stock.
- `src/reports.js`: exclude cancelled orders from `revenue()` and `unitsSold(sku)`.
- New tests in `test/`.

**Out of scope**
- `place`, `get`, `all` behaviour (`all()` keeps returning every order, including cancelled ones).
- `src/events.js` (no change; `on`/`emit` are enough).
- `src/shop.js` wiring (no new dependencies are passed in, so no change).
- Refunds, partial cancellation, and any payment logic. None exists in the project.

**Current architecture**
- `createShop` (`src/shop.js`) wires `bus`, `inventory`, `orders`, `reports` by injection.
- `orders` depends on `inventory` and `bus`. `reports` depends on `orders` only.
- Orders are held in a private `Map` and returned as copies. Callers never hold a live reference, so mutating status must happen on the internal object only.
- `inventory` exposes only `quantity` and `take`. There is no way to return stock yet.

**Decisions the Developer must follow**
1. **Add `inventory.restock(sku, qty)`.** It mirrors `take`: `stock.set(sku, (stock.get(sku) ?? 0) + qty)`. Do not write to the stock map from `orders`.
2. **Validation order in `cancel`:**
   1. `reason` check first: `typeof reason !== 'string' || reason.trim() === ''` throws `TypeError`. Treating whitespace-only as empty is my call; it is the usual reading of "non-empty".
   2. Look up the order. Missing throws `Error` with message containing `not found`.
   3. If `status === 'cancelled'`, throw `Error` with message containing `already cancelled`.
   4. Only then restock every item and set `status = 'cancelled'` and `reason` on the internal order.
   5. Emit `order.cancelled` with `{ orderId, reason }` last, after state is final, same as `place`.
   6. Return a copy in the same shape as `get`.
   Nothing may change on any error path.
3. **Store the reason on the order** as a `reason` field. `place` does not set it, so it is `undefined` for uncancelled orders. Do not add a separate map.
4. **Filter in `reports`, not in `orders.all()`.** Add a small helper in `reports.js` that returns `orders.all().filter((o) => o.status !== 'cancelled')` and use it in both `revenue` and `unitsSold`. Reports owns the definition of "sold".
5. **Idempotency:** a second cancel must not restock and must not emit. The status check in step 2.3 covers this.
6. **No new abstractions.** No state machine, no event sourcing, no new modules. The codebase uses plain closures and `createX({ deps })`; keep that.

**Files and contracts to change**
- `src/inventory.js`: add `restock(sku, qty)` to the returned object.
- `src/orders.js`: add `cancel(orderId, reason)` to the returned object. Order record gains `reason` (set on cancel only).
- `src/reports.js`: `revenue()` and `unitsSold(sku)` read only non-cancelled orders.
- `test/cancel.test.js` (new file, same `node:test` + `assert` style as `test/shop.test.js`, using `createShop`). Keeping the existing file untouched makes the diff easy to review.

**Tests to add**
- Cancel returns the cancelled order with `status: 'cancelled'` and the reason; `inventory.quantity` returns to the pre-order value.
- Exactly one `order.cancelled` event with `{ orderId, reason }`.
- Unknown id throws `Error` matching `/not found/`; nothing changes.
- Second cancel throws `Error` matching `/already cancelled/`; no stock move and no second event.
- `reason` of `''`, `'   '`, `undefined`, `42` throws `TypeError`; no stock move, no event, status unchanged.
- After cancelling one of two orders: `revenue()` counts only the other; `unitsSold('pen')` counts only the other.
- `orders.get(id)` and `orders.all()` still return the cancelled order (reports exclude it, the store does not).
- Existing three tests in `test/shop.test.js` pass unchanged.

**Risks**
- **Event handler failure after state change.** `emit` is synchronous, so a throwing `order.cancelled` handler would surface after the state changed. `place` has the same property. Mitigation: emit last, as specified. Not fixing it here, since the bus has no error policy and that would be a new abstraction.
- **Id type mismatch.** Ids are numbers. `cancel('1')` will be "not found", consistent with `get`. Worth knowing; not a bug.
- **Historical data.** Orders placed before this change have no `reason` field. Reports and `get` handle that without change.

**Verification**
- `npm test` must pass the three existing tests and the new ones. Baseline run just now: 3/3 pass.
- Developer reads the diff against the decisions above; no other files should change.
