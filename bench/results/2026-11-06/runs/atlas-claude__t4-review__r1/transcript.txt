Review of `src/users.js` is complete. Verdict: **fail**. Three defects are confirmed by reading the code: a pagination off-by-one, a birthday check that ignores month and day, and an HTML escaper that only replaces the first occurrence of each character. The escaper defect is an XSS path. The findings rest on reading alone; I did not run the code, because this review is read-only.

## Findings

**1. High, Security: `escapeHtml` replaces only the first occurrence of each character** (`src/users.js:16-21`)
- `String.prototype.replace` with a string pattern replaces only the first match. Only the first `&`, `<` and `>` are escaped.
- `userRow` (line 25) passes `user.name` through `escapeHtml`, so a crafted name gets through unescaped.
- Example: name `a<b><img src=x onerror=alert(1)>` becomes `a&lt;b&gt;<img src=x onerror=alert(1)>`. The second `<` and `>` are raw, so the `img` tag is live HTML.
- Recommendation: use global regexes, e.g. `.replace(/&/g, '&amp;').replace(/</g, '&lt;').replace(/>/g, '&gt;').replace(/"/g, '&quot;').replace(/'/g, '&#39;')`. Keep `&` first. The quote escapes also make the function safe in attribute context, which the docstring ("safe to put inside HTML") claims.

**2. High, Correctness: `paginate` skips the first page** (`src/users.js:4-6`)
- The docstring says `page` is 1-based, but `start = page * size`. For `paginate([a,b,c,d], 1, 2)` the result is `[c,d]`, not `[a,b]`. Page 0 returns the first page, which contradicts the docstring. The last page can also come back short or empty.
- Recommendation: `const start = (page - 1) * size;`, and reject `page < 1` or non-integer input (for example by throwing a `RangeError`), so callers cannot get silent wrong pages.

**3. Medium, Correctness: `isAdult` compares only the calendar year** (`src/users.js:10-12`)
- `age = today.getFullYear() - birthDate.getFullYear()` ignores month and day. Someone born 2008-12-31 is reported as an adult on 2026-01-01, when they are still 17.
- Recommendation: subtract one year if the birthday has not yet occurred on `today`, e.g. `let age = today.getFullYear() - birthDate.getFullYear(); const m = today.getMonth() - birthDate.getMonth(); if (m < 0 || (m === 0 && today.getDate() < birthDate.getDate())) age--;`. Be explicit about timezone handling, since `Date` getters use local time.

**4. Medium, Testing: no tests exist for this module** (repository root)
- `package.json:1` defines `"test": "node --test"`, but the tree contains only `src/users.js`, `README.md` and `package.json`. None of the three defects above would be caught.
- Recommendation: add `test/users.test.js` covering: page 1 and the last partial page; a birthday on the boundary day; names with multiple `<`, `>`, `&`, quotes.

**5. Low, Conventions: the module header and README do not state the page-numbering convention** (`src/users.js:1`, `README.md:2`)
- Mentioned only for completeness. Once finding 2 is fixed, document the 1-based convention in one place.
