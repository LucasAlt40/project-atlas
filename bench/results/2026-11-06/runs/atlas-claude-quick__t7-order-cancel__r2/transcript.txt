The change is small in code, but it touches three modules with a shared order record and a status that reports must respect, so it needs a written design.

## Plan: order cancellation

**Goals**
- `orders.cancel(orderId, reason)` cancels a placed order, returns mine it, restores its stock and emits `order.cancelled` once.
- Reports (`revenue`, `unitsSold`) ignore cancelled orders.
- Existing behaviour and the 3 existing tests stay unchanged. Baseline: `npm test` passes 3/3.

**In scope**
- `src/inventory.js`: a stock-restore method.
- `src/orders.js`: the `cancel` method and the `reason` field on the order.
- `src/reports.js`: filtering of cancelled orders.
- `test/shop.test.js`: new tests.

**Out of scope**
- Cancelling already-shipped orders, partial cancellation, refunds, and any change to `place`, `get`, `all`, `events.js` or `shop.js`.

**Modules and dependencies**
- `orders` depends on `inventory` (to restore stock) and `bus` (to emit). Both are injected via `createOrders`, so no wiring change is needed in `shop.js`.
- `reports` depends only on `orders.all()`. The cancelled state is visible to it through the `status` string, so `reports` relies on the literal `'cancelled'` that `orders` writes.

**Decisions the Developer must follow**
1. **Validation order in `cancel`:** check `reason` first (TypeError, before any lookup), then find the order (`not found` Error), then check the status (`already cancelled` Error). Nothing is mutated until all checks pass.
2. **Reason validity:** `typeof reason === 'string' && reason.trim() !== ''`. Whitespace-only counts as empty. This is my reading of "non-empty"; flag it if you want the literal check instead.
3. **Mutation pattern:** follow `place`. Restore stock with `inventory.restore(sku, qty)` for each item, then set `order.status = 'cancelled'` and `order.reason = reason` on the internal Map record, then `bus.emit('order.cancelled', { orderId, reason })`. The payload must be exactly `{ orderId, reason }`.
4. **Return value:** a copy shaped like `get()` (`{ ...order, items: copies }`), so callers cannot mutate internal state.
5. **Keep `total` on a cancelled order.** It is the historical record. Reports exclude it by status, not by deleting or zeroing it.
6. **Reports filter:** `o.status !== 'cancelled'` in both `revenue` and `unitsSold`, applied before the existing reductions.
7. **No new abstractions:** no status enum, no event wrapper, no transaction helper. Inline code matching the surrounding style.

**Files and contracts**
- `src/inventory.js`: add `restore(sku, qty)` next to `take`, which does `stock.set(sku, (stock.get(sku) ?? 0) + qty)`. Existing `quantity` and `take` are unchanged.
- `src/orders.js`: add `cancel(orderId, reason)` to the object returned by `createOrders`. Order records gain an optional `reason`, present only on cancelled orders. `place`, `get` and `all` are unchanged.
- `src/reports.js`: add the status filter in `revenue` and `unitsSold`.
- `test/shop.test.js`: append tests and reuse the existing `setup()` helper.

**Tests to add (in `test/shop.test.js`)**
1. Cancel restores stock, sets `status: 'cancelled'` and `reason`, returns the cancelled order, and emits `order.cancelled` once with `{ orderId, reason }`.
2. Unknown id throws an Error matching `/not found/`, with no stock change and no event.
3. Cancelling twice throws an Error matching `/already cancelled/`. Stock is restored only once and only one event is emitted.
4. Invalid reasons (`''`, `'   '`, `undefined`, `42`) throw a TypeError. The order stays `placed`, stock is unchanged and no event is emitted.
5. After cancelling one of two orders, `revenue()` and `unitsSold(sku)` count only the remaining order.
6. The three existing tests pass unchanged.

**Verification**
- Run `npm test`. All 3 existing tests and the new ones must pass.
- Read the diff to confirm that `place`, `get`, `all`, `events.js` and `shop.js` are untouched.

**Risks (architectural)**
- **No atomicity across modules.** `orders` mutates `inventory` and then the order record. Validation runs first, so the only partial-failure path is a throwing event handler after the state change. This is the same as `place` today. Accepted, not fixed here.
- **Coupling through a string.** `reports` depends on `'cancelled'`. If another status is added later, reports must be updated too. A status constant would fix this, but it is not needed for one status.
- **Synchronous bus.** A handler that throws during `emit` propagates into `cancel` after the state has changed. Same as `place`; no change proposed.
