## Plan: token bucket limiter (`src/limiter.js`, `test/limiter.test.js`)

**Goal:** A CommonJS token bucket exporting `{ createLimiter }`, with `tryRemove`, `available`, `msUntil`, and `reset`, plus `node:test` tests.

**In scope:** `src/limiter.js` (new), `test/limiter.test.js` (new). Nothing else.

**Out of scope:** `package.json`, README, any integration with other code, any dependencies. The project has no other modules, so there is no existing pattern to match beyond CommonJS and `node --test`.

**Architectural impact:** None. This is a leaf module with no dependencies. The only external input is the injected `now()` clock.

### Design decisions the Developer must follow

1. **Lazy continuous refill.** Keep `tokens` as a float and `last` as the last time seen. Every public method calls a private `refill()` first:
   - `t = now()`.
   - If `t < last` (clock went backwards): set `last = t` and add nothing. No tokens are lost.
   - Otherwise: `tokens = Math.min(capacity, tokens + (t - last) * refillPerSecond / 1000)`, then `last = t`.
   - Nothing runs on a timer.
2. **Validation in `createLimiter`.** Use `const { capacity, refillPerSecond, now = Date.now } = options ?? {}`, so a missing argument is treated as missing options and throws `RangeError`.
   - `capacity`: `Number.isInteger(capacity) && capacity > 0`.
   - `refillPerSecond`: `typeof === 'number' && Number.isFinite(x) && x > 0`.
   - Failure throws `RangeError`.
   - I am not validating that `now` is a function. If the caller passes a non-function, the failure will show up as a `TypeError` on first use. Say so if you want it checked up front.
3. **Token count (`n`) validation** for `tryRemove` and `msUntil`: `Number.isInteger(n) && n > 0`, else `RangeError`. Also `n > capacity` throws `RangeError`, because it can never succeed. `available()` takes no argument.
4. **Initial state:** `tokens = capacity`, `last = now()`, computed in `createLimiter`.
5. **`reset()`:** set `tokens = capacity` and `last = now()`.
6. **`available()`:** after refill, return `Math.floor(tokens)`.
7. **`msUntil(n)`:** after refill, `deficit = n - tokens`. If `deficit <= 0`, return `0`. Otherwise return `Math.ceil(deficit * 1000 / refillPerSecond)`.
8. **`tryRemove(n)`:** after refill, if `tokens >= n`, subtract `n` and return `true`. Otherwise change nothing and return `false`.
9. **Export:** `module.exports = { createLimiter };` and nothing else.

### Files and contracts

- `src/limiter.js`: the module above. Creates the `src/` directory.
- `test/limiter.test.js`: `require('node:test')`, `require('node:assert')`. Inject a controllable clock, e.g. `let t = 0; const now = () => t;` and advance `t` between calls.

### Test plan

- **Validation:** a table of invalid `capacity` values (missing, `0`, `-1`, `1.5`, `'3'`, `NaN`, `Infinity`) and invalid `refillPerSecond` values (missing, `0`, `-1`, `NaN`, `Infinity`, `'1'`). Each throws `RangeError`. Also check that `createLimiter()` with no argument throws `RangeError`.
- **Starts full:** `available()` equals `capacity`.
- **`tryRemove`:** removes tokens and returns `true`. Returns `false` and leaves the count unchanged when there are not enough tokens.
- **Refill:** after advancing time, tokens grow by `elapsed * rate / 1000`.
- **Cap:** a long wait never pushes `available()` above `capacity`.
- **Fractional rate:** with `refillPerSecond: 0.5`, one token returns after 2000 ms.
- **`available()` floors:** a partial token does not count.
- **`msUntil`:** returns `0` when tokens are already available. Otherwise returns the rounded-up ms. Advancing the clock by exactly that amount makes `tryRemove(n)` succeed.
- **`n` validation:** `0`, `-1`, `1.5`, and `n > capacity` throw `RangeError` in both `tryRemove` and `msUntil`.
- **`reset()`:** returns the bucket to `capacity`.
- **Clock going backwards:** time goes 1000, then 500, then 750. Nothing is added at 500. At 750, the refill covers 250 ms (`last` was reset to 500), not 500 ms.

### Risks

- **Float rounding.** Tokens are fractional, so `floor` and `ceil` can be thrown off by tiny errors. For example, `0.1 * 3` is not exactly `0.3` in JavaScript. Tests should use rates and intervals that are exact in binary, such as `0.5`, `2`, `4`, and multiples of 1000 ms. Only use decimal rates like `0.1` if the assertion tolerates the error.
- **`msUntil` vs `tryRemove` agreement.** If `msUntil` rounds up but the float tokens fall just short after that exact wait, `tryRemove` fails. The test in step 7 above covers this with exact values.
