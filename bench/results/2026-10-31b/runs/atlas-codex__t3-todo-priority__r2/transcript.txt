## Architecture and impact

This is a small in-memory module with two boundaries:

- `src/store.js`: owns todo creation, mutation, filtering, copying, and ordering.
- `src/format.js`: pure presentation function consuming todo-shaped objects.
- `test/store.test.js`: integration-level contract coverage for both modules.

There are no runtime dependencies. The only architectural impact is expanding the todo data contract with `priority`. `formatList` should remain tolerant of existing todo objects without a priority and only add `!` when `priority === 'high'`.

## Implementation plan

1. Update `createStore().add(title, options)` in `src/store.js`.
   - Default omitted options to an empty object.
   - Default omitted priority to `'normal'`.
   - Accept only `'low'`, `'normal'`, and `'high'`.
   - Throw `RangeError` for any other explicit priority.
   - Store `priority` on every todo.

2. Update `store.list(filter)` in `src/store.js`.
   - Preserve the existing copied-object behavior.
   - When `filter.priority` is present, return only matching todos.
   - Without a priority filter, order todos by `high`, `normal`, then `low`.
   - Preserve insertion order among todos with equal priority.
   - Avoid mutating the store’s internal array.

3. Update `formatList` in `src/format.js`.
   - Render high-priority todos as `[ ] !Title` or `[x] !Title`.
   - Leave normal and low priority output unchanged.

4. Add tests in `test/store.test.js` covering:
   - Default priority.
   - Explicit valid priorities.
   - Invalid priority throwing `RangeError`.
   - Priority ordering with stable same-priority insertion order.
   - Priority filtering.
   - High-priority formatting and unchanged formatting for other priorities.
   - Existing tests remain unchanged and must continue passing.

## Decisions for the Developer

- Use a local priority ranking (`high`, `normal`, `low`) inside `list`; do not introduce a separate module.
- Sort a copied/result array, never the internal `todos` array.
- Use exact string matching for priority values.
- Keep `add`’s current title validation and trimming behavior.
- Preserve the current shallow-copy behavior of `list`.
- Treat missing priority on formatter input as non-high, preserving compatibility with existing callers.

## Risks

- Returning sorted results changes the previous default insertion ordering across different priorities, as explicitly required.
- Adding `priority` changes the shape of returned todos, also explicitly required.
- An unstable sort could violate same-priority insertion order; tests must assert this contract directly.
