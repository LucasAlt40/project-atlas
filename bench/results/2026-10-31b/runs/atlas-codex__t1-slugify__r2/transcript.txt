# Plan: Add `slugify` utility

## Goals

Implement a dependency-free CommonJS utility that:

- Exports exactly `{ slugify }`.
- Validates that `text` is a string.
- Lowercases input and removes diacritics.
- Collapses non-ASCII-alphanumeric runs into one hyphen.
- Trims leading/trailing hyphens.
- Applies `maxLength` without splitting words when possible.

## Scope

In scope:

- New module: `src/slugify.js`.
- New built-in tests: `test/slugify.test.js`.
- Coverage for normalization, separators, trimming, length limits, hard cuts, and invalid text input.

Out of scope:

- Changes to `package.json`, README, or test configuration.
- External dependencies or new abstractions.
- Defining behavior for unsupported `maxLength` values beyond the stated positive-integer contract.

## Architecture and dependencies

The project is a small CommonJS package with no runtime dependencies. `src/slugify.js` will be a standalone utility boundary with no imports. `test/slugify.test.js` will use Node’s built-in `node:test` and `node:assert`, matching the existing `node --test` script.

The implementation should use native Unicode normalization (`NFD`) and remove combining marks before replacing separators. This keeps the behavior local, deterministic, and dependency-free.

## Decisions for the Developer

- Preserve the exact export shape: `module.exports = { slugify }`.
- Throw `TypeError` when `text` is not a string.
- Normalize accents before separator replacement so values such as `ação` become `acao`, not a sequence containing separators.
- Treat every run outside `[a-z0-9]` as one separator after lowercasing and normalization.
- Trim separators before applying `maxLength`.
- For `maxLength`, retain the longest complete hyphen-delimited prefix that fits; if the first word exceeds the limit, hard-cut that word.
- Do not split a word when a valid hyphen boundary fits.
- Do not modify existing project files.

## Files and contracts

- `src/slugify.js`
  - Public contract: `slugify(text, options)`.
  - Public export: `{ slugify }`.
  - No external dependencies.

- `test/slugify.test.js`
  - Verify the examples from the task.
  - Add cases for accents, punctuation runs, whitespace, leading/trailing separators, `maxLength` boundaries, hard cuts, and `TypeError`.

## Risks

- Unicode characters outside the Latin diacritic range will normalize but may still become separators; this follows the explicit `[a-z0-9]` output rule.
- Cutting by raw string length must not leave a trailing hyphen or accidentally split a word when a prior hyphen boundary is available.
- Adding validation rules for unspecified `options.maxLength` values could create an unrequested API contract, so tests should focus on the stated positive-integer input.
