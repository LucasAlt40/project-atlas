## Review: `src/users.js`

Scope: the whole file (28 lines, 4 exported helpers). The project has no test files, and the only other match for these names is `package.json`, which I did not treat as a caller. No other module in the repo imports `src/users.js`.

### Findings, most severe first

**1. High · Correctness · `paginate` skips the first page**
- **File:** `src/users.js:4-6`
- **Reason:** The doc comment says `page` is 1-based ("1 is the first page"), but the code computes `start = page * size`. For `page = 1, size = 10`, it returns items 10–19, so the first page (items 0–9) is never reachable. `page = 0` returns the first page, which contradicts the comment.
- **Recommendation:** Use `const start = (page - 1) * size;`. Optionally reject `page < 1` or non-integer input so a bad page does not silently return a wrong slice.

**2. High · Correctness · `isAdult` ignores the birthday**
- **File:** `src/users.js:10-12`
- **Reason:** The function subtracts only the birth year from the current year. Someone born 2008-11-01, evaluated on 2026-10-31, is actually 17 but is reported as 18 and therefore an adult. The result is wrong for roughly every person in the year they turn 18, and it is wrong in the other direction for anyone whose birthday falls later in the year. The doc comment ("18 or older on `today`") describes the correct behavior the code does not implement.
- **Recommendation:** Compare full dates. For example:
  ```js
  let age = today.getFullYear() - birthDate.getFullYear();
  const m = today.getMonth() - birthDate.getMonth();
  if (m < 0 || (m === 0 && today.getDate() < birthDate.getDate())) age--;
  return age >= 18;
  ```
  Using UTC accessors consistently would also avoid timezone drift for dates-only input.

**3. High · Security · `escapeHtml` escapes only the first occurrence of each character**
- **File:** `src/users.js:17-20`
- **Reason:** `String.prototype.replace` with a string pattern replaces only the first match. `'<img><img onerror=...>'` becomes `'&lt;img><img onerror=...>'`; the second tag passes through unescaped. `userRow` (line 25) passes user-supplied `user.name` through this function, so a crafted name can inject markup into the users page (stored XSS). The `&`-first ordering is correct, but the non-global replacements defeat it.
- **Recommendation:** Use a global map-based replacement:
  ```js
  const HTML_ESCAPES = { '&': '&amp;', '<': '&lt;', '>': '&gt;', '"': '&quot;', "'": '&#39;' };
  return String(text).replace(/[&<>"']/g, (c) => HTML_ESCAPES[c]);
  ```

**4. Medium · Security (hardening) · Quotes are not escaped**
- **File:** `src/users.js:16-21`
- **Reason:** `escapeHtml` is documented as "safe to put inside HTML", but it does not escape `"` or `'`. That is enough for element content as used in `userRow`, but if this helper is ever used inside an attribute value (`title="${...}"`) it becomes an injection point. This is a latent risk rather than a live bug in the current code.
- **Recommendation:** Escape `"` and `'` as part of the fix for finding 3, and state in the doc comment that the output is only safe for element content if that is the intent.

**5. Medium · Testing · No tests for any exported helper**
- **File:** repository root (no `*.test.js` / `*.spec.js` found)
- **Reason:** Three of the four bugs above (pagination off-by-one, birthday handling, partial escaping) would be caught by a basic unit test. With no tests, nothing guards these helpers.
- **Recommendation:** Add tests for `paginate` (page 1 returns the first `size` items), `isAdult` (birthday before/after today), and `escapeHtml` (multiple `<`, `&`, `>` in one string).

### Not an issue
- `userRow` (`src/users.js:24-26`) correctly escapes the name, and `isAdmin` is a boolean with a fixed label, so it introduces no injection path on its own.

### Verdict
**Fail.** Three high-severity defects are present (wrong pagination, wrong adult check, and an XSS-capable partial escape). They must be fixed before this module is relied on.
